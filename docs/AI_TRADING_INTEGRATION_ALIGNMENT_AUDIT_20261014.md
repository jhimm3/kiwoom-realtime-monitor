# AI Trading Intelligence 종합 명세와 현재 개발 방향 대조

감사 시작 2026-10-14 · 완료 2026-10-15 · 제품 2.1.0 · 로컬 main HEAD `232737d`와 누적 미커밋 소스 기준

최종 목표는 유지되고 있지만, 정책별 데이터 요구조건, 테마와 가격 입력의 결합, 현재 모델 지원 판정, 순자산 분모, 비상정지 중 보호 처리에서 보완이 필요하다. 기존 수집·판단·주문 기능을 전면 다시 만들거나, 종목별 수동 투자금 지정으로 최종 목표를 바꾼 것은 확인되지 않았다.

기준은 [00 종합 명세](archive/2026-09-22/references/00_전체통합_AI_Trading_Intelligence.md)의 공통 설계와 ①·②·③이다. 이후 사용자가 정한 공통 Shadow, Collector RAM 재사용, 목적별 미체결 관리, 상위 자동 비중, 개발 완료와 운용 승인 분리 원칙을 함께 적용했다. 00에 포함된 과거 단계 명령을 새로운 실행 권한으로 사용하지 않았다.

**감사 이후 수정:** 2026-10-15 A01의 현재 R4 정책·행동별 요구자료와 테마 없는 v2 시작/복원, A02의 독립 가격/조건부 점수/구성요소 lease/테마 위험 소속 분리를 연결했다. 사용자 지정으로 A03을 다음에 진행하고 A04는 뒤로 옮겼다. A03의 현재 상태·미래 native 정책 지원 계약은 [설계 재검토](AI_TRADING_SYSTEM_REDESIGN.md#a03-설계-재검토)가 필요하다. 아래 원문은 감사 시점 근거이며 현재 구현·검증/잔여는 [CURRENT_STATUS](CURRENT_STATUS.md)·[OPEN_ITEMS](OPEN_ITEMS.md)에 둔다. 장별 원장·소스 지문은 감사 시점 스냅샷으로 보존한다.

## 대조 범위와 판정 기준

00의 번호가 있는 상위 장 95개를 모두 대조했다. 공통 19장, ① 24장, ② 24장, ③ 28장이다. 장별 판정과 근거는 아래 대조표와 [장별 원장](../data/diagnostics/20261014-integration-alignment-audit/requirement-coverage.json)에 있다.

`src`와 `scripts`의 Python 547파일은 AST 구문·정의 목록·SHA-256을 확인했고, 관련 실제 호출 경로를 읽었다. 이 수치는 547파일의 모든 함수 동작이나 모든 외부 연동을 시험했다는 뜻이 아니다. 실제 NAS·PostgreSQL·브로커·장중 수락은 이번 감사의 실행 범위가 아니다.

판정은 다음과 같이 구분한다.

- **방향 차이:** 현재 계약·연결이 원래 원칙과 다른 조건을 강제하거나 다른 의미를 사용한다.
- **미완료:** 필요한 책임·연결·양의 지원 경로가 아직 구현되지 않았다. 반대 방향의 구현과 구분한다.
- **후속 기획에 따른 변경:** 원문과 달라도 이후 명시한 범위·원본 보존·운용 경계를 따르는 변경이다.
- **일치:** 읽은 경로와 수행한 검증에서 원칙을 유지한다. 전체 운영 수락을 뜻하지 않는다.

## 방향을 보완해야 하는 항목

### A01 정책별 데이터 요구조건 계약이 없다

00 ②8·13·17장은 시나리오 분기, 조건부 관찰, 행동 후보별 `required_data_capabilities`를 선언한다. 현재 `src`·`scripts`·`tests`에는 이 계약의 구현이 없고, 해당 이름은 보존된 설계 원문에만 있다.

현재 R4의 `owner_ram_risk_and_thesis` 모드는 신선한 `stock-thesis-shadow/v1`을 공통 필수로 요구한다. 이 판단은 기존 테마 대장 평가를 사용한다. 따라서 테마를 사용하지 않는 정책을 같은 native 모드에 연결할 별도의 필요 자료 판정이 없다. 반면 순수 행동 비교와 `supplied_fixed` 연구 경로는 테마·뉴스 없이 계산할 수 있고, 기존 Family에는 선택적인 rank filter와 입력 해상도 검사도 있다. 모든 기존 전략에 데이터 조건 처리가 없다는 뜻은 아니다. 직접 호출에서 비교 `COMPARABLE`, 테마 판단을 제거한 native 행동 선택 `BLOCKED`를 확인했다. 뉴스 누락 자체를 모든 R4의 공통 차단 사유로 넣은 코드는 확인하지 못했다.

근거: [행동 비교와 native 입력 검사](../src/kiwoom_monitor/application/position_target.py) `_native_selection_inputs` 1318행, `evaluate_position_action_comparison_shadow` 1396행; [R3 테마 판단](../src/kiwoom_monitor/application/market_theme_shadow.py) `_stock_thesis_result` 318행.

필요한 보완은 정책·행동별 요구자료와 공통 계좌 안전조건을 분리하는 것이다. 테마·뉴스를 사용하지 않는 정책에 해당 자료를 요구하지 않고, 해당 자료를 사용하는 정책의 결측은 계속 차단한다. 해상도·venue·가용시각·신선도도 같은 요구조건에 포함해야 한다. 결측을 0점이나 가짜 테마로 채우는 방식은 사용하지 않는다.

### A02 가격과 상위 맥락 입력이 테마 연결에 묶여 있다

00 ②5·6장은 공통 가격·거래 특징을 재사용하고, 처음부터 뉴스·시장 지표를 모두 AND 조건으로 강제하지 말라고 한다.

현재 [실시간 R4](../src/kiwoom_monitor/central_server/market_theme_shadow_monitor.py)의 `_evaluate_live_position`은 테마 구성원인 종목의 context를 찾은 뒤 그 context의 `second_points`에서 가격을 얻는다(964~981행). 테마 context가 없으면 Collector에 가격이 있는지 독립적으로 읽지 않고 `ram_reference_price_unavailable`로 반환한다. 이는 테마 자료 누락을 가격 자료 누락으로 보고할 수 있는 연결이다.

[상위 비중 RAM 변환](../src/kiwoom_monitor/central_server/market_theme_shadow_inputs.py)은 모든 후보에 시장·테마·종목 강도와 비어 있지 않은 테마 집합을 요구한다(588·629~634행). `DynamicPositionCandidate`도 테마 소속과 세 점수를 필수로 받는다. `(0,0,1)` 가중치는 허용되지만 테마 소속 제거는 `candidate theme/source identity invalid`다.

다만 가중치 0은 **점수 계산에서 사용하지 않는다는 뜻**이다. 현재 테마 집중 위험 한도는 여전히 작동하므로 테마 소속의 필요성을 가중치만으로 판단하면 안 된다. 보완 대상은 가격·정책 특징·포트폴리오 테마 위험의 요구조건을 각각 선언하는 경계다. 같은 Collector와 RAM snapshot을 유지하고 별도 수집기를 만들지 않는다.

### A03 현재 R4 모델 적용 경로에 양의 지원 판정이 없다

00 ③9·19장은 모델의 사건·기간·모집단·자료·규모 지원 범위를 검증하고, 미지원은 null로 표시하도록 한다. 모든 상태의 사용을 영구 차단하는 것을 최종 기능으로 정하지 않았다.

[현재 goal binding](../src/kiwoom_monitor/central_server/market_theme_shadow_inputs.py)의 `position_study_current_goal_binding`은 시작부터 맥락·상위 입력 독립성·보호 상태·후속 정책 사유를 넣는다(313행). native owner 상태가 확인되면 일부 사유를 다른 미검증 사유로 바꾸고, 마지막 반환은 항상 `status='EV_UNAVAILABLE'`, `result=None`, `order_authorized=False`다(421행). 조건을 모두 만족했을 때 현재 모델 지원 상태를 계산하는 분기는 없다.

따라서 v2 연구 표본 생성·과거 짝 비교·게시·현재 계좌 연결은 구현되었지만 **현재 상태에 적용 가능한 R4 모델 지원 판정은 미완료**다. 이를 현재 EV 생산자 완료나 현재 R4 전체 완료로 세면 안 된다.

`exact-observed-context/v1`와 같은 가격·수량을 요구하는 최초 지원 범위는 보수적인 연구 제한으로 유지할 수 있다. 다만 그 제한은 해당 모델의 명시 지원 규칙이어야 한다. 다른 정책도 모든 테마·초 단위 맥락을 동일하게 요구하는 공통 규칙으로 확대하지 않는다. 일반화·보간을 임의로 허용하거나 차단 상수를 단순히 제거하는 것은 보완이 아니다.

같은 맥락을 여러 판단에서 재사용하는 것과 같은 미래 결과로 목표를 선택하고 그 결과를 독립 검증으로 재사용하는 것도 구분해야 한다. `audit_position_study_ev_lineage`는 같은 날짜 창만 겹쳐도 `REPORTED_OVERLAP`을 보고한다. 서로 다른 run·revision·outcome의 같은 창으로 이 보고를 재현했다. 이는 보수적 진단이며 실제 누출 확정이나 독립성 확정은 아니다. 00 ③4·8의 날짜·사건 그룹과 TRAIN/VALIDATION 분리를 이용해 실제 학습·선택·평가 의존성을 판정해야 한다.

### A04 순자산과 주문가능금액의 의미가 분리되지 않았다

00 공통6·③10.5·11.1은 노출 분모인 순자산과 현금·미결제금·주문가능금액을 구분한다.

기존 [계좌 codec](../src/kiwoom_monitor/infrastructure/kiwoom_rest/mock_account.py)의 `parse_account_snapshot`은 `kt00001.ord_alow_amt + 알려진 매수 예약`을 `available_cash_won`으로 매핑한다(318~354행). 이는 기존 주문 가능성 계산에 맞추어 만든 계약이며 독립적인 계좌 순자산 값이 아니다.

[상위 비중 계산](../src/kiwoom_monitor/application/position_target.py)은 이 값을 보유 평가액과 더해 `equity_won`, `equity_basis='cash_plus_marked_long_positions/v1'`로 사용한다(261~266행). 현재 `AccountSnapshot`에는 검증된 순자산·현금·미결제·부채의 별도 필드가 없다. 같은 주문가능금액과 다른 예수금 payload를 넣어도 동일 AccountSnapshot이 되는 것을 재현했다. 예수금이 곧 순자산이라는 주장은 하지 않는다.

연구 fixture에서는 명시 현금으로 계산이 맞지만, native 계좌에서 이 합계를 00의 실제 순자산으로 일반화할 근거가 없다. 보완은 기존 주문가능금액 codec의 의미를 보존하면서 계좌 owner가 검증한 순자산 기준·금액·시각을 상위 비중에 별도로 전달하는 것이다. 현재 증거만으로 실제 계좌의 오산 금액을 추정하지 않는다.

### A05 기본 비상정지와 보호 유지 정책이 다르다

00 ③15.6은 신규 진입 중지·미체결 매수 취소·감액만 허용·청산 시도를 구분하고, 기본 비상정지에서도 보호·대사를 유지하도록 한다.

현재 [자동운용 stop](../src/kiwoom_monitor/application/mock_automation_execution.py)은 `STOPPED`와 `new_orders_enabled=False`를 저장한다. [Runner.run_once](../src/kiwoom_monitor/central_server/mock_automation_runner.py)는 체결 반영 후 `STOPPED`를 만나면 보호·미체결 소비 전에 반환한다(1816~1833행). 시계 마감 중지는 별도 예외가 있다. 격리 SQLite에서 PENDING 보호 cue와 STOPPED control을 함께 주었을 때 보호 소비 호출 0회, PENDING 유지, Runner STOPPED를 확인했다. 계좌 monitor와 기존 제출 주문의 응답·체결 대사가 모두 중단된다는 뜻은 아니다.

이 동작은 [현재 모의 실행 계약](KIWOOM_MOCK_EXECUTION_CONTRACT.md)의 ‘긴급 중지 후 기존 주문·포지션을 자동 취소·청산하지 않음’과 일치한다. 따라서 기존 STOP 권한을 무시하고 보호 주문을 켜는 수정은 하지 않는다. 00 목표와 현행 실행 계약 사이의 **비상제어 종류와 보호 권한 분리**가 필요한 항목이다. 운영 승인 전 우선 해결해야 한다.

### A06 개발 단계 번호의 의미가 바뀌어 있다

00 ③24장의 R3는 행동 EV·분할 정책, R4는 후보 학습·Shadow·Paper다. 현재 재구성 로드맵의 R3는 시장/테마 연결, R4는 포지션/EV, R5는 학습·운용 확장이다. 현재 R4 작업을 00의 R4 완료로 읽으면 후보 학습·전진 예측·Paper/브로커 검증이 완료됐다고 오해할 수 있다.

근거: [현재 재구성 단계](AI_TRADING_SYSTEM_REDESIGN.md) 347~363행과 원문 2727~2769행. 현재 단계 번호의 변경 자체는 재구성 계획에 따른 것으로 제품 목표 폐기가 아니다. 보고에서 `현재 재구성 R4`와 `00 ③R3/R4`를 함께 적고 기능 구현·전략 검증·실제 운용 수락을 나누어 표시해야 한다.

### A07 현재 진행 기록이 여러 정본에 중복되어 있다

[현재 설계](AI_TRADING_SYSTEM_REDESIGN.md) 29행은 같은 진행 로그를 여러 설계 문서에 누적하지 말고 상태·보류·순서를 각각의 정본으로 나누도록 한다. 그러나 최신 실제 입력 복구·REENTER 기록은 CURRENT_STATUS, OPEN_ITEMS, FUTURE_DEVELOPMENT_ROADMAP, AI_TRADING_SYSTEM_REDESIGN에 반복되어 있다. 이후 한 문서만 갱신하면 서로 다른 ‘다음 단계’가 남을 수 있다.

원래 목표 기능의 변경은 아니지만 진행 관리 방식이 정한 원칙에서 벗어난 항목이다. CURRENT_STATUS에는 완료/검증 상태, OPEN_ITEMS에는 미완료와 해소 조건, 로드맵에는 순서와 범위, 설계에는 오래 유지할 계약만 남기고 서로 링크하는 방식으로 정리해야 한다. 이번 감사에서는 기존 기록을 삭제하거나 재작성하지 않았다.
