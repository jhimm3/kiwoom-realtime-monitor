# AI로 강의 자료를 전략팩으로 만드는 방법

이 문서는 사용자가 보유한 주식 강의 PDF·스크립트를 AI로 분석한 뒤, 키움 매매일지의 자동분석 전략팩으로 안전하게 옮기는 방법을 설명합니다.

핵심은 강의를 단순 요약하는 것이 아니라 다음 세 가지를 분리하는 것입니다.

1. 강사가 실제로 설명한 원칙
2. 앱 데이터로 계산할 수 있는 규칙
3. 새로운 개발이나 사용자 판단이 필요한 규칙

AI가 만든 결과를 바로 신뢰하거나 자동으로 활성화하지 마세요. 숫자 기준·강의 출처·필요 데이터를 확인한 뒤 전략팩을 승인해야 합니다.

## 1. 준비할 자료

가능하면 다음 자료를 함께 준비합니다.

- 강의 PDF 또는 PPT를 PDF로 저장한 파일
- 강의 음성을 받아쓴 스크립트
- 강사가 배포한 체크리스트나 요약본
- 강의의 목차와 강의별 주제
- 사용자가 별도로 기록한 보충 메모

PDF 화면에 글자가 보이더라도 실제 텍스트가 들어 있지 않은 이미지 PDF일 수 있습니다. AI가 글을 제대로 읽지 못하면 OCR된 PDF나 TXT 스크립트를 함께 제공하세요.

### 자료 정리 권장 방식

파일명에 강의 순서를 표시하면 AI가 문맥을 섞을 가능성이 줄어듭니다.

```text
00_기초강의.pdf
01_주도주선정.pdf
02_눌림매매.pdf
02_눌림매매_스크립트.txt
03_매도와위험관리.pdf
```

PDF와 스크립트가 같은 강의라면 파일명 앞번호를 같게 지정합니다.

## 2. AI 서비스에 자료를 넣기 전 주의사항

- 업로드 권한이 있는 강의 자료만 사용하세요.
- 강의 원문이나 AI가 만든 장문의 요약을 공개 저장소·커뮤니티에 배포하지 마세요.
- 계좌번호, API 키, 주문번호, 개인 메모 등 개인정보는 제거하세요.
- AI 서비스의 파일 보관·학습·개인정보 설정을 직접 확인하세요.
- 앱은 원본 강의 파일을 GitHub에 올리지 않습니다. 추출한 텍스트와 검토 규칙은 사용자 로컬 매매일지 DB에 저장됩니다.

## 3. AI에 사용할 기본 요청문

아래 요청문을 복사한 뒤 PDF와 스크립트를 함께 첨부합니다. 자료가 많으면 강의별로 나눠 분석하고 마지막에 통합을 요청하세요.

```text
첨부한 강의 PDF와 스크립트를 주식 매매일지 앱의 자동분석 전략팩으로 변환해 줘.

목표는 강의를 일반적으로 요약하는 것이 아니라, 실제 매수·매도 체결과 분봉·일봉 데이터를 이용해 사용자가 강의 원칙을 지켰는지 자동 판정할 수 있는 구조를 만드는 것이다.

반드시 지킬 원칙:

1. 강사가 직접 말하지 않은 숫자나 기준을 임의로 만들지 않는다.
2. 강의에서 명확히 제시한 기준과 AI가 분석 편의를 위해 제안한 기준을 구분한다.
3. 잠깐 언급한 다른 매매법을 해당 강의의 핵심 원칙으로 취급하지 않는다.
4. PDF와 스크립트가 중복되면 하나의 규칙으로 합치되 출처는 모두 기록한다.
5. PDF와 스크립트가 충돌하면 충돌 내용을 표시하고 사용자 확인을 요청한다.
6. 심리·재량·경험처럼 차트 데이터로 확인할 수 없는 내용은 자동 판정 규칙으로 만들지 않는다.
7. 숫자가 없는 정성적 표현에 임의의 기준값을 넣지 않는다.
8. 불확실하면 추측하지 말고 사용자 확인 필요로 분류한다.
9. 미래 봉이나 매도 후 데이터를 진입 시점 판정에 사용하지 않는다.
10. 강의 원문 전체를 다시 출력하지 말고 자동분석에 필요한 파생 규칙만 작성한다.

강의 전체를 다음 계층으로 구조화한다.

- 강의명과 강의별 실제 중심 주제
- 핵심 매매유형과 보조 매매유형
- 매매법의 전제조건
- 종목 선정 조건
- 진입 조건
- 진입 제외 조건
- 손절 조건
- 익절·청산 조건
- 비중 및 위험관리
- 장세·테마·재료 조건
- 자동 확인 불가능한 항목
- 다른 매매법을 잠깐 언급한 참고 내용

각 규칙은 다음 중 하나로 분류한다.

- entry: 진입 조건
- exclude: 진입 제외 조건
- exit: 청산 조건
- risk: 위험관리
- context: 설명 또는 전제
- manual: 사용자 확인 필요

현재 앱에서 계산할 수 있는 측정값:

- entry_from_open_pct: 장 시작가 대비 진입 등락률(%)
- breakout_over_30m_high_pct: 직전 30분 고점 대비 진입률(%)
- pullback_from_session_high_pct: 장중 고점 대비 조정폭(%)
- rebound_from_pullback_low_pct: 조정 저점 대비 반등률(%)
- entry_trade_value_eok: 진입 1분봉 거래대금(억원)
- trade_value_vs_prior_ratio: 직전 5개 봉 평균 대비 진입봉 거래대금 배율
- recent_high_distance_pct: 최근 20거래일 고점과 진입가의 거리(%)
- entry_time_hhmm: 진입 시각(HHMM)

현재 앱이 보유한 자료:

- 매수·매도 체결시각, 가격, 수량
- 1분봉과 일봉 OHLCV·거래대금
- 실시간 순위, 거래대금, 신고가 거리
- 테마와 테마 내 순위
- 당시 뉴스와 재료
- 외국인·기관 수급 스냅샷
- 프로그램 순매수와 변화량
- 체결강도와 최근 매수 체결 비중
- 코스피·코스닥 지수와 시장 거래대금

각 규칙마다 다음을 판단한다.

- 강의의 핵심 규칙인지 참고 설명인지
- 자동 확인 가능 여부
- 필요한 원본 데이터
- 현재 앱에서 지원되는지
- 대응하는 측정값
- 비교 연산자와 기준값
- 기준값이 강의에서 직접 제시됐는지
- 규칙 위반 시 제외인지 경고인지
- 출처 파일·페이지·스크립트 위치

숫자가 없는 규칙은 다음과 같이 처리한다.

- threshold: null
- threshold_source: not_specified
- needs_user_threshold: true
- approved: false

AI가 시험 기준을 제안할 때는 다음과 같이 강의 원칙과 분리한다.

- threshold_source: ai_suggestion
- approved: false
- 제안 이유 표시
- 사용자 승인 전 자동판정에 사용하지 않음

결과는 JSON과 사람이 읽는 검토 요약 두 가지로 출력한다.

JSON에는 pack, lessons, rules, validation 항목을 포함한다. 각 규칙에는 rule_id, category, text, importance, automatable, metric_key, comparison, threshold, unit, threshold_source, needs_user_threshold, required_data, data_status, effect, source, ambiguity, approved를 기록한다.

마지막 검토 요약에는 다음 내용을 기록한다.

1. 전략의 핵심 전제
2. 반드시 충족해야 하는 진입조건
3. 하나라도 해당하면 피해야 하는 조건
4. 점수만 낮추는 주의조건
5. 청산과 위험관리
6. 현재 앱 데이터로 확인 가능한 항목
7. 기능 개발이나 추가 수집이 필요한 항목
8. 숫자 기준을 사용자가 정해야 하는 항목
9. 서로 충돌하거나 모호한 내용
10. 자동분석 적용 전에 사용자에게 물어볼 질문
```

## 4. AI 결과의 숫자 기준 확인

AI가 만든 숫자는 반드시 출처를 확인합니다.

| 기준 출처 | 의미 | 앱 적용 |
|---|---|---|
| `lecture` | 강사가 직접 제시 | 출처를 확인한 뒤 승인 가능 |
| `ai_suggestion` | AI가 시험용으로 제안 | 기본적으로 승인하지 않음 |
| `not_specified` | 강의에 숫자가 없음 | 사용자가 직접 기준을 정해야 함 |

예를 들어 강의에서 “충분히 눌린 뒤 반등할 때 진입”이라고만 했다면 AI가 임의로 5%를 강의 원칙으로 확정하면 안 됩니다.

```json
{
  "category": "entry",
  "text": "상승 후 충분한 조정을 거친 뒤 반등이 확인될 때 진입한다.",
  "automatable": true,
  "metric_key": "pullback_from_session_high_pct",
  "comparison": ">=",
  "threshold": null,
  "threshold_source": "not_specified",
  "needs_user_threshold": true,
  "approved": false
}
```

강사가 “고점 대비 최소 5% 조정”이라고 명확히 말했다면 `threshold`를 5로 지정할 수 있습니다.

## 5. 앱에 전략팩 등록하기

1. 매매일지를 엽니다.
2. 오른쪽 위 `⚙`를 누릅니다.
3. `자동분석 전략` 옆의 `전략팩 관리…`를 누릅니다.
4. `새 강의 추가`를 누릅니다.
5. 강의·전략 이름과 주력 매매유형을 입력합니다.
6. 필수 데이터와 선택 데이터를 쉼표로 나눠 입력합니다.
7. PDF·DOCX·TXT·MD 자료를 선택합니다.
8. `검토 대기로 등록`을 누릅니다.
9. 등록한 전략팩을 선택하고 `규칙 초안 만들기·보기`를 누릅니다.

앱은 강의 문단을 다음 항목으로 나눕니다.

- 진입 조건
- 제외 조건
- 청산 조건
- 위험관리
- 필요 데이터
- 설명

PDF와 스크립트에서 추출한 원문 텍스트는 로컬 매매일지 DB에 저장됩니다. 원본 파일을 이동해도 저장된 초안은 다시 볼 수 있지만, 원본 페이지를 재추출하려면 원래 파일이 필요합니다.

## 6. 앱의 규칙 검토 화면 사용법

각 자동 확인 규칙에 다음 값을 지정합니다.

- `분류`: 진입·제외·청산·위험관리 등
- `자동확인`: 차트 데이터로 검사할 규칙인지
- `측정값`: 앱에서 계산할 값
- `비교`: `>=`, `<=`, `>`, `<`, `==`
- `기준값`: 강의 또는 사용자가 확인한 숫자
- `필요 데이터`: 계산에 필요한 자료
- `출처`: 원본 파일과 위치

정성적인 설명은 자동확인을 끄고 수동 확인으로 남깁니다. 핵심 규칙을 억지로 숫자로 바꾸지 마세요.

검토가 끝나면 `검토 내용 저장`을 누릅니다. 이어서 전략팩 관리 화면에서 `검증 후 승인`을 누릅니다.

## 기존 전략팩에 강의 추가하기

같은 전략을 보충하는 심화 강의는 새 전략팩으로 만들지 않고 기존 전략팩을 선택한 뒤
`선택 전략팩에 강의 추가`를 누릅니다. 새 PDF·DOCX·TXT·MD만 선택하면 기존에 저장한
원문과 검토 규칙은 유지되고 새 문단만 합쳐집니다.

- 기존과 같은 문장: `유지`로 표시하고 측정값·비교식·기준값을 승계합니다.
- 새 문장: `신규`로 표시합니다.
- 같은 측정값인데 기준이 달라진 문장: `충돌 확인`으로 표시합니다.
- 강의를 추가하면 버전이 1 올라가며 사용 상태가 해제됩니다.
- 변경 내용을 검토하고 다시 승인한 뒤 `사용`을 체크해야 자동분석에 반영됩니다.

강의 추가 직전 상태는 자동 보관됩니다. 문제가 있으면 전략팩을 선택하고
`이전 버전 복원`에서 원하는 버전을 선택합니다. 원본 파일을 옮겼더라도 이미 추출해
저장한 이전 문단은 유지되며, 새로 추가할 파일만 현재 위치에서 읽을 수 있으면 됩니다.

다음 경우에는 승인되지 않습니다.

- 자동 확인 가능한 진입조건이 없음
- 측정값 또는 기준값이 비어 있음
- 현재 지원하지 않는 필수 데이터가 있음
- 사용자가 허용하지 않은 새로운 실시간 저장이 필요함

승인 후 `사용`을 체크하고 전략팩 설정을 저장해야 자동분석에 참여합니다.

매매일지 설정의 `분석 결과 표시`에서는 다음 방식을 선택할 수 있습니다.

- 기본분석·전략팩 함께 표시
- 조건 충족 시 자동 교체: 진입조건 60% 이상, 보통 2개 이상 일치한 전략팩 중 기본분석보다 신뢰도가 5%포인트 이상 높거나 기본분석이 `기타`일 때 교체
- 전략팩 우선
- 기본분석 우선

어떤 방식을 선택해도 회차별로 사용자가 직접 확정한 유형이 가장 우선합니다.

## 7. 여러 전략팩의 판정 방식

승인된 사용자 전략팩은 기존 미모사 기본 전략팩과 함께 같은 매매를 분석합니다.

```text
전략팩 비교:
미모사 기본 전략팩 주도주 돌파 72%
눌림 강의 눌림 90% (선택)
```

조건 하나가 우연히 맞았다는 이유로 다른 전략이 선택되지 않도록 다음 안전장치를 적용합니다.

- 진입조건이 여러 개라면 최소 2개 이상 일치
- 전체 진입조건 중 60% 이상 일치
- 기존 판정보다 신뢰도가 5%p 이상 높을 때 변경
- 기존 판정이 `기타`라면 사용자 전략에 충분한 근거가 있을 때 선택 가능

자동 판정은 정답이 아니라 복기 보조 도구입니다. 사용자는 각 매매 회차의 최종 유형을 직접 수정할 수 있습니다.

## 8. 앱에 없는 지표가 나온 경우

AI가 미지원 기능을 기존 지표로 임의 대체하지 않게 다음 요청문을 추가합니다.

```text
현재 앱에 없는 지표나 판정 방식이 강의에 나오면 제외하거나 기존 지표로 임의 대체하지 마라.

각 미지원 규칙을 다음 중 하나로 분류하라.

- 기존 데이터로 추가 계산 가능
- 새로운 실시간 데이터 저장 필요
- 추가 TR/API 조회 필요
- 외부 데이터 제공처 필요
- 사용자 입력 필요
- 자동화 불가능

기존 데이터로 계산 가능하다면 기능 이름, 필요한 원본 데이터, 계산식, 시간 단위, 필요한 과거 데이터 길이, 미래 데이터 사용 방지 방법, 측정값 이름, 비교 기준, 추가 API·TR·저장 용량, 실시간 화면 영향, 사용자 결정사항을 포함한 개발 명세를 작성하라.

이동평균선·정배열·VWAP·RSI·MACD·볼린저밴드처럼 기존 OHLCV로 계산 가능한 지표는 derived_indicator로 분류하라.

피보나치·추세선·파동처럼 기준점 선택에 따라 결과가 달라지는 기능은 시간봉, 탐색 구간, 고점·저점 확정 방식, 꼬리·종가 기준, 사용할 비율, 허용 오차, 파동 재설정 조건을 사용자에게 질문하라.

핵심 진입조건이 미지원이면 지원 가능한 일부 조건만으로 최종 매매유형을 판정하지 말고 development_required 상태로 출력하라.
```

### 현재 봉 데이터만으로 추가 가능한 대표 기능

- 단순·지수 이동평균선
- 정배열·역배열
- 이동평균선 기울기와 이격도
- VWAP
- RSI·MACD·볼린저밴드
- 거래량·거래대금 이동평균
- 피보나치 비율 계산

피보나치는 계산보다 기준 파동 선택이 중요하므로 자동 적용 전에 파동 정의를 먼저 확정해야 합니다.

### 추가 실시간 저장이 필요한 대표 기능

- 호가 잔량 변화
- 주문 취소·정정 흐름
- 초단위 체결 속도
- 특정 시점의 매수·매도 호가 변화 과정

이 기능들은 앞으로 데이터를 수집해야 하므로 과거 매매에는 완전한 분석을 적용할 수 없습니다.

## 9. AI가 만들어야 할 개발 요청서 예시

```text
요청 기능: 이동평균선 정배열 판정
사용 전략팩: ○○ 눌림 강의
강의상 필요 이유: 5일선과 20일선이 상승 정렬된 종목만 진입
필요 데이터: 일봉 종가 21개 이상
현재 데이터 보유: 가능
추가 API/TR: 없음
새 측정값:
- ma_5
- ma_20
- ma_5_slope
- ma_20_slope
- distance_from_ma_5_pct
사용자 결정 필요:
- 단순이평 또는 지수이평
- 기울기 계산 기간

개발 전 처리: 수동 확인
```

이 요청서를 개발자 또는 코딩 AI에게 전달하면 강의 원칙과 앱 데이터 구조를 섞지 않고 기능을 확장하기 쉽습니다.

## 10. 최종 검토 체크리스트
