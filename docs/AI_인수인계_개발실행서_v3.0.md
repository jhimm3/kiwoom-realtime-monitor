# 키움 실시간 모니터 — AI 인수인계 개발실행서 v3.2

> 기준일: 2026-08-21  
> 대상: 이 저장소를 새로 받은 개발자 또는 AI  
> 목표: 기존 동작을 깨지 않고 기능을 재현·수정·확장한다.

## 1. 제품의 범위

키움 REST API와 WebSocket `0B`를 이용해 **실시간 조회 상위 20종목**을 표시하는 Windows 데스크톱 모니터다. 주문·계좌·자동매매 기능은 범위 밖이다.

핵심 화면 정보는 순위, 종목, 테마, 등락률, 현재가, 기간 거래대금, 기간 거래강도, 선택 기간의 최고가(화면 명칭 `신고가`), 최고가까지의 거리, 시가총액이다.

사용자는 테마를 직접 편집하거나 Excel·이미지 OCR·텍스트 묶음 입력으로 갱신한다. 모든 테마 최종 데이터는 SQLite에 저장한다.

## 2. 반드시 지켜야 할 제품 원칙

1. 순위(`ka00198`)가 최우선이다. 분봉·기본정보·NXT 등 후속 작업은 순위 기준 시각 직전에 양보한다.
2. 화면 UI 스레드를 REST 요청, OCR, 파일 처리로 막지 않는다. 시간이 걸리는 작업은 `QThread` Worker로 실행한다.
3. API 키·토큰·`data/`·로그는 GitHub에 올리지 않는다.
4. 사용자가 명시적으로 요청하지 않은 주문·계좌·조건검색 기능을 추가하지 않는다.
5. 설정을 새로 추가하면 기본값, 설정 초기화, 백업/복원에 함께 반영한다.
6. 순위 관련 우선순위·시각 규칙을 바꾸기 전에는 사용자에게 다시 확인한다.

## 3. 기술 구성과 실행

| 구분 | 내용 |
| --- | --- |
| 언어 | Python 3.13 이상 |
| GUI | PySide6 |
| 통신 | 키움 REST API, WebSocket `0B` |
| 저장소 | SQLite (`data/monitor.sqlite3`) |
| OCR | PaddleOCR + PaddlePaddle 3.2.2 + Pillow |
| 테스트 | `unittest` |

`pyproject.toml`에는 직접 의존성의 검증된 정확한 버전을 기록한다. 새 PC에서 같은 OCR 환경을 재현할 때는 `requirements.lock.txt`를 사용한다. 현재 검증 조합은 **PaddleOCR 3.7.0 + PaddlePaddle 3.2.2 + PaddleX 3.7.2 + NumPy 2.3.5**다. PaddleX 3.7.2는 NumPy 2.4 미만이 필요하므로 NumPy를 임의로 최신 버전으로 올리지 않는다.

개발 실행:

```powershell
.\.venv\Scripts\python.exe -m kiwoom_monitor
```

새 환경 의존성 설치:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
```

검증:

```powershell
.\.venv\Scripts\python.exe -m compileall -q src tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
```

현재는 PyInstaller 실행 파일 제작을 하지 않는다. 기능과 장중 API 동작을 먼저 검증한다.

- 앱을 처음 실행했을 때 키가 없으면 API 설정 창을 먼저 연다.
- 모의투자와 실전투자 키를 각각 저장할 수 있고 실행 중 선택한다.
- 키 입력은 가려서 표시하며 `data/api.env`에만 암호화해 저장한다.
- Access Token은 메모리에만 보관하고 필요 시 `au10001`으로 재발급한다.

## 6. API별 목적, 순서, 시점

### 6.1 REST/실시간 데이터

| 우선 | API | 사용하는 정보 | 시점/캐시 |
| ---: | --- | --- | --- |

| 7 | `ka10100` | `nxtEnable` Y/N | 종목별 일간 캐시 |

| 보조 | `au10001` | Access Token | 만료·미발급 시 자동 |

### 6.2 요청 제한과 순위 스냅샷 보정

- `KiwoomRestClient`는 **모든 REST 요청을 합산**해 실전 초당 최대 5회(0.2초 간격), 모의 초당 1회로 제한한다.
- WebSocket `0B` 수신은 REST 요청이 아니므로 이 제한에 포함되지 **않는다**.
- 순위 기준 시각의 기본 요청은 항상 기준 시각 +0.25초다. 사용자 수동 시간 보정 설정은 제거됐다.
- `ka00198`이 직전 기준 시각의 스냅샷을 주면 0.75초 간격으로 재조회한다. 새 스냅샷이 오면 즉시 끝내며, 서버가 계속 이전값만 주는 경우는 최대 20회(약 15초)로 멈춘다.
- 순위 기준 2.5초 전에는 진행 중인 저우선순위 Worker에 중단을 요청한다. 이미 서버에 보낸 HTTP 요청은 강제 종료하지 않는다.
- 순위가 20개 미만이면 기존 표를 유지하고 짧게 재시도한다.

### 6.3 시간과 거래 세션

앱의 거래 시간 판정·분봉 집계·순위 예약은 REST 응답 `Date` 헤더로 보정한 키움 서버 시간(`client.server_now()`)을 사용한다. 첫 REST 응답 전에는 로컬 KST를 임시 사용한다.

| 구간 | 0B 구독 규칙 |
| --- | --- |
| 07:55~08:00 | NXT 가능 또는 아직 미확인 종목만 구독 준비 |
| 08:00~09:00 | 실전 NXT 가능/미확인 종목 수신 |
| 09:00~15:30 | KRX 전체 순위 종목 수신 |
| 15:30~20:00 | 실전 NXT 가능/미확인 종목 수신 |
| 20:05~다음 07:55 | 0B·분봉·일봉·신고가 후속 조회 중지 |

NXT 여부를 아직 모르거나 조회 실패한 종목은 안전하게 NXT 가능으로 간주해 NXT 시간에도 수신한다. NXT 불가가 확인된 종목은 KRX 시간에만 수신한다.

현재가의 우선순위는 시간대별로 분리한다. KRX·NXT 장중에는 지연이 가장 작은 `0B`의 필드 `10`만 현재가를 갱신한다. 20:05~다음 날 07:55에는 `0B`가 새 체결을 보내지 않으므로 순위 응답의 `past_curr_prc`를 사용한다. 키움 가이드에는 `cur_prc`로 표기된 경우가 있지만, 실제 `ka00198` 응답은 `past_curr_prc`를 반환할 수 있으므로 두 이름과 호환 필드를 함께 처리한다. 마지막 수신 가격은 SQLite `stocks.last_price`에도 저장해 API 응답이 잠시 비어도 표시를 유지한다.

## 7. 계산 규칙

### 7.1 거래대금

1. `ka10080`으로 앱 실행 전 누락된 당일 1분봉을 채운다.
2. 이후 0B 체결로 현재 분봉을 누적한다. 체결량은 `15` 우선, 없을 때만 누적거래량 `13`의 증가분을 쓴다.
3. 분봉 거래대금(억):

```text
거래량 × (고가 + 시가 + 저가 + 종가) ÷ 4 ÷ 100,000,000
```

4. 1분·5분·60분은 **시계 경계 기준**이다. 예를 들어 11:07의 현재 5분은 11:05~11:09, 직전 5분은 11:00~11:04다.
5. 각 기간 열 머리글을 눌러 현재 진행 구간과 직전 완료 구간을 독립적으로 전환한다.

### 7.2 거래강도

```text
유통시가총액 = 시가총액 × 유통비율 ÷ 100
거래강도(%) = 기간 거래대금 ÷ 유통시가총액 × 100
```

유통비율이 없으면 100%로 계산한다. 1·5·60분·1일은 각자 거래대금을 사용하므로 같은 값이 되면 안 된다.

### 7.3 최고가/신고가 표시

- 5일·20일: `ka10005` 일봉 고가 최댓값
- 250일: `ka10001` 기본정보 고가
- 0B 당일 고가가 더 높으면 표시 값에 반영
- 화면의 `신고가`는 선택한 기간의 **최고가 가격**이다. `신고가%`는 현재가와 그 가격의 거리다.
- 값이 없을 때는 신고가 근접 강조·알림을 하지 않는다.

## 8. UI와 설정의 핵심 동작

### 8.1 기본 설정 탭 구성

기본 설정은 길어지지 않도록 기능별 탭으로 나눈다.

| 탭 | 포함 항목 |
| --- | --- |
| 거래강도 | 기간별 관심·주의·불 기준, 거래대금 강조 기준, 아이콘 |
| 신고가 | 기준 기간, 근접 단계·행 강조·아이콘·소리 |
| 화면 구성 | 화면 모드, 홀짝/순위 변동 행 색, 고정 UI 글자·행·배지 크기 |
| 표시 형식 | 상위 테마 거래대금, 소수점, 시가총액 색 구간, 오른쪽 하단 시각 |
| 필드 편집 | 메인 표 필드 표시·순서·폭. 변경 즉시 표에 반영 |
| 종목/테마 | 상장종목 동기화, 수동/Excel/OCR/텍스트 테마 입력과 관리 |
| 관리 | API 설정, 로그 폴더, 설정 백업·복원 |

`화면 구성`과 `표시 형식`은 각자 초기화 버튼을 가지며, 해당 탭에 속한 값만 기본값으로 되돌린다.

기본 설정은 메인 표를 막는 모달 창이 아니라 별도 창으로 연다. 따라서 설정을 편집하는 동안에도 순위·0B 수신·알림·집계는 계속 동작하고 메인 표의 순위 갱신도 보류하지 않는다.

아이콘 이미지는 선택 시 PNG로 자동 축소·압축한 **2MB 이하** 복사본만 `data`에 저장하며 원본 파일은 건드리지 않는다. 신고가 알림 소리는 WAV·MP3·OGG·M4A 형식에서 파일당 **5MB·30초 이하**만 선택할 수 있다. 전체 첨부파일 합계 제한은 두지 않는다.

기본 신고가 근접 알림은 `data/near_high_sounds`의 관심(15%)·주의(10%)·불(5%) MP3 파일을 사용한다. 사용자가 다른 파일을 선택하면 해당 단계의 기본 파일을 대체하며, 신고가 탭 초기화 시 기본 파일 연결로 되돌린다.

### 8.2 메인 표

- 표시 필드는 기본 설정의 **필드 편집**에서 일괄 표시/숨김, 순서, 폭을 바꾼다. 표 헤더 드래그·우클릭도 지원한다.
- 수동으로 열 폭을 바꾼 후 30초 동안은 창 크기를 바꿔도 행 높이와 열 너비를 모두 그대로 유지한다. 30초가 지난 뒤부터 다시 반응형 자동 조절한다.
- 반응형 UI는 창 너비에 맞춰 열 폭을, 창 높이와 행 수에 맞춰 행 높이를 조정한다. 수동 글자/행 높이는 우선한다.
- 표의 오른쪽 또는 마지막 행 아래 빈 공간을 더블클릭하면 창 크기를 현재 표 내용에 맞춘다. 실제 셀을 더블클릭했을 때는 이 동작을 하지 않는다.
- 첫 정상 순위 수신 때는 상위 20개 행이 보이도록 세로 크기를 한 번 보정한다.
- 순위 변동은 설정 시간 동안 연초록 행 강조를 적용한다. 신고가 근접 빨강 강조가 우선한다.
- 마우스 호버·선택은 셀 배경을 덮지 않고 셀 왼쪽의 작은 시스템 파란 배지로 표시한다. 같은 셀을 다시 누르면 선택이 해제된다.
- 등락률은 상승 빨강/하락 파랑이다. 종목 오른쪽 아래 빨간 삼각형은 NXT 가능 표시다.
- 시가총액은 `63조 · 7,000억`처럼 조·억을 읽기 쉽게 구분하되 단위 글자만 따로 강조하지 않는다. 전체 글자색은 설정한 구간에 따라 1단계 파랑, 2단계 주황, 3단계 빨강으로 표시한다. 기본 기준은 1조(10,000억)·5조(50,000억)·10조(100,000억)이며, 각 기준을 `0`으로 설정하면 그 단계는 끈다.
- 상단 테마 거래대금 표시를 누르면 `1분 → 5분 → 60분 → 1일` 순서로 기준을 바꾸며, 제외 종목 반영 표시도 동일하게 전환한다.
- 도구 모음은 숨김 메뉴를 제공하지 않는다.

### 8.3 테마와 입력 흐름

최종 테마 데이터는 항상 SQLite `stock_themes`에 저장한다. 입력 경로는 모두 **미리보기 → 수정 → 적용**을 거친다.

| 입력 | 위치 | 규칙 |
| --- | --- | --- |
| 수동 종목/테마 | 기본 설정 > 종목/테마 관리 | 추가가 기본, 수정·삭제·일괄 수정·초기화 지원 |
| Excel | 종목/테마 관리 | 종목명/테마 열을 읽고 미리보기에서 추가·대체를 행별 선택 |
| 이미지 OCR | 종목/테마 관리 | PaddleOCR 결과를 편집 가능한 미리보기로 표시 |
| 텍스트 묶음 | 종목/테마 관리 | `🔥테마명`, `#소제목:종목` 등 자유 형식 파싱. 소제목은 별도 테마로 붙이지 않음 |

- 테마 비교는 공백·대소문자·순서를 정규화한다. `AI, 로봇`과 `로봇, ai`는 변경 없음이다.
- 추가 테마 구분자와 제외 테마는 설정에 저장되며 모든 입력 경로에 적용한다.
- 같은 종목명을 못 찾으면 후보 검색·직접 검색·선택·이번 종목 무시·전체 취소를 제공한다.
- 전체 상장종목 동기화는 입력 시 자동이 아니라 사용자가 눌러 실행한다. 마지막 동기화 시각을 표시한다.
- 테마 배지 글자는 검정/흰색 고정이 아니라 배경과 같은 색조의 읽기 쉬운 진한/밝은 색을 쓴다.

### 8.4 OCR 모델

모델 자동 다운로드가 실패할 수 있으므로 수동 설치 경로와 모델 이름을 유지한다. 자세한 절차는 [OCR 모델 직접 설치](OCR_모델_직접_설치.md)를 따른다.

## 9. 변경 시 체크리스트

### API/Worker 변경

- REST 호출은 반드시 `KiwoomRestClient.request()`를 통과시켜 전체 요청 제한을 유지한다.
- 네트워크·OCR·상장종목 동기화는 메인 스레드에서 실행하지 않는다.
- 새 Worker를 추가하면 `MainWindow._workers()`와 종료 중단 처리에도 넣는다.
- 앱 종료 시 타이머·Worker·미디어 재생을 중지하고, Worker가 끝날 때까지 재시도한다. `QThread: Destroyed while thread is still running` 경고를 만들면 안 된다.

### 설정 변경

- `DEFAULT_SETTINGS`에 기본값 추가
- `SettingsDialog` 저장·초기화 추가
- `SettingsBackupService` 내보내기·복원 포함 여부 확인
- 기존 DB에 키가 없을 때도 정상 동작 확인

### 표 표시 변경

- 아이템을 새로 만들 때 `MainWindow._row_background_color()`를 적용한다. 그렇지 않으면 순위 변동·신고가 행 강조가 일부 열에서 사라진다.
- 셀 위젯(테마 배지 등)은 item 배경과 별도이므로 `_apply_row_background()` 처리도 확인한다.

## 10. 검증 시나리오

1. API 키가 없을 때 설정 창이 먼저 열리는지 확인한다.
2. 실전/모의 전환 후 토큰·순위·상태 표시가 정상인지 확인한다.
3. 30초와 1분 기준 각각에서 기준 시각 응답, 직전 스냅샷 재조회 로그, 20개 미만 재조회 동작을 확인한다.
4. 장중 영웅문과 순위·현재가·등락률·1/5/60분 거래대금·거래강도를 비교한다. 계산 방식과 수신 지연 때문에 완전 일치는 보장하지 않는다.
5. KRX와 NXT 시간대에서 NXT 삼각형·구독 대상이 맞는지 확인한다.
6. Excel·이미지·텍스트 입력 각각에서 미리보기 수정, 제외 테마, 종목 후보 선택, 추가/대체 적용을 확인한다.
7. 설정 백업 후 다른 로컬 DB에서 복원해 열·테마·색·별칭·설정이 복구되는지 확인한다.
8. 앱 종료 중 Worker가 남지 않고 경고 없이 종료되는지 확인한다.
