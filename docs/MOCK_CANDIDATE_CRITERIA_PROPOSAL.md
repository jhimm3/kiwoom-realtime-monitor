# 첫 모의 후보의 기준·final 범위 초안

2026-10-12 사용자 요청에 따른 **검토용 제안**이다. 실제 eligibility policy·final batch·운용 명세는 아니며 기준 파일이나 UI의 입력값에 적용하지 않았다. 기존 목표인 돌파·KRX 정규장·단일 포지션·지정가를 유지한다. 현재 돌파 설정을 그대로 final 후보로 승인한다는 의미는 아니다.

| 항목 | 제안 값 | 이유와 해석 |
|---|---:|---|
| 최소 완료 거래 | 100건 | 몇 번의 거래만으로 통과하는 일을 막는 잠정 최소 표본. 거래끼리 독립이라는 가정이나 통계적 신뢰 수준은 부여하지 않는다. |
| 최소 운용일 | 20일 | 기존 지표인 **완료 거래가 있는 날짜 수**다. 거래 수가 많아도 특정 며칠에만 집중된 결과를 통과시키지 않는다. |
| 최소 순실현손익 | 1원 | 기존 계약은 `>=` 비교이므로 비용 차감 후 양수를 요구하는 최소 정수다. 수익성의 충분조건은 아니다. |
| 최대 낙폭 | 5% (`50,000ppm`) | 기존 final 보고서의 `max_drawdown_ppm`에 적용할 검토용 한도다. 사용자 위험선호를 확인한 운영 한도나 실제 계좌 손실 상한은 아니다. |

위 숫자는 검토 가능한 초기 기준을 제안한 것이며, 데이터에서 추정된 정답이나 업계·논문 표준값이 아니다. 현재 손실 전략을 통과시키려고 음수 손익 기준을 넣거나 성과에 맞춰 표본·낙폭을 조정하지 않는다.

## 권고 final 범위

고정 개발 기간 이후의 **아직 결과를 보지 않은 연속 40 KRX 거래일**, 사전에 선택한 **단일 후보**를 제안한다. 먼저 기존 과거 자료에서 해당 범위의 미사용·품질·출처를 검증할 수 있는지 확인하고, 없으면 새로 관측할 자료를 확보한다. 현재 날짜·자료·미사용 원장은 확정되지 않았으므로 시작과 끝 시각은 미정으로 둔다. 기존 봉인 하루만으로는 제안한 운용일 20일을 만족할 수 없다.

기간은 달력과 접근·미사용 기록으로 결과 확인 전에 고정한다. 거래 없는 날·실패·자료 공백도 기록하며 성과가 좋거나 봉이 많은 날짜만 골라 40일을 채우지 않는다. 결과를 본 뒤 거래 100건·운용일 20일을 채우려고 같은 final 기간을 늘리지 않는다. 표본 부족이면 그대로 부적격/미확인으로 남기고 별도의 새 미사용 기간을 준비한다. 날짜·입력 hash·미사용 원장은 기존 final batch 계약에서 결합하며 후보 설정 hash만으로 대체하지 않는다.

## 현재 결과가 보여 주는 제약

현재 정규장 시간 정책의 고정 개발 결과를 native 원장으로 재대조했다. 돌파 VALIDATION은 4일·완료 거래 132건이며 네 날 모두 손실, 닫힌 거래 순손익 합계는 **-50,971원**이다. 수수료·세금을 더하기 전 체결가 손익도 **-19,109원**이며 슬리피지는 체결가에 이미 포함돼 있다. 날짜별 독립 자금의 손익 금액 합계이며 하나의 연속 계좌 수익률이 아니다. 이 결과는 거래 수만 100건을 요구하는 기준이 부족함을 보여 주지만, 새로운 20일·40일·5% 값의 통계적 타당성을 증명하지 않는다.

기존 16개 결과일은 월별 선정 표본이므로 시장 전체·연속 40일의 대표성을 승인하지 않는다. 20bp 현재 비용 시나리오와 당시 세율 참고값은 구분했지만 실제 계좌·매체·할인·슬리피지는 미검증이다. 내부 긴 공백 18구간의 과거 기록은 일치하나 9종목·일의 원응답이 없어 현재 바이트 검증은 미완료다.

반복 탐색의 선택 편향과 단순 holdout의 한계는 [Bailey 등의 원 논문](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)을 참고했다. **100건·20일·40일이나 한 번의 final 통과를 통계적 수익성 보장으로 해석하지 않는다.** 이 작업에서 PBO·CSCV를 계산하거나 새 평가 지표를 구현하지 않았다.

## 다음 개발 순서

1. 기존 개발 자료에서 돌파의 손실 원인을 좁히고, 변경 후보가 있으면 같은 조건의 개발 분할에서 비교한다. 기준을 낮춰 현 손실 결과를 통과시키지 않는다.
2. 실제 비용·입력 품질과 final의 미사용 자료·범위를 확인한다. 기준·후보·구체적인 시작/끝을 결정한 뒤 기존 동결 경로에 넣는다.
3. 별도 final 평가와 같은 설정 Shadow를 검증하고, 기존 후보 게시·운용 명세·모의 주문 경계로 연결한다.
