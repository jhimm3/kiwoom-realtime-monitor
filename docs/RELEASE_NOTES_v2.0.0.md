# 2.0.0 변경 내역

2.0.0은 1.1.20 이후 누적된 개인 NAS 데이터 서버, 백업 계약, 시점별 시장 데이터 저장과 안정성 리팩터링을 하나의 기준 버전으로 묶은 릴리스입니다. 기존 로컬 모드는 유지되며 NAS 사용은 선택 사항입니다.

## 개인 NAS 데이터 서버와 장애전환

- FastAPI·PostgreSQL 기반 개인 NAS 서버가 평일 08:00~20:00에 실시간 종목조회순위, TOP20 편입 종목의 `0B`, 1분봉, TOP20 지수와 시장 상태를 앱과 독립적으로 수집합니다.
- 앱은 NAS에 이미 보존된 분봉·일봉을 우선 사용하고 실제 누락 구간만 키움 TR로 보완합니다.
- NAS 조회 또는 실시간 연결이 끊기면 사용자가 허용한 경우 로컬 키움 API로 전환하고, 서버 복구 뒤 NAS 경로로 돌아옵니다.
- 중앙 API 인증, WebSocket, 자원 사용량, 운영 설정, 데이터 coverage와 PostgreSQL 실제 왕복 검사 도구를 제공합니다.
- 순위·분봉·일봉·시장 상태·TOP20 지수에는 관측 시각, 실제 가용 시각, 출처, 완결 상태를 함께 보존해 미래 데이터가 과거 분석에 섞이지 않게 했습니다.

## 설정·테마·뉴스·매매일지 동기화

- 공통 설정과 표 표시/순서, 전체 테마 및 활성 프로필, AI 분석 뉴스, 매매일지와 연결한 기사 자료를 NAS 백업 계약에 포함했습니다.
- Google Drive는 사용자가 선택한 설정·테마 범위와 AI 분석 결과를 보존하며, 창 위치·크기처럼 PC마다 달라야 하는 로컬 UI 상태는 공통 설정에서 제외합니다.
- 테마 전송 실패는 디스크 대기열에 보존하고 재시도하며, 로컬과 NAS의 수정 시각을 비교해 최신 스냅샷을 선택합니다.
- 뉴스 설정 화면과 NAS 운영 설정이 같은 값을 사용하고, 종목 뉴스 자동분석은 선택 종목의 관점과 실제 HTTP 실패 상태를 유지합니다.

## TOP20·차트·매매일지

- TOP20 거래대금 지수의 KOSPI/KOSDAQ 분리, 중단 구간, 날짜 조회, 1분·5분·60분·일봉과 기간별 통계를 제공합니다.
- 매매일지 본창과 따로보기 차트가 같은 종목의 봉수·이동평균선·그리기·텍스트 설정을 공유하고 현재 보이는 구성을 이미지로 저장합니다.
- 일봉은 매매일을 기준점으로 표시하되 이후 거래일까지 함께 볼 수 있으며, 분봉·일봉 보완과 자동분석 입력의 시점·출처를 구분합니다.
- 진입 스냅샷, 비용·손익, 전략팩 평가, 뉴스 연결과 복기 저장 흐름을 독립 저장 경계로 정리했습니다.

## 정확성·성능·안정성

- KRX·NXT 신고가와 기본정보의 출처 우선순위를 고정하고 신고가 목록·시가총액·NXT 가능 여부를 NAS에 시점별로 보존합니다.
- ETF·ETN의 미분류 항목 때문에 KRX 전체 상장 목록을 반복 저장하던 조건을 제거해 메인 UI의 주기적 SQLite 잠금을 없앴습니다.
- 실시간 순위 우선순위와 TR 제한, worker 수명, 프로세스 종료, SQLite/PostgreSQL 마이그레이션과 저장 원자성을 회귀 테스트로 보호합니다.
- Windows 창 모드 설치본에서 로컬 중앙 서버의 Uvicorn 로깅이 표준 출력 스트림 부재로 시작하지 못하던 패키징 결함을 수정했습니다.
- 뉴스 프로세스가 무관한 DB 파일 변경을 콘텐츠 변경으로 오인해 대량 동기화하던 피드백 루프와 과거 뉴스 AI 재분석 폭주를 차단했습니다.

## 개발·운영 문서

- 현재 구현 아키텍처, 기능별 모듈 지도, NAS API 계약, DB 스키마, 시점별 데이터 계약과 향후 개발 로드맵을 추가했습니다.
- 증거 기반 버그 수정, TR 중앙 스케줄러 우회 금지, 최소 변경과 문서 동기화 규칙을 `DEVELOPMENT_GUARDRAILS.md`와 `AGENTS.md`에 고정했습니다.
- 리팩터링 종료 감사 결과와 아직 시간이 필요한 NAS 장시간 운용·다른 PC 접속 검증을 별도 보고서에 남겼습니다.

## 업데이트 안내

- 기존 1.x의 로컬 설정과 SQLite 데이터는 그대로 사용합니다.
- NAS를 사용하지 않아도 기존 로컬 키움 API 방식으로 실행할 수 있습니다.
- NAS 서버를 사용하는 경우 앱 2.0.0과 `2026.09.12-shared-backup-contract-v1` 서버 소스를 함께 사용해야 최신 백업·콘텐츠 계약이 일치합니다.
