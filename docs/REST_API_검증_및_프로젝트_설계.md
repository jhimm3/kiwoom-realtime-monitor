# REST API 검증 및 프로젝트 구조 설계 (참조용)

작성일: 2026-08-14  
상태: **현재 채택한 설계.** 실제 구현은 아직 시작하지 않았으며, OpenAPI+ 문서는 비교·참조용으로 보관한다.

범위: REST API 구조 설계와 공식 문서 기반 사전 검증만 수행. API 호출·GUI·DB 기능은 구현하지 않음.

## 1. 결론

키움 REST API는 별도 OCX 설치 없이 Windows/Python 환경에서 사용할 수 있고, 국내주식 조회 REST와 WebSocket 실시간 시세를 제공한다. 인증은 App Key/Secret 기반 OAuth 2.0 Client Credentials이며 접근 토큰은 24시간마다 재발급해야 한다.

명세에 포함된 일부 데이터는 공식 문서 목록만으로 세부 응답 필드가 확정되지 않았거나, 계산에 필요한 정적 기준 데이터가 별도로 필요하다. 따라서 아래 `확인 필요` 항목은 실제 App Key로 모의투자 응답을 저장·대조하기 전에는 구현하지 않는 전제였다.

## 3. 호출 제한과 설계 영향

- 국내주식 실서버 조회 TR은 계좌/토큰당 초당 5회다.
- 모의투자는 TR 하나당 초당 1회다.
- 세션 하나는 실시간 시세 200종목까지 구독할 수 있다.

30초마다 Top 20을 다시 조회하고, 그 20개만 실시간으로 구독하는 방식은 이 한도에 맞는다. 반면 20개 종목의 분봉·일봉을 매 30초 모두 요청하면 특히 모의투자 한도를 쉽게 넘길 수 있다. 거래강도는 캐시·순차 수집·요청 큐를 전제로 하며, API 실측 전에는 기본 화면의 필수 데이터로 확정하지 않는다.

## 4. 사전 검증 목록

실제 키를 소스·문서·로그에 저장하지 않는다. 모의투자 App Key/Secret으로 다음을 확인한다.

1. 토큰 발급, 만료, 재발급과 오류 응답
2. `ka00198`의 요청 파라미터, 순위 수, 종목코드·이름·현재가·등락률·거래량/거래대금 필드
3. 주식기본정보의 시가총액·유통 관련 필드와 단위
4. 분봉/일봉의 시간대·거래량·거래대금 필드 및 기간 집계 가능 여부
5. WebSocket 종목체결 수신 필드, 재연결, 구독 해제, 20종목 동시 수신
6. 장중·장외·장 시작 전 응답과 호출 제한 오류

## 5. 제안 구조

```text
src/kiwoom_monitor/
├─ application/                 # 화면이 호출하는 유스케이스·스케줄 조정
├─ domain/                      # 순수 모델 및 계산 규칙
├─ infrastructure/
│  ├─ kiwoom/                   # REST·WebSocket·인증·요청 제한·응답 변환
│  ├─ persistence/              # SQLite 저장소와 마이그레이션
│  └─ excel/                    # Excel 읽기·검증·변경 미리보기
├─ presentation/                # PySide6 창·테이블 모델·대화상자
└─ bootstrap/                   # 환경설정, 의존성 조립, 앱 진입점
```

- `domain`은 PySide6, HTTP, SQLite, pandas를 직접 알지 않는다.
- 키움의 TR 코드와 원본 필드명은 `infrastructure/kiwoom` 밖으로 새지 않는다.
- API 미확인 필드는 `None/미지원`으로 표현하며 계산기에서 0으로 취급하지 않는다.
