## 1. 제품 방향과 이번에 정한 범위

현재의 실시간 모니터·뉴스·테마·차트·매매일지를 바탕으로, **시장의 재료를 이해하고 → 관심 종목과 상황을 관찰하고 → 판단 근거를 남기고 → 복기하며 기준을 개선하는 앱**으로 발전시킨다. 데이터와 검증이 준비된 뒤 행동별 기대값·비중·위험·실행으로 확장한다.

사용자가 아직 매매법을 학습하고 있으므로 타점 기준의 완성을 선행 조건으로 두지 않는다. 지금 필요한 것은 기준을 성급하게 확정하는 일이 아니라, 나중에 이해가 깊어졌을 때 기존 사례에 새 기준을 적용하고 비교할 수 있는 기반이다.

테마는 구현하며 명칭·묶음의 세부 기준을 조정한다. 특히 **같은 재료가 다른 이름으로 들어와 여러 테마로 쪼개지는 문제**를 해결해야 한다. LLM의 테마 결과도 **기존 테마 프로필 기능을 활용해 저장·선택**한다.

| 구분 | 이번 기획의 취급 |
|---|---|
| 사용자에게 확인된 방향 | 기존 앱에서 확장, 타점은 학습 후 계속 개선, 같은 의미의 테마명 통합, LLM 테마에 기존 프로필 활용 |
| 첨부에서 가져올 큰 구조 | Market → Trading → Research/EV/Risk/Execution의 책임 구분, 당시 근거 보존, 단계별 검증 |
| 구현하며 구체화할 제안 | 대표 테마·별칭·연결 근거·수정 이력, 학습 사례 보관, 판단 기록, 작은 재생 |
| 아직 정하지 않는 것 | 타점 공식, 거래대금 문턱, 시간 제한, 점수 가중치, 손절·익절·증감·재진입 수치, 테마 강도 공식 |
| 별도 환경 확인이 필요한 것 | NAS 서비스와 DB, Mac의 로컬 LLM, 과거 자료 실제 범위, 설치본에 반영된 기능 |

첨부 문서에 있는 구현·테스트·배포 지시문은 이번 요청의 실행 지시로 취급하지 않았다. 이번 산출물은 기획 문서이며 앱 코드·설정·운영 데이터는 변경하지 않았다.

## 2. 현재 앱에서 확인한 출발점

README의 버전 표기는 1.1.19다. 다만 현재 저장소에는 미커밋·신규 파일이 다수 있으므로 아래는 **현재 코드에서 경로를 확인한 결과**이며, 배포판이나 실행 중인 앱의 검증 결과와 다르다. 운영 DB·NAS·실계좌에는 접속하지 않았다.

| 영역 | 현재 코드에서 확인 | 앞으로 연결할 범위 |
|---|---|---|
| 실시간 모니터 | 조회 상위20, 체결 수신, 가격·분봉·거래대금·강도·신고가, TOP20 거래대금 지수 | 후보의 편입·이탈과 당시 관측의 재현 |

| 뉴스·AI | 종목 뉴스, 선택형 공시, 사건 묶음, 원문 분석, 사용자 API 기반 AI, 일지 기사 연결 | 지속적인 사건 기억, 테마와의 관계, 시점별 해석 이력 |
| 차트·일지 | 체결 조회·수신, 차트 표식·주석, 회차 구분, 복기·통계, 비용 추정·정산 비용 배분 | 거래하지 않은 관심 사례와 당시 판단도 연결 |
| 타점 관련 | 실제 체결과 차트를 이용한 유형 분류, 전략팩 조건 비교 | 장중 후보·시나리오·행동 판단은 별도 발전 영역 |
| 개인 규칙·전략팩 | 원문 근거, 초안 검토, 버전·복원, 측정 가능한 조건 평가 | 학습 중인 생각과 실험 규칙을 보관하는 기반 |
| 체결 당시 맥락 | 순위·테마·시장·수급 등의 스냅샷과 사후 보충 | 원래 관측과 나중에 보완한 정보를 분리 |
| 연구·실행 | 실거래 결과를 복기하는 기반은 있음 | 정책 재생·가상 체결·행동 EV·주문 전송 엔진은 조사 범위에서 확인되지 않음 |
| 운영 환경 | 로컬 SQLite와 분리된 뉴스·일지 프로세스 | NAS·로컬 LLM은 외부 환경 확인 후 연결 설계 |

재사용할 자산이 상당하다. 별도 앱으로 처음부터 다시 만드는 기획보다 기존 화면과 데이터 경로에 필요한 기능을 붙이는 편이 적합하다.

### 실제 구현과 첨부 전제의 주요 차이

1. **조회 Top20과 거래대금 Top20은 다르다.** 현재 관찰 집합은 조회순위다. 첨부의 과거 거래대금 Top40 뉴스 수집은 다른 목적의 미래 기능이다.
2. **1초마다 저장하는 1분봉은 1초봉 이력이 아니다.** 현재 코드는 분 단위 키의 분봉을 갱신 저장한다. 과거 각 초의 가격·고저·판단 입력을 이미 보유한다고 전제하지 않는다.
3. **현재 테마 거래대금은 조회 상위20 범위다.** 여러 테마에 속한 종목은 각 테마에 포함된다. 이를 시장 전체 테마 순위나 순자금 유입으로 해석하지 않는다.
4. **분류 신뢰도는 승률이 아니다.** 현재 분류기의 규칙 점수·조건 일치도를 미래 성공확률이나 EV로 이어 쓰지 않는다.
5. **복기 자료는 당시 의사결정 자료와 다를 수 있다.** 체결 뒤 뉴스·수급 보충과 스냅샷 갱신이 있다. 당시 입력과 사후 설명을 구분해야 한다.
6. **과거 연구 자료의 범위는 미확인이다.** 모니터 분봉에는 30일 정리 경로가 있으며, 현재 캐시를 장기 연구 저장소와 동일시할 수 없다.
7. **기존 뉴스 AI와 문서의 로컬 LLM은 다른 경로다.** 현재 코드는 외부 API 공급자를 지원한다. 새 로컬 분석 경로를 붙일 때 기존 선택형 뉴스 AI와의 역할을 정한다.

## 3. 테마 기획: 기존 프로필에 의미가 같은 이름을 모은다

### 사용자에게 보이는 구조

기존 테마 프로필 선택을 그대로 사용한다. 예를 들어 현재 수동 프로필과 `AI 테마` 프로필을 두고, 선택한 프로필의 테마가 기존 배지·집계·차트·일지에 연결되도록 한다. `AI 테마`는 가칭이며 이름이나 개수를 지금 확정할 필요는 없다.

LLM은 지정된 프로필을 갱신한다. AI를 위한 별도의 테마 관리 화면을 처음부터 만들기보다 현재의 테마 편집·변경 미리보기·프로필·백업 기능을 확장한다. 여러 프로필을 동시에 화면에 합쳐 보여주는 기능은 초기 필수가 아니다.

### 대표 테마와 별칭

테마의 동일성을 표시 문자열만으로 판단하지 않는다. 이름이 바뀌어도 같은 테마를 가리키는 식별자와 대표명을 두고, 들어온 원래 표현은 별칭 또는 출처 표현으로 보관한다.

| 들어온 표현 | 맥락 판단 | 저장·표시 예시 |
|---|---|---|
| 호남개발 | 동일한 개발 재료 | 대표 테마 `호남 개발`에 연결 |
| 호남클러스터 | 위와 같은 개발 사업·정책을 가리킴 | 같은 대표 테마에 연결하고 원래 이름 보존 |
| 호남○○ | 같은 재료의 다른 표현으로 확인됨 | 같은 대표 테마에 연결 |
| 호남 지역의 별개 산업·사업 | 지역명은 같지만 다른 재료 | 독립 테마 또는 상하위 관계 후보로 구분 |

위 표는 사용자의 문제를 설명하는 예시다. 특정 실제 사업들이 동일하다는 사실 판단이 아니다. 핵심은 **같은 재료의 다른 이름은 합치고, 실제 다른 재료는 구분하는 것**이다.

초기 연결 순서는 다음처럼 제안한다.

1. 띄어쓰기·괄호 등 단순 표기를 정리한다.
2. 해당 프로필에서 사용자가 이미 정한 대표명·별칭을 먼저 찾는다.
3. LLM이 기존 테마 목록과 기사·사건의 맥락을 보고 기존 테마 연결 또는 신규 테마를 제안한다.
4. 이미 확정된 별칭은 반복해서 새 테마를 만들지 않고 자동 연결한다.
5. 모호한 연결은 보류 상태로 남겨 현재 변경 미리보기에서 조정할 수 있게 한다.

문자열 유사도만으로 자동 병합하지 않는다. 같은 지역·정책·산업이라는 이유만으로 모두 하나로 합치는 것도 피한다. 같은 이름이 문맥에 따라 다른 뜻이면 문맥 조건을 가진 별칭으로 다룬다. 상하위 관계는 실제 사례에서 필요해질 때 추가하고, 처음부터 거대한 분류체계를 요구하지 않는다.

### 한 번 수정한 결과가 다음 갱신에도 유지되어야 한다

사용자가 `호남클러스터 → 호남 개발`로 합쳤다면 그 연결을 다음 LLM 실행에도 적용한다. 반대로 사용자가 다른 재료라고 분리한 관계는 다시 자동 병합하지 않도록 기록한다. 별칭 적용 범위는 우선 프로필 기준으로 두어 서로 다른 프로필의 분류 의도를 보존한다.

사용자 직접 수정 항목과 AI 갱신 항목을 구별한다. 사용자 수정은 재분석 때 무조건 덮어쓰지 않으며, 새로운 근거로 변경이 필요하면 변경 후보로 제시한다. 갱신 범위 밖의 종목이나 이번 분석에 나오지 않은 관계를 자동 삭제하지 않는다. 추가·변경·만료는 각각 근거를 가진 작업으로 다룬다.

화면은 간단하게 유지하되 내부에는 프로필, 테마 식별자, 대표명, 원래 표현, 종목 연결, 근거 기사·사건, 판단 시각, AI/사용자 출처, 병합·분리 이력을 남긴다. 이 정보는 기존 프로필을 뒷받침하는 메타데이터이며 사용자에게 또 다른 분류 체계를 요구하는 것이 아니다.

### 집계와 과거 복기

같은 테마의 별칭 여러 개에 연결된 같은 종목은 **그 대표 테마 안에서 한 번만 집계**한다. 서로 다른 테마에 걸친 종목은 각 테마에 등장할 수 있으므로, 테마 전체 합계를 중복 없는 시장 총액처럼 표시하지 않는다.

대표 테마로 종목들이 제대로 모인 뒤에 테마 활동도를 구체화한다. 초기에는 관측 종목 수·등락·거래대금·관련 사건 등 확인 가능한 항목을 보여주고, 강도 공식과 대장 판별 기준은 실제 사용하며 조정한다. 조회 상위20 집계라는 현재 범위도 유지해 표시한다.

테마 수정은 현재 화면에 반영하되 과거 판단 당시의 관계를 덮어쓰지 않는다. 복기에서는 `당시 분류`와 `현재 기준으로 다시 묶은 분류`를 구별한다. 기존 병합·분리는 이름과 종목 연결을 바꾸는 기반으로 재사용하되, 별칭·수정 이력·되돌리기는 확장 과제다.

테마 첫 버전의 완료 기준:

- 같은 재료의 서로 다른 명칭이 하나의 대표 테마로 모인다.
- 사용자의 병합·분리 결과가 LLM 재실행 후에도 유지된다.
- 기존 수동 프로필과 AI 저장 대상 프로필이 의도치 않게 섞이지 않는다.
- 별칭 중복으로 종목 수·거래대금이 증가하지 않는다.
- 잘못 묶인 관계를 수정하고 되돌릴 수 있다.
- 출처·관측 시각과 과거 분류를 확인할 수 있다.

## 4. 타점 기획: 학습이 진행되어도 바꿀 수 있는 구조

타점 엔진의 세부 전략은 미정으로 남긴다. 첨부의 주도주 돌파는 첫 연구 후보로 참고하되, 문서에 등장하는 수치나 현 분류기의 조건을 완성된 매매법으로 확정하지 않는다. 지금 사용자에게 어떤 진입·청산 기준이 정답인지 결정하도록 요구하지 않는다.

논리적 역할은 다음처럼 구분하면 이후 개선하기 쉽다. 각각을 별도 서버나 서비스로 만들 필요는 없다.

| 역할 | 답할 질문 | 초기 취급 |
|---|---|---|
| 시장·재료 맥락 | 어떤 사건·테마·시장 상황인가? | 근거·범위·시각을 제시 |
| 관찰 후보 | 왜 이 종목을 보고 있는가? | 조회순위·사용자 관심·재료 등 유입 사유를 구분 |
| 가격 구조·조건 | 어떤 형태이고 무엇을 더 확인해야 하나? | 현재 분류를 참고하되 관측과 해석을 구분 |
| 행동 판단 | 기다릴지, 진입·보유·축소할지? | 기준이 구체화된 뒤 관찰용 정책부터 적용 |
| 비용·위험·실행 | 행동의 비용·위험과 실제 처리 결과는? | 검증 단계에서 별도로 연결 |

주도주 여부와 돌파 모양은 별도 판단이다. 가격이 고점을 넘었다는 사실만으로 시장의 주도주라고 확정하지 않는다. 마찬가지로 테마에 속한다는 사실과 그 테마가 현재 활발하다는 판단도 구분한다.

### 학습하는 동안 먼저 유용한 기능

기존 차트·일지에 관심 구간과 메모를 남기고, 관련 뉴스·테마·분류 결과를 함께 볼 수 있게 한다. 실제 매수·매도한 사례뿐 아니라 관찰만 한 사례, 놓친 기회, 피한 사례, 실패와 애매한 사례도 보관한다. 사용자가 아직 설명하지 못하는 사례는 `미정`으로 저장할 수 있어야 한다.

사례에는 다음 정도면 출발할 수 있다.

- 무엇을 보고 관심을 가졌는지와 그 시각.
- 당시 볼 수 있었던 가격·거래대금·뉴스·테마.
- 사용자의 생각, 나중에 추가한 해석, 확인하지 못한 점.
- 적용한 규칙 또는 아직 규칙을 정하지 않았다는 상태.
- 이후 관측 결과와 실제 체결 여부.

이후 배운 내용을 규칙 초안에 반영하고 같은 사례에 적용한다. `이전 기준은 어떤 이유로 후보로 봤고, 새 기준은 무엇을 다르게 보나`를 비교할 수 있어야 한다. 사용자 메모·강의 설명·AI 제안·실제 결과는 출처를 구별한다. 사용자의 의견을 자동으로 정답 라벨이나 모델 훈련 승인으로 바꾸지 않는다.

### 기준 관리

기존 전략팩의 초안·검토·버전 기능을 재사용한다. 규칙은 `학습 메모 → 가설 → 관찰 실험 → 검증된 적용 범위`로 발전할 수 있게 하고, 새 규칙이 기존 판단 기록을 덮어쓰지 않게 한다.

진입 조건, 진입 제외 조건, 보유 판단, 시나리오 무효화, 계좌 위험 제한은 각각의 역할을 유지한다. 거래대금·시간대·추가매수·분할익절·재진입 기준은 나중에 구체화한다. 현재 신뢰도 점수는 조건 일치 설명으로 취급하고, 검증된 확률이 생기기 전에는 성공확률로 표시하지 않는다.

## 5. 공통 기반: 당시의 판단을 나중에도 설명할 수 있어야 한다

테마와 타점 기준이 바뀔수록 당시 입력과 기준의 기록이 중요해진다. 처음부터 많은 테이블을 만드는 대신, 실제로 사용하는 기록부터 다음 정보를 연결한다.

| 기록 | 핵심 내용 |
|---|---|
| 관찰 집합 | 그 시각의 종목·순위·선정 사유·편입과 이탈·관측 범위 |
| 관측 | 발생 시각과 수신 시각, 값·단위·집계 구간, 완결 여부, 결측·지연 |
| 뉴스·테마 근거 | 원문·사건 참조, 당시 이용 가능 시각, 프로필·테마 관계 버전 |
| 판단 | 판단 시각, 입력 참조, 규칙 버전, 상태·근거·미확인 조건 |
| 결과 | 실제 또는 모의 구분, 관측 종료 여부, 비용·체결 가정, 평가 버전 |

기존 운영 캐시와 연구용 기록의 보존 목적을 구분한다. 캐시 정리로 연구 사례의 근거가 사라지지 않도록 선택된 사례와 관측 기록의 보존 범위·저장량을 따로 설계한다. 기간은 실제 저장량과 필요한 연구 범위를 보고 정한다.

첫 기록은 현재 분봉·순위·사건 변경만으로 시작할 수도 있다. 초 단위 스냅샷이 필요하면 별도 기록 기능과 누락 표시를 도입한다. 이를 진짜 1초 OHLCV나 원본 틱이라고 부르지 않는다. 과거에 저장하지 않은 고해상도 경로는 복원됐다고 간주하지 않는다.

### 실시간·재생으로 확장하기 전에 점검할 기존 의미

- 범용 전략 평가기는 최종 진입 분봉의 고저·대금과 날짜 필터가 없는 일봉 입력을 사용할 수 있다. 복기 함수의 값을 그대로 실시간 신호에 쓰기 전에 시점 필터와 완결 봉 기준을 정한다.
- 체결 뉴스 연결에는 체결 후 5분 이내 발행 기사도 포함될 수 있다. 사후 복기용 연결과 당시 알 수 있던 뉴스 집합을 분리한다.
- 스냅샷은 사후 보충 시 갱신된다. 최초 관측과 보충본을 구별하는 기록이 필요하다.
- 현재 1분 거래대금, 완료된 1분봉 합, 고정 시각 구간 합은 다르다. 화면과 정책 입력의 집계 의미를 명시한다.
- 조회 Top20에서 빠진 종목을 보유·관찰 이유로 계속 추적하는 정책은 추가 설계가 필요하다.

이 항목은 이번에 수정한 버그 목록이 아니라 **기존 기능을 다른 목적에 재사용할 때 필요한 설계 조건**이다.

## 6. 뉴스·Market Intelligence와 운영 배치

기존 종목 뉴스 수집·사건 묶음·원문 분석을 재사용한다. 다음 확장은 기사 수를 늘리는 것보다 같은 사건의 후속 보도와 새 사건을 구분하고, 그 사건을 대표 테마·종목과 연결하는 데 우선순위를 둔다.

종목 기억은 사건·테마·가격 반응의 사례가 축적되며 만들어지도록 한다. 장전에는 전일 관심의 연속성과 새 재료, 장중에는 변경된 사실, 장후에는 당시 판단과 이후 결과를 연결한다. 초기에는 자료가 있는 종목·기간만 보여주며 시장 전체를 이해했다고 표시하지 않는다.

첨부의 로컬 LLM·NAS 방향은 향후 배치안으로 검토한다. 현 저장소에는 해당 연결을 확인하지 못했으므로 실제 서비스·저장소·인터페이스·운영 여건을 확인한 뒤 재사용한다. 기존 SQLite를 당장 이전하거나 새 서버를 선행 구축할 이유는 없다.

로컬 LLM은 사건·테마 의미 해석에 활용하고, 초단위 가격 집계나 위험 처리가 매번 LLM 응답을 기다리게 하지 않는다. 분석이 지연되면 마지막 분석 시각·대기 상태를 보여준다. 기존 사용자가 선택한 외부 뉴스 AI는 별도 기능으로 유지할 수 있다. 신규 로컬 분석 경로는 첨부 방향에 맞춰 외부 API로 자동 대체하지 않고 분석 대기 상태로 남기는 것을 초기 설계로 제안한다.

| 장전 | 전일 관심의 연속성, 새 사건, 오늘 확인할 조건 | 뉴스와 관심 사례를 요약하는 패널 |

핵심 화면에는 `현재 상태 / 근거 / 더 확인할 조건 / 자료 시각`을 우선한다. 내부 모델 이름·데이터 계약·원장 구조를 메인 매매 화면에 늘어놓지 않는다. AI 테마를 쓰는 일도 기존 프로필을 선택하고 필요할 때 묶음을 조정하는 흐름 안에서 해결한다.

## 8. 개발 순서와 완료 기준

날짜·공수는 운영 환경과 다음 구현 범위를 확인한 뒤 산정한다. 타점 학습이 진행되는 동안에도 1단계와 2단계는 독립적으로 진척할 수 있다.

| 단계 | 사용자에게 생기는 가치 | 주요 작업 | 완료 기준 |
|---|---|---|---|
| 0. 현재 기준 정리 | 현재 기능과 목표의 차이를 알 수 있음 | 이 기획과 코드 근거 정리, 실제 배포·NAS·자료 범위는 후속 확인 | 코드 확인과 미확인이 구분됨. 이번 문서로 코드 기반 초안 작성 |
| 1. 프로필 기반 AI 테마 | 같은 재료가 한 테마로 모이고 수정이 유지됨 | 기존 프로필 연결, 대표명·별칭, 근거, 병합·분리 기억, 갱신 미리보기 | 3절의 사례와 완료 기준 충족 |
| 2. 관측·학습 사례 | 타점이 미완성이어도 나중에 비교할 자료가 쌓임 | 당시/사후 정보 구분, 관찰·미거래 사례, 시각·규칙·테마 버전 기록 | 한 사례의 당시 근거와 나중에 추가한 설명을 각각 재현 |
| 3. 작은 판단 실험 | 새로 배운 기준이 어떤 판단을 바꾸는지 보임 | 이해가 구체화된 한 조건부터 주문 없는 관찰, 이전 기준과 비교 | 같은 입력·버전은 같은 결과, 조건 불충족·자료 부족도 기록 |
| 4. 비용 포함 연구 | 보기 좋은 패턴과 실제 운용 가정을 비교할 수 있음 | 작은 재생, 가상 체결·현금·수량·비용, 시간순 검증, 실패·결측 처리 | 결과 재현과 금액 대사, 비용·해상도 한계 명시 |
| 5. 장중 판단 보조 확장 | 후보부터 보유·축소·재진입까지 검증된 판단을 연결 | 필요 행동을 순차 추가, 관찰 운영과 내부 모의, 조건부 통계 | 과거 재생과 실시간 차이·누락·지연·표본 범위를 설명 |
| 6. 선택적 실행 연결 | 검증된 정책의 주문·체결까지 일관되게 관리 | 별도 범위 합의 후 위험·주문·대사·재시작 처리 | 모의와 실제 결과를 구분하고 운영 조건을 검증 |

1단계의 전체 자동 테마 생성 전에 소수 기사·테마 사례로 명칭 연결과 갱신 동작부터 확인한다. 2단계의 공통 시각·이력 기록은 1단계와 함께 도입할 수 있다. 광범위한 과거 뉴스 백필이나 최종 타점 공식이 준비될 때까지 둘을 미룰 필요는 없다.

비용 계산은 기존 체결·일지·정산 코드를 재사용하되 목적을 확인한다. 현재 예상비용 기본값은 매수 0.015%, 매도 0.215%지만 이는 코드의 기본값이며 모든 계좌·기간에 적용되는 비용으로 검증한 값이 아니다. 미청산 매매에서 0을 반환하는 완결 복기용 함수를 가상 원장 비용 계산에 그대로 쓰지 않는다.

전략의 연구 결과는 순손익뿐 아니라 관측 범위·표본·비용 가정·위험·자료 누락과 함께 본다. 분봉 안에서 발생한 순서를 알 수 없으면 유리한 체결 순서를 만들어내지 않는다. 나중에 확률이나 EV를 표시할 때에도 어떤 사건·기간·정책에 대한 값인지 확인할 수 있어야 한다.

## 9. 변경 가능한 부분과 유지할 원칙

계속 조정할 대상은 테마 이름·별칭·그룹 수준, 테마 활동도·주도주 판단, 타점 형태·조건, 시간대·대금 기준, 보유·증감·청산·재진입 정책이다. 변경 때는 이유와 적용 버전을 남기고, 이전 사례에 어떤 차이를 만드는지 비교한다.

유지할 원칙은 원래 관측과 사후 해석의 구분, 근거·버전 보존, 사용자 테마 수정 존중, 같은 테마 안의 중복 집계 방지, 기존 실시간 모니터의 응답성이다. 기존 판단 기록은 최신 기준으로 덮어쓰지 않는다.

다음 구현 단위로는 **프로필 기반 테마 명칭 연결과 수정 유지**, 그리고 **관찰 사례의 시각·근거 기록**을 권한다. 타점 전략의 완성은 이 작업의 선행 조건이 아니다.
