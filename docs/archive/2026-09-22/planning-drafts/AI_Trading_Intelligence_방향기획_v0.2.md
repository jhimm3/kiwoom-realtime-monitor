## 1. 최우선: 기존 후보에 과거 시세·뉴스를 채운다

**기존 주도후보를 기준으로 대신증권의 과거 분봉과 네이버 증권 사이트 뉴스를 확보한다.** 이를 지금까지 쌓인 데이터 및 2.1.0의 저장·연구 기능에 연결해 LLM 분석·학습과 전략 연구용 데이터셋을 만든다.

| 사용자 방향 | 기획에 반영할 내용 |
|---|---|
| 기존 주도후보 사용 | 지정 DB의 `candidate_days`를 수집 출발점으로 재사용 |
| 최근 2년 | 기존 데이터 + 대신 1분봉, 중첩 5분봉·뉴스 연결 |
| 최근 2년 이전~최근 5년 | 대신 5분봉 + 기존 일봉·후보·확보 가능한 뉴스 |
| 뉴스 경로 | 네이버 개발자 검색 API를 과거 수집의 중심으로 삼지 않고 네이버 증권 사이트 경로 우선 검증 |
| LLM 학습 | 뉴스·사건·테마와 시세·결과가 연결된 사례 자료를 먼저 구축 |
| 테마 | 기존 프로필에 LLM 결과 저장. 같은 재료의 다른 표현은 대표 테마·별칭으로 연결 |
| 타점 | 사용자의 학습과 실제 사례를 반영해 기존 엔진을 계속 개선 |

타점의 세부 기준을 완성하는 일은 데이터 확보의 선행 조건이 아니다. 첨부 문서의 구현 명령을 이번 기획 요청의 실행 지시로 취급하지 않았으며, 이번에는 기획만 수정했다.

## 4. 대신증권 과거 시세 수집 기획

공식 담당자의 2026-09-01 답변에서 주식 기준 **1분봉 약 2년·5분봉 약 5년** 제공 안내를 확인했다. 실제 종목별 가장 오래된 날짜와 누락은 표본 수신으로 검증한다. [공식 제공기간 답변](https://money2.daishin.com/e5/mboard/ptype_basic/Basic_018/DW_Basic_Read_Page.aspx?boardseq=60&m=9508&p=8827&page=1&searchString=&seq=29008&v=8636)

| 구간 | 보존할 자료 | 활용 범위 |
|---|---|---|
| 최근 2년 | 대신 1분·5분, 기존 키움 분봉, 실제 보유한 NAS 관측 | 세밀한 장중 사례·정책 연구, 공급자 비교 |
| 2년 이전~최근 5년 | 대신 5분, 기존 일봉·후보 | 5분 수준 구조·뉴스 반응·정책 연구 |
| 5년 이전 | 기존 일봉·후보와 확보 가능한 뉴스 | 일 단위 사건 기억·분석 |

최근 2년의 1분·5분은 중첩 자료다. 7년치 분봉으로 합산하거나 독립 사례로 두 번 학습시키지 않는다. 중첩 구간에서는 1분을 5분으로 집계한 값과 공급자 5분봉을 비교한다. 5분에서 1분·1초 내부 경로를 만들지 않는다.

수집 시작일과 실제 응답으로 기간 경계를 고정한다. 조회가 늦어지면 가장 오래된 자료가 제공 범위 밖으로 밀릴 수 있으므로 표본 검증 후 확보를 우선한다.

### 후보와 수집 구간

`candidate_days`의 종목·날짜를 읽어 같은 종목의 중복 구간을 합친다. 후보일뿐 아니라 판단에 필요한 선행 구간과 결과 평가 구간을 명시한다. 앞뒤 기간은 설정으로 관리하고 같은 종목의 5년 전체를 후보일마다 반복 요청하지 않는다.

분봉은 `CpSysDib.StockChart`의 개수 요청과 연속조회로 필요한 구간까지 내려가는 방식이 공식 안내다. 요청 잔여량·대기시간을 확인해 재개하고, 날짜 입력만으로 범위 요청이 된다고 가정하지 않는다. [공식 연속조회 안내](https://money2.daishin.com/e5/mboard/ptype_basic/Basic_018/DW_Basic_Read_Page.aspx?boardseq=60&m=9508&p=8827&page=1&searchString=&seq=26051&v=8636)

### 출처와 해상도

기존 외부 SQLite `minute_bars`의 키는 `(code, ts)`이며 공급자·1분/5분 구분이 없다. 대신 5분봉을 같은 키에 바로 적재해 기존 값을 덮어쓰지 않는다. 기존 중앙 계약에 맞춰 **공급자·봉 주기·거래소·세션·수정주가 기준**을 구분한다.

키움·대신 원본은 각각 보존하고 연구 입력의 출처 선택 규칙을 고정한다. 값이 다르면 단위, 수정주가, 거래소·세션, 봉 시각이 시작인지 끝인지부터 비교한다. StockChart의 거래소·세션·수정 여부 기본값을 방치하지 않는다. [공식 도움말](https://money2.daishin.com/e5/mboard/ptype_basic/HTS_Plus_Helper/DW_Basic_Read_Page.aspx?boardseq=284&m=9508&p=8839&page=1&searchString=StockChart&seq=102&v=8642)

수집 이력에는 요청 범위·실제 첫/끝 시각·행수·누락·재개 지점·오류를 남긴다. `처리 완료·자료 없음·부분 확보·확보 확인·오류`를 구분한다. 기존 자료의 일괄 교체나 자동 후보 재계산은 이 단계에 필요하지 않다.

## 5. 네이버 증권 사이트 과거 뉴스

사용자가 지정한 사이트 경로를 우선한다. 앱의 기존 네이버 검색 API를 실행하고 사이트 과거 수집이 완료됐다고 보고하지 않는다. 종목별 목록·시장 속보 중 실제 지원 경로는 과거 날짜 표본에서 확인한다.

이미 [backfill_news.py](C:/Users/pc-1/Desktop/kiwoom_history_backfill/backfill_news.py)가 있다. 사이트 속보·공지·해외뉴스와 일반 네이버 웹뉴스 검색을 사용한다. 후보 연결, 기사 중복키, 출처, 원응답, 작업 상태 기반을 재사용한다. 일반 웹뉴스 검색은 네이버 증권 종목별 뉴스 목록과 다르다.

현재 파일에는 `get_stock_search_names()` 호출과 정의의 불일치가 정적으로 확인됐다. 검색 대상 날짜를 기사 발행값으로 저장하는 경로는 정확한 발행시각을 덮을 수도 있다. 구현 전 재현·보완할 항목이며 이번에는 수집기를 실행·수정하지 않았다.

### 표본 검증

최근·2년 경계·5년 경계에서 소수 후보를 골라 날짜 조회·페이지 이동·가장 오래된 도달 범위를 확인한다. 목록, 본문, 구간의 완전성은 별도 결과로 기록한다. 이번 웹 조사에서는 현재 종목 뉴스 페이지 본문을 확인하지 못했으므로 5년 전체 수집 가능성을 확정하지 않는다.

Npay 공식 도움말에는 증권정보를 서비스 화면 밖 개인 프로그램 등에 재가공해 이용하는 것을 제한하는 안내가 있다. 뉴스별 목록·본문 저장과 학습 이용의 적용 범위는 별도 확인 항목이다. 사이트 접근 가능성과 저장·이용 범위를 구분해 수집 방식을 정한다. [공식 이용 안내](https://help.pay.naver.com/faq/content.help?faqId=17106)

### 저장·연결 원칙

- 후보일 및 선행 재료 기간을 연결하고 같은 종목의 겹치는 기간은 합친다. 후보일 당일 기사만으로 전일·주말 재료를 놓치지 않게 한다.
- 기사 ID·URL로 중복 제거하고 종목·테마 관계를 별도 연결한다. 여러 후보에 나온 기사를 여러 독립 사건으로 세지 않는다.
- 제목·매체·원문 URL·발행/수정/실제 수집시각·시각 정밀도·본문 확보 상태를 보존한다. 날짜만 확인되면 시각을 만들어 넣지 않는다.
- 페이지에서 발견된 사실과 해당 기업에 직접 관련된다는 판단을 구분한다. 당시 종목명·상호변경은 코드 기준으로 연결한다.
- 요약만 확보한 기사와 본문까지 확보한 기사를 구분한다.
- 기존 중앙 기사·본문·AI·사건 revision 및 영속 작업 경로를 재사용한다. 최신 표시용 캐시를 장기 연구 원본과 동일시하지 않는다.

## 6. LLM 분석·학습용 사례 연결

사용자가 말한 학습 목표는 과거의 뉴스·재료·테마와 가격 움직임을 함께 활용하는 것으로 반영한다. 자료 확보와 모델 가중치 학습은 다른 단계이므로 먼저 다음 사례 묶음을 만든다.

```text
기존 후보 날짜·종목·선정 이유
 + 뉴스·사건·테마 근거
 + 같은 종목·시각의 일봉/1분봉/5분봉 및 실제 보유 관측
 + 계산한 특징과 이후 결과
 → 출처·해상도·입력 시각·결과 기간이 명시된 사례 데이터셋
 → LLM 사건/테마 해석·사례 검색·필요한 학습
 → 기존 연구 엔진의 정책 비교와 검증
```

LLM에는 뉴스 사실·해석·테마 관계와 비교 가능한 시세 특징을 연결한다. 수익률·거래대금·경로 계산은 기존 코드로 만들고 출처를 붙인다. 모든 분봉 숫자를 프롬프트에 넣는 것과 유효한 매매 능력 학습을 동일시하지 않는다.

검색용 기억 구축, 지도 예제 작성, 가중치 미세조정의 구체적 방식은 소수 사례의 품질과 모델·장비 여건을 보고 정한다. 원본 확보만으로 LLM 학습 완료를 표시하지 않는다. 타점 개선도 이 데이터셋과 기존 정책 비교 기반에서 진행한다.

연구 연결 시 다음을 유지한다.

1. 사후 후보 목록을 당시 아침에 알려진 조회 Top20로 바꾸지 않는다. 가짜 순위 없이 역사 후보 사례 연구라는 모집단을 표시한다.
2. 후보 안의 실패·무반응·미거래 사례도 남긴다. 후보 자료만으로 비후보까지 포함한 전체 시장 성과를 입증했다고 하지 않는다.
3. 지금 수집한 과거 뉴스·봉의 실제 수집시각은 지금이다. `available_at`을 과거로 조작하지 않는다. 당시 수신이 기록된 재생과 발행·봉 시각을 가정한 과거 복원 연구를 구분한다.
4. 최신 LLM의 과거 기사 해석도 사후 생성 자료다. 학습자료 작성과 당시 실시간 성능 검증을 구분한다.
5. 같은 종목·사건의 중복 기사와 1분/5분 중첩 구간을 훈련·검증 양쪽에 흩뿌리지 않는다. 기존 시간순 검증·미사용 평가 구간 계약을 재사용한다.
6. 기존 strict TOP20/KRX 연구 입력과 새 후보집합이 다르면 어댑터·지원 정책을 명시한다. 필수 순위·1초 자료가 없는 전략은 미지원으로 남긴다.

## 7. 테마: 기존 프로필과 의미별 명칭 연결

LLM 결과는 기존 프로필에 저장한다. 예를 들어 `AI 테마` 프로필을 선택하면 기존 배지·집계에 그 결과가 적용된다. 이름과 개수는 예시이며 기존 편집·미리보기·NAS 동기화·시점별 스냅샷을 재사용한다.

사용자 예시의 `호남개발·호남클러스터·호남○○`가 같은 개발 재료를 가리킨다면 대표 테마 `호남 개발`에 연결하고 원래 표현은 별칭으로 보관한다. 같은 지역명이라는 이유만으로 다른 사업까지 합치지 않게 사건·정책·사업 맥락을 함께 본다. 이는 분류 동작 예시이며 특정 사업의 동일성을 검증한 결과가 아니다.

연결 순서는 표기 정리 → 해당 프로필의 확정 별칭 조회 → 기존 테마와 의미·근거 비교 → 연결 또는 신규 후보 생성으로 제안한다. 사용자 병합·분리 결과를 다음 LLM 실행에서도 유지하고 직접 수정한 관계를 무조건 덮어쓰지 않는다.

내부 식별자와 표시명을 구분한다. 별칭 적용은 우선 프로필 범위로 두고 사용자/AI 출처와 변경 근거를 남긴다. 이번 분석에 나오지 않았다는 이유만으로 기존 관계를 삭제하지 않는다.

같은 종목이 한 대표 테마의 여러 별칭에 연결돼도 그 테마 안에서 한 번만 집계한다. 다른 테마 사이에는 종목이 겹칠 수 있으므로 테마 합계를 시장 전체 금액으로 표시하지 않는다. UI의 조회 상위20 집계와 연구의 관측 범위도 각각 표시한다.

기존 중앙 테마 revision에 대표명·별칭·사용자 결정 근거를 연결한다. 당시 분류와 지금 다시 정리한 분류를 구별한다. 강도·대장 기준은 기존 연구 모듈과 실제 사용 사례로 조정한다.

완료 기준은 같은 재료 명칭 통합, 반복 갱신에도 사용자 수정 유지, 프로필 분리, 중복 집계 방지, 잘못된 연결의 수정·되돌리기와 근거 확인이다.

## 8. 타점: 기존 엔진을 계속 개선

돌파·눌림 재가속 판단, 후보 감시, 연구·재생·비교 기반은 이미 있다. 이를 현재의 잠정 정책으로 취급한다. 사용자에게 학습 전에 진입·손절·익절 정답을 정하도록 요구하지 않는다.

관심 이유·가격 형태·실제 매매 여부·애매하거나 실패한 이유를 기존 차트·일지·전략팩과 연구 피드백에 연결한다. 거래하지 않은 사례도 비교한다. 새로 배운 조건은 초안으로 만들고 같은 자료에서 이전 정책과 달라진 점을 확인한다.

시장 주도주 여부와 가격 돌파 형태, 테마 소속과 현재 활동도를 구분한다. 조건 일치 점수를 검증된 승률로 바꾸지 않는다. 거래대금·시간대·보유·증감·청산·재진입 기준은 이후 사례와 검증으로 조정한다.

새 규칙은 새 정책·평가 버전으로 남기며 과거 판단·사용자 복기·미사용 검증자료를 덮어쓰지 않는다. 과거 데이터 확보를 위해 기존 자동 모의운용이나 실전 권한을 변경할 필요는 없다.
