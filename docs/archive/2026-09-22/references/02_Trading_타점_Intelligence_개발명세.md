## 0. Codex에게 먼저 전달할 실행 지시

기존 시장·테마·뉴스·타점·포지션 엔진과 시세 수집 경로를 먼저 확인하고, 동일 기능을 새로 만들지 마라. ①의 API·스키마는 읽기 중심으로 소비하고 뉴스 원본·Stock Memory 계산을 복제하지 마라.

처음에는 **현재 수집 데이터의 정확한 의미 확인 → 공통 특징 → 돌파 기준선 → 판단 기록·재생**만 구현한다. 실거래·미수·자동 주문은 이 문서만으로 활성화하지 않는다. 후보 신호와 실제 체결 상태를 섞지 않는다.

본 문서의 모듈명·필드·설정·경로는 제안이다. 존재 여부를 조사하고 실제 저장소에 맞춰 최소 변경으로 구현한다. 모델이 아직 없으면 `규칙 기준선`, `확률 미추정`, `분석 대기`가 올바른 결과다.

## 1. 제품이 답해야 하는 질문

1. 오늘/현재 주목할 종목이 있는가? 없으면 쉬는가?
2. 그 종목을 주목하는 뉴스·테마·전일 연속성은 무엇이며, 실제 가격·거래가 이를 확인하는가?
3. 지금 **처음 진입**, **추가매수**, **보유**, **일부 매도**, **전량 청산**, **재진입** 중 무엇을 검토할 상황인가?
4. 그 판단은 어떤 새로운 관측으로 바뀌었고, 무엇이 생기면 무효가 되는가?
5. 자료가 충분한가? 판단을 내리지 않는 편이 맞는가?

②는 이를 구조화하여 ③으로 보낸다. **행동 후보를 찾는 것과 비용 차감 기대값을 검증하는 것, 최종 주문 허가는 각각 다르다.**

## 2. 범위와 초기 전략

### 2.1 초기 중심

사용자가 이해하는 주도주 돌파를 초기 중심으로 한다.

```text
기존 관심 후보
  → 충분한 관측·거래·맥락 확인
  → 이미 정의된 가격 구조에 접근
  → 돌파/확인 조건 관측
  → 최초 진입 후보
  → 확인 강화 시 증액 후보
  → 약화 시 유지·축소·청산 비교
  → 새로운 기회가 생기면 재증액·재진입 후보
```

매매를 한 번의 BUY와 한 번의 SELL로 단순화하지 않는다. 그러나 첫 구현부터 모든 행동의 학습모델을 만들지는 않는다. **Entry/Hold/Exit의 재현 가능한 기준선** 이후 Add/Reduce/Re-entry를 단계적으로 확장한다.

### 2.2 나중에 추가할 전략

주도주 안의 짧은 파동·스캘핑, 비주도주 통계 패턴, 종가베팅, 상한가 관련 전략 등은 별도 정책 ID·데이터 조건·검증 결과가 있을 때 추가한다. ‘스캘핑=몇 %’, ‘주도주=고비중’ 같은 고정 연결은 하지 않는다.

종가베팅은 다음 거래일 갭·야간 위험·세션 종료·결제까지 필요한 다른 정책이므로, 초기 장중 정책을 단순히 장 마감 후까지 켜두는 방식으로 구현하지 않는다.

## 3. 기존 ①과의 연결

①에서 다음을 읽는다.

- `Market State`: 지수 방향뿐 아니라 참여·편중·테마 집중·분산과 확인/반대 근거.
- `Theme`: 수동 관계와 자동 후보를 구분한 시점별 관계·상태.
- `Stock Memory`: 이전 강세·거래대금·주도 역할·살아 있는 사건과 연속성.
- `Event Revision`: 새로운 재료·정정·취소·후속 진행과 근거 시각.

기존 ① 제안 API가 실제 구현되어 있으면 재사용한다.

```text
GET /api/mi/v1/market-state?as_of=...&run_id=...
GET /api/mi/v1/themes?as_of=...&status=...
GET /api/mi/v1/stocks/{security_id}/memory?as_of=...
```

아직 없는 엔드포인트는 구현 완료로 취급하지 않는다. 검증된 기존 내부 계약이나 fixture로 개발하되 상태를 구분한다. 이전 판단을 바꾸지 않고 새 스냅샷을 연결한다.

LLM이 잠시 꺼져도 체결·가격 감시가 멈추지 않는다. 마지막 스냅샷의 신선도와 사용 조건을 검사한다. 맥락이 꼭 필요한 전략은 신규 진입을 대기할 수 있지만, 이미 보유한 포지션의 보호 절차를 LLM 응답까지 기다리지 않는다.

## 4. 종목 집합과 수집 범위

### 4.1 Top20은 현재 관심 후보군

초기에는 기존 실시간 조회 Top20을 재사용한다. 조회순위와 거래대금 순위, 테마 내 주도 순위를 별도 값으로 기록한다. 조회순위만 높다고 주도주·매수 대상으로 확정하지 않는다.

순위가 30초 등 별도 주기로 갱신된다면 마지막으로 수신한 순위를 그 시각과 함께 유지한다. 1초 시세 행에 같은 순위를 복사했다고 1초마다 새 조회순위가 관측된 것은 아니다. Top20 밖의 83위→51위 같은 경로를 추측하지 않는다.

### 4.2 좁게 계산하되 선택 과정을 남긴다

```text
기존 Top20·관심 목록           : 기존 경량 시세 기록
실제 후보·구조 접근 종목       : 공통 특징·상태 평가
보유·미체결·청산 진행 종목     : 우선 감시, 필요한 실행 데이터
```

핵심 후보가 보통 소수일 것이라는 사용자의 관찰은 자원 계획의 출발점이다. 매일 후보 1~2개를 억지로 만들거나, 추가로 나타난 유효 후보를 숫자만으로 숨기지는 않는다. 동시 보유 상한은 별도의 승인된 위험 설정이다.

Top20 이탈 시 경량 관측 종료 여부와 결과 관찰의 지속기간을 명시한다. 보유·미체결 종목은 계속 관리한다. 모델 결과의 관찰기간이 끝나기 전에 수집이 중단되면 `OUTCOME_INCOMPLETE`로 남긴다.

### 4.3 호가·틱은 단계적으로

초기에는 Top20 전체 호가창·원본 틱 저장을 요구하지 않는다. 실제 주문·핵심 후보의 체결 품질을 확인할 때 필요한 수준의 호가만 선택적으로 추가할 수 있다. 저장 가능한 데이터와 현재 API에서 실제 제공되는 필드를 먼저 확인한다.

고해상도 수집을 후보 선정 뒤 시작했다면 그 이전 구간의 호가가 없다는 사실을 보존한다. 나중에 호가를 보고 선정했어야 할 시점을 과거에 알고 있었다고 재생하지 않는다.

## 5. 1초 자료를 먼저 감사한다

‘1초 데이터’라는 이름만으로 진짜 1초봉으로 간주하지 않는다.

| 실제 수집 방식 | 정확한 표현 | 가능한 값 | 생성하면 안 되는 값 |
|---|---|---|---|
| 모든 수신 체결을 초 단위 집계 | 수신 체결 기반 1초 OHLCV | 수신 범위 내 OHLC·량·대금·건수 | 원천 피드 누락이 없었다는 보장 |
| 매초 마지막 가격/누적값 저장 | 1초 스냅샷 | 해당 시점 가격·누적 변화 | 그 초의 실제 고가·저가·체결 건수 |
| 누적 거래대금 차분만 저장 | 초 간 누적값 차분 | 두 관측 사이의 누적 증가 | 큰 단일 매도·매수 주체·호가 취소 |

필수 감사 항목: 원천 이벤트 시각, 실제 수신시각, 저장시각, 공급자 필드·단위, 집계 경계, 중복 처리, 누락 감지, 재연결, 누적값 리셋, 세션 범위, 정정 자료 처리.

사후에 더 정확한 자료가 들어와도 **당시 실시간으로 알고 있던 스냅샷**을 조용히 덮어쓰지 않는다. 정정 버전으로 추가하고 실시간 관측 재생과 정정 자료 연구를 구분한다.

### 5.1 제안 데이터 계약

현재 테이블에 매핑하고 중복 원본 테이블을 만들지 않는다. 실제 수집할 수 없는 필드는 null과 품질 상태로 둔다.

```text
security_id / provider_id / venue_scope / session_scope
observation_kind: second_bar | sampled_snapshot | cumulative_delta
event_time / received_at / stored_at / source_sequence
interval_start / interval_end / available_at
last_price
open / high / low / close                  # 실제 집계가 있을 때만
volume / turnover                         # 실제 값 또는 검증된 차분
cumulative_volume / cumulative_turnover
observed_duration_ms / observed_count
coverage_status / quality_flags / source_ref
```

매수·매도 체결 방향, 최대 단일체결, 호가 취소량 등은 검증된 원천이 있을 때만 확장한다. 가격 상승/하락만으로 거래 주체나 주문 취소를 사실처럼 생성하지 않는다.

### 5.2 거래가 없던 초와 못 받은 초를 구분

정상 연결·관측이 확인된 무체결 초와 연결 장애로 없는 초는 다르다. 누락 구간을 거래대금 0으로 메우면 ‘매도 압력 소멸’ 같은 잘못된 판단이 생길 수 있으므로 결측으로 표시한다.

화면용 가격 forward-fill은 가능하지만 `filled_for_display=true`로 구분하고 원본 실제 체결로 집계하지 않는다. 실제 체결 가능 가격을 화면 보간값에서 가져오지 않는다.

## 6. 특징 계산의 공통 원칙

특징 계산은 한 구현을 실시간·재생·연구가 공유한다. ①의 일봉 Stock Memory와 동일한 값을 ②에서 다시 다르게 계산하지 않는다. 비용이 큰 특징은 후보에만 계산하고 같은 `as_of + input_version`이면 재사용한다.

### 6.1 거래대금 창의 정의

`turnover_rolling_60s`는 **완결된 최근 60초**의 합으로 정의한다. 고정 분봉 거래대금, 현재 진행 중인 분의 누적값, 누적값을 1분으로 단순 환산한 추정치와 구분한다.

초별 구간이 `[09:00:00,09:00:01) ... [09:00:59,09:01:00)`이라면 09:01:00 기준 합계는 정확히 그 60개 구간이다. `59초 값 - 00초 값`이 자동으로 한 분을 대표한다고 가정하지 않는다. 경계·샘플 간격·이용 가능 시각을 테스트한다.

누적값 C를 사용하는 경우 동일 세션·동일 범위의 `C(t)-C(t-60s)`가 기본 관계다. 실제 관측 간격이 다르거나 기준값이 없으면 관측 범위·결측을 함께 표시한다. 리셋·음수 차분을 정상 거래대금으로 사용하지 않는다.

금액 저장은 원화 단위 또는 기존 원천 단위를 명시한다. `40억=4,000,000,000원`, `50억=5,000,000,000원` 변환 오류를 테스트한다.

### 6.2 초기 필수 특징

| 계열 | 필수 또는 우선 특징 | 사용 맥락 |
|---|---|---|
| 가격 구조 | 현재가, 과거 확정 고저, 기준 박스, 돌파 거리, 시가 갭 | 지금 위치와 가설 무효화 |
| 거래 | 최근 60초·수분 대금, 감소/회복, 창 완전성 | 신규 진입·증액 적격성 |
| 상대성 | 이전 거래일 동일 시간대 대비 거래대금 | 절대 대금의 종목·시간 왜곡 보완 |
| 전일 기억 | 전일/최근 강세·거래 집중·연관 Event | 연속성·시초 가설 |
| 시장·테마 | ①의 맥락과 현재 수치·반응 | 지수와 실제 매매 환경 분리 |
| 포지션 | 실제 보유·평단·미체결·시나리오 버전 | 행동의 가능 범위 |
| 품질 | 신선도·결측·관측 시작·지원 필드 | 판단 보류·신뢰 범위 |

VWAP, 유통시총 대비 회전, 호가·체결 상세 등은 자료가 확보되고 독립적인 검증 기여가 있을 때 추가한다. 기존에 이미 계산하는 지표라면 의미와 버전을 맞춰 재사용한다.

### 6.3 상대 거래대금

```text
relative_turnover_same_time
  = 현재 완결된 비교 창 거래대금
    / 이전 거래일의 동일 세션·동일 시간 창 기준값
```

기준값은 평균·중앙값 등 정책 버전으로 고정하고 **당일 미래 구간을 포함하지 않는다**. 신규 상장·거래정지·비교 거래일 부족·분모 0은 별도 상태로 처리한다. 작은 분모로 수백 배가 나왔다고 무조건 가장 강한 종목으로 판정하지 않는다.

```text
turnover_to_float_value
  = 동일 창 거래대금 / 당시 확인 가능한 유통시가총액
```

이 값은 금액 회전의 정규화 특징이지 순유입률이나 유통주주 교체율이 아니다. 주식수·유통비율의 시점과 가격 기준을 기록한다. 이미 유통시총인 분모에 유통비율을 다시 곱하지 않는다.

### 6.4 봉과 가격 구조의 시간적 정확성

진행 중인 봉의 최종 고가·거래대금을 미리 사용하지 않는다. 구간 끝에서 확인한 신호를 같은 봉 시작가에 체결시키지 않는다.

양쪽 미래 봉을 보고 확정하는 스윙 저점·지그재그를 즉시 알려진 지지선처럼 사용하지 않는다. 확인에 미래 관측이 필요하면 `confirmed_at` 이후에만 사용한다. 박스 경계·지지선은 생성 시각과 적용 정책을 기록한다.

## 7. 시장 환경과 주도주 후보

### 7.1 지수 방향과 거래 환경을 분리

①의 판단을 재사용하며, ‘좋은 장’ 한 점수만으로 진입하지 않는다.

예시 상황은 모두 가설적 분류다.

- 지수 상승·대형주 집중·중소형주 거래 약화·돌파 후보 부재.
- 지수 보합·한 테마 집중·관측된 종목 상대강도 유지.
- 지수 하락·시장 폭 약화·독립적 사건이 있는 테마만 활성.
- 전체 거래 활발하지만 여러 테마로 분산되고 돌파 실패가 반복.

상승/하락 종목 비율이나 시장 점유율을 Top20만으로 계산했다면 `Top20 내 비율`로 표시한다. 전체 시장 지표로 이름을 바꾸지 않는다. 테마 내 순위도 관측 커버리지를 명시한다.

### 7.2 주도주 판별은 점수 하나로 확정하지 않는다

관심·절대 대금·상대 대금·가격 반응·테마 역할·전일 연속성·뉴스 근거를 별도 관측으로 둔다. 주가 상승, 신고가, 단기 모멘텀처럼 겹치는 신호를 독립 증거 세 개로 합산하지 않는다.

후보 상태는 `UNASSESSED / WATCH / ELIGIBLE / ACTIVE / WEAKENED / INVALID / DATA_BLOCKED` 등 최소 집합으로 표현할 수 있다. 이름은 기존 엔진에 맞춘다. `ELIGIBLE`은 매수 확정이 아니라 해당 정책의 평가 대상이라는 뜻이다.

당일 나중에 가장 많이 오른 종목을 과거부터 `ACTIVE leader`였던 것처럼 라벨링하지 않는다. 당시 후보 판단과 사후 결과 라벨은 별도 열이다.

## 8. 장전 시나리오 계약

### 8.1 시나리오는 조건부 계획

LLM의 ‘오를 것 같다’를 주문 규칙으로 직접 사용하지 않는다. ①의 근거를 받아 **확인 조건·반대 조건·가격 구조·자료 신선도·정책 식별자**를 가진 계획을 만든다.

```text
scenario_id / scenario_version / security_id
created_at / as_of / valid_until_or_review_due
market_snapshot_ref / event_revision_refs / stock_memory_ref
thesis_summary / supporting_evidence / opposing_evidence
continuity_context
branches[]
  branch_id / required_observations / disqualifying_observations
  candidate_policy_id / required_data_capabilities
  structural_invalidation_rule_ref
  risk_profile_ref
unknowns / quality_flags
```

규칙 참조는 검증된 설정/코드 ID다. 자연어에 있는 임의 가격을 LLM이 주문 가격으로 바로 전송하지 않는다. 실제 수치가 없으면 ‘시초 구조 형성 후 갱신’처럼 보류한다.

### 8.2 강세·보통·약세 분기

시장의 단순 상승률 외에도 집중·분산·시장 폭을 분기 입력으로 사용할 수 있다. 위험 한도와 목표 노출은 ③이 계산한다. ②가 ‘약세면 무조건 25%, 강세면 500%’를 임의 확정하지 않는다.

각 분기에는 **진입하지 않음**이 포함될 수 있다. 장전 관심 후보가 장중 주도주가 되지 않아도 오류를 숨기거나 새로운 이유로 과거 가설을 덮어쓰지 않는다.

## 9. 장 초반과 시간대 정책

09:00~09:20은 기본 관찰 가설, 09:20~10:30은 사용자가 관찰한 활동 집중 가설이다. 검증 없이 하드 시간 제한으로 구현하지 않는다.

### 9.1 조기 진입 후보

전일 주도 연속성·현재 유효한 재료·실제 시초 가격 확인·충분한 거래·구조적 무효화 기준이 있다면 09:20 이전에도 후보 생성이 가능하다. 필요한 관측이 부족하면 장전 설명이 좋아도 기다린다.

초기 돌파가 무조건 우수하거나 무조건 위험하다고 라벨링하지 않는다. 관찰 시간과 놓친 기회, 성급한 진입의 손실을 같은 재생 조건에서 비교한다.

### 9.2 오전 이후

시간 경과만으로 청산하지 않는다. 보유·추세 정책의 종료 조건을 따르고, 새 진입은 해당 시간대의 자료·거래·EV·위험 조건을 다시 평가한다. 종가에 포지션을 남길지 여부는 ③의 세션 정책에서 명시한다.

## 10. 돌파 기준선: 먼저 측정 가능한 한 정의

‘돌파’라는 이름만 두지 말고 최초 기준선을 완전히 정의한다. 다음은 **구현 형식의 예시**이지 검증된 파라미터가 아니다.

```yaml
policy_id: leader_breakout_baseline
policy_version: 0.1
status: research_only
reference_level:
  type: prior_window_high
  window_seconds: null           # 데이터 해상도·기존 코드 확인 후 연구 설정
  exclude_current_interval: true
confirmation:
  mode: observed_price_cross
  min_breakout_ticks: null
  persistence_seconds: null
entry_gate:
  require_data_freshness: true
  require_turnover_gate: true
  turnover_threshold_krw: null    # 40억·50억 등은 연구 후보값
exit_policy:
  structural_rule_ref: null
  hard_risk_profile_ref: null
```

실행에 필요한 null이 남아 있으면 거래 정책을 활성화하지 않는다. 사용자 안전 승인값·기존 검증 설정을 재사용하거나, **주문 없는 연구 구성**에서 후보값을 명시한다. 초기에 박스·VWAP·호가·뉴스·모든 시장 지표를 AND로 강제하지 않는다. 가장 단순한 기준선을 먼저 두고 변수의 추가 효과를 비교한다.

같은 조건의 연속 1초 신호는 개별 독립 돌파 수백 건이 아니라 한 돌파 episode일 수 있다. 신호 시작·유지·실패·재시작을 정의한다.

## 11. 행동 후보와 포지션 정책

### 11.1 행동의 의미

| 행동 | 의미 | 기본 조건 |
|---|---|---|
| WAIT | 현재 신규 위험을 만들지 않음 | 정보·조건·EV 부족 또는 무신호 |
| ENTER | 무포지션에서 새 진입 후보 | 진입 적격·구조·무효화 기준 |
| HOLD | 현재 보유 유지 후보 | 시나리오·보호 조건 유지 |
| ADD | 보유량 증액 후보 | 새 증거·추가 진입 적격·③ 위험 여유 |
| REDUCE | 보유량 일부 축소 후보 | 검증된 익절/약화 정책 또는 위험 제한 |
| EXIT | 전량 청산 의도 | 무효화·보호 한도·정책 종료 |
| REENTER | 청산 후 새 진입 후보 | 새 episode·신호·현재 EV 확인 |

부분 익절 후 보유량이 남아 있는 상태에서 다시 사는 것은 실행상 ADD이고, 사용자 화면에는 ‘재증액’으로 설명할 수 있다. 전량 청산 후 새로 사는 REENTER와 로그를 구별한다.

### 11.2 현재가와 과거 체결가

이전에 10,000원에 사서 팔았다는 이유로 10,500원 재진입을 자동 금지하지 않는다. 그렇다고 고점을 갱신했다는 이유로 허용하지도 않는다. **현재 가격·새 보호선·비용·보유기간 기준의 새 기대값**을 ③에서 평가한다.

원금 회복·평단 낮추기만을 이유로 ADD를 만들지 않는다. ‘가격이 올랐으니 불타기는 언제나 안전’도 금지한다. 손실 중 증액 같은 다른 정책은 초기 범위 밖이며 별도 연구·위험 승인이 필요하다.

### 11.3 목표 노출은 ③이 결정

②는 가능한 행동과 근거를 보낸다. ③의 EV·정책이 목표 노출을 제안하고 Risk가 허용량을 정한다. ②가 신호 하나마다 고정 30% 주문을 누적시키지 않는다.

**설명용 고정 자본 예시:** `0→0.3→0.6→0.9→0.4→0.7→1.0→0`은 각 시점의 총 목표 노출이다. 증감은 목표와 실제·미체결 상태의 차이로 계산한다. 실제 기준 순자산이 변할 때는 숫자를 단순 차감하지 않고 수량을 다시 산정한다.

### 11.4 행동하지 않음도 비교 대상

새 정보가 없고 목표 변화가 작으면 같은 보유 상태를 유지할 수 있다. 조건 충족·해제 문턱 차이, 최소 변화량 등으로 불필요한 매매 반복을 줄이는 정책을 연구한다. 이런 지연·중복 방지 장치가 hard 보호 신호를 늦추면 안 된다.

## 12. 거래대금 감소 중 보유 판단

사용자 의도를 다음과 같이 고정한다.

```text
최근 60초 대금: 100억 → 40억
가격 구조: 유지
시나리오: 유효
위험 상태: 허용

→ 거래대금 감소만을 이유로 EXIT하지 않는다.
→ 신규 ADD 적격성은 별도로 재평가한다.
→ HOLD/REDUCE 등의 비교는 정책·EV·위험 근거에 따른다.
```

반대로 거래대금이 많아도 가격 구조 무효·뉴스 정정·위험 한도 위반이면 EXIT 후보 또는 보호 절차가 가능하다. 거래대금은 방향이 아니라 거래 규모이므로 하락 체결이 많아지는 때에도 증가할 수 있다.

거래대금 급감이 **큰 보유량의 출구 위험**을 높이면 ③의 유동성 위험 모듈이 축소를 요구할 수 있다. 이것은 `분당 50억 미만이면 매도`라는 단독 전략 룰과 다르며, 보유액·탈출 시간·호가·위험 조건을 근거로 기록한다.

## 13. 손절·무효화·조건부 관찰

### 13.1 세 가지를 구분

- **가격 구조 경계:** 돌파·지지 가설을 확인하는 수준.
- **조건부 관찰 정책:** 작은 이탈을 즉시 청산할지 제한적으로 관찰할지 사전 정의한 정책.
- **하드 위험 한도:** 계좌·포지션 보호를 위해 더 이상 모델의 판단을 기다리지 않는 제한.

관찰 경계의 이탈을 전부 ‘손절 위반 허용’이라고 표현하지 않는다. 하드 한도는 높은 확신·전일 주도·수익 중이라는 이유로 해제되지 않는다.

### 13.2 조건부 관찰 요구사항

```text
observation_policy_id / version
trigger_rule_ref
max_observation_duration
max_breach_depth
required_data_capabilities / freshness_limit
recovery_confirmation_rule
timeout_action / deterioration_action
hard_risk_profile_ref
```

초기에는 조건부 대기 기능을 OFF로 두거나, 기존에 검증된 명시적 정책만 재생에서 비교한다. 켜기 전에 실패·미회복 사례를 포함해 검증한다. 관찰 중 신규 ADD는 기본 금지한다. timeout이 반복 초기화되어 무한 대기가 되지 않도록 한다.

회복된 뒤에만 알 수 있는 ‘2초 만에 돌아왔다’를 이탈 직후 판단 특징에 넣지 않는다. t+2에 관측했다면 그때부터만 사용할 수 있다.

### 13.3 1초 해상도 제약

1초 스냅샷만으로 ‘누군가 큰 매도를 한 번 던졌다’, ‘0.2초만 이탈했다’, ‘매도물량을 모두 받아냈다’를 단정하지 않는다. 관측된 가격 이동·회복 샘플 수·누적대금 변화로 한정한다. 원인을 모르면 `unknown`이다.

### 13.4 보호선 상향과 버전

새 박스·지지 구조가 관측되고 정책이 허용하면 보호 기준을 높이는 후보를 만들 수 있다. 기존 구조·새 구조·확인 시각·기존/새 위험을 기록한다. 손실을 회피하려고 롱 포지션의 하드 가격 한도를 아래로 옮기는 기능은 초기 금지다. 보호선 변경과 실제 청산 체결가격은 동일하지 않다. [T2]

## 14. 분할익절·재증액·재진입

고정 수익률 도달, 추세 약화, 가격 구조, 테마 변화 등 정책별 후보를 생성한다. ‘오른 폭이 크다’만으로 항상 매도하거나, ‘주도주라서’ 항상 보유하지 않는다.

한 종목의 하루 흐름은 여러 거래 episode를 포함할 수 있다.

```text
campaign_id           # 하루·종목·시나리오 묶음
  episode_id_1        # flat → 보유·증감 → flat
    decision_ids
    order_ids
    fill_ids
  episode_id_2        # 재진입 후 새로운 flat-to-flat 구간
```

수익 일부를 실현한 뒤 재증액해도 동일 캠페인의 비용·최고 순자산·현재 위험은 이어서 본다. 수익 거래만 분리하고 손실 재진입을 다른 통계로 숨기지 않는다.

장기적으로 추세 물량과 짧은 파동 물량을 구분할 수 있으나, 실제 계좌 주문은 ③의 단일 원장·조정자가 합산한다. 서로 다른 정책이 같은 종목을 동시에 사고팔도록 독립 주문 루프를 만들지 않는다.

## 15. 뉴스·테마 급변 시 재평가

①의 새 Event Revision 또는 시장 상태 변경을 받으면 관련 시나리오만 재평가한다. 모든 뉴스마다 모든 종목의 LLM 분석을 다시 하지 않는다.

신규성·정정/취소·근거 품질·실제 가격 반응·이미 알려진 사건과의 관계를 소비한다. 기사 긍정 점수만으로 ENTER하지 않는다. 연관종목 관계가 `proposed`인 경우 확정 테마처럼 취급하지 않는다.

테마 1등주 강세·상한가 유지·이탈 같은 관찰은 관계가 검증된 범위에서만 특징으로 사용한다. 1등주 변화가 다른 종목 상승/하락을 보장하는 규칙은 아니다. ‘방어/헤지 테마’라는 명칭도 손실이 없다는 뜻으로 표시하지 않는다.

## 16. 상태·행동·주문을 분리한 최소 구조

단일 enum에 모든 조합을 넣어 수백 상태를 만들지 않는다. 다음처럼 직교하는 축을 기존 구조에 맞춰 사용할 수 있다.

```text
scenario_status : pending | active | weakened | invalid | expired
position_status : flat | open | closing | unknown
setup_status    : watching | approaching | triggered | failed | none
order_status    : none | pending | partially_filled | unknown
risk_status     : allowed | limited | reduce_only | halted
```

상태가 `triggered`여도 주문은 없을 수 있다. 주문이 승인되어도 미체결이면 포지션은 늘지 않는다. 잔고를 알 수 없으면 새 위험 확대를 멈추고 ③에 대사를 요청한다.

기존 상태 머신이 이미 같은 의미를 표현한다면 새 상태 체계를 통째로 도입하지 말고 매핑한다.

## 18. 알림과 사용자 화면

기존 Top20 화면·종목창을 무단 교체하지 않는다. 작은 배지·상세 패널·판단 타임라인부터 붙인다. 기본 화면은 다음 정도로 유지한다.

```text
A종목 | 돌파 관찰 | 장전 연속성 유지
거래 조건: 충족 / 가격 구조: 확인 대기
현재 행동: 신규 진입 대기
변경 이유: 거래는 회복했지만 기준 가격 돌파는 아직 미확인
통계: 미검증 기준선 / 자료: 09:06:04 기준
```

알림은 `접근 관찰 / 조건 충족 / 가설 약화 / 무효화 / 위험 제한 / 주문 상태`를 구분한다. ‘접근 관찰’은 상승 예언이나 진입 확정이 아니다. 시각·근거·현재/목표 상태·품질을 포함한다.

같은 조건 유지 중 알림을 매초 반복하지 않는다. 상태 변화·새 근거·중요한 위험만 갱신한다. 알림 수신이 늦으면 당시 기회와 현재 조건을 구별한다. 사용자가 알림을 읽기 전에 가격이 변했을 수 있으므로 주문 단계에서 반드시 재검사한다.

## 19. 최소 코드 구조와 설정

아래는 기능 배치 예시다. 기존 파일에 의미가 있으면 재사용하고, 단계별로 필요한 파일만 만든다.

```text
trading_intelligence/
  contracts.py       # 스냅샷·판단 계약
  features.py        # 실시간/재생 공통 계산
  scenarios.py       # 장전·장중 가설 및 버전
  breakout.py        # 첫 기준선 정책
  decisions.py       # 상태 평가와 행동 후보
  integration.py     # 기존 시세·①·③ 연결
  alerts.py          # 기존 알림 경로 확장
  tests/
```

권한·원장·주문 전송은 여기서 중복 구현하지 않는다. 범용 플러그인 프레임워크 대신 정책 ID와 작은 함수 인터페이스부터 시작한다. 새 전략 추가 시 필요한 계약 변경만 최소화한다.

```yaml
trading_intelligence:
  enabled: false
  mode: live_shadow
  primary_policy: leader_breakout_baseline
  universe_source: existing_realtime_top20
  extra_universe_expansion: false
  keep_monitoring_held_and_pending: true
  require_0920_for_all_entries: false
  exit_on_turnover_drop_alone: false
  full_orderbook_for_all_top20: false
  soft_observation_enabled: false
  allow_live_order_submission: false
  allow_leverage: false
```

설정 키는 이 프로젝트의 제안이다. 외부 API가 위 이름을 지원한다는 뜻이 아니다. 핵심 안전 키는 LLM 응답이나 자동 튜닝이 수정할 수 없도록 권한을 분리한다.

## 20. 구현 순서와 완료 기준

### T0 — 기존 구현·1초 의미 확인

실제 수신 필드·단위·시간·세션·Top20 갱신·보유 유지 여부를 조사한다. 기존 엔진에 매핑하고 `확인됨/미실행/미확인`을 구분한다.

**완료:** 가격 스냅샷과 진짜 1초봉을 구분하고, 누락·리셋·단위의 테스트 fixture를 확보한다.

### T1 — 공통 특징과 판단 기록

기존 Top20 기록과 필요한 공통 특징, ①의 읽기 결과 연결을 만든다. 부족한 맥락은 unknown으로 표시한다.

**완료:** 같은 입력·설정·시각으로 실시간 기록과 재생 특징이 일치한다. 원본을 복제하지 않으며 기존 앱 시작·수집 지연을 측정한다.

### T2 — 한 가지 돌파 기준선

Entry/Hold/Exit, 구조적 무효화, 거래대금 진입 게이트, 시간대 조건부 처리를 구현한다. 주문은 보내지 않는다.

**완료:** 실제 또는 합성 소규모 구간을 차트와 대조해 언제 어떤 정보를 보고 판단했는지 확인된다. 임의 승률이 없다.

### T3 — 분할 행동과 ③ 연결

ADD/REDUCE/REENTER 후보, 캠페인·episode, ③ EV/Risk 응답 소비를 추가한다.

**완료:** 부분 매도 후 재증액·완전 청산 후 재진입이 다르게 기록되고, 실제 잔고·미체결 기준을 유지한다.

### T4 — 확장 연구·경량 알림

통계 검증이 있는 정책만 연결하고 조건부 관찰·새 정책은 별도 실험으로 둔다.

**완료:** 기준선과 비교한 검증 근거, 자료 한계, 신호·알림 지연을 보고한다. 실거래 권한은 이 단계에도 자동 추가되지 않는다.

## 22. 확장 시 지켜야 할 원칙

사람이 붙인 전략 이름은 필수가 아니다. 그러나 이름이 없어도 관측 입력·행동·결과·비용·위험·자료 범위는 명시되어야 한다. 사람이 모르는 패턴 후보를 제시할 수 있지만, 발견과 실전 승격 사이의 검증을 생략하지 않는다.

필터를 늘릴수록 안전해진다고 가정하지 않는다. 단순 돌파 기준선 대비 어떤 변수·분기·시간대 조정이 독립적으로 성과를 개선했는지 ③에서 검증한다. 개선 근거가 없는 복잡성은 제거할 수 있어야 한다.

**핵심:** 시황·주도주·거래대금·타점이라는 간단한 화면 뒤에, 시점과 근거가 명확한 상태·행동 계약을 둔다. 복잡한 설명을 만드는 것이 아니라 같은 상황에서 같은 판단을 재현하고 검증할 수 있게 만든다.
