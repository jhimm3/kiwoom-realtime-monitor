# ③ Research·EV·Risk·Execution — Codex 개발 명세

> 버전: 1.0 · 작성일: 2026-09-20  
> 범위: 데이터 연구·정책 평가·확률/기대값·목표 비중·위험 한도·모의/실거래 실행·일일 개선.  
> 연결: ① Market Intelligence의 기억·시장 맥락, ② Trading Intelligence의 상태·행동 후보.  
> 초기 실행: 연구/재생/Shadow. 신규 실거래와 미수는 기본 OFF.  
> 목적: 경험칙을 계산과 전진 검증으로 다듬는다. 높은 백테스트 수익·LLM 자신감·주도주 명칭을 수익 보장이나 레버리지 허가로 사용하지 않는다.

## 0. Codex에게 먼저 전달할 실행 지시

현재 연구·백필·Replay·주문·계좌 원장·비용 계산 코드를 먼저 조사한다. 동일 엔진·운영 DB·백필 DB를 새로 만들지 않는다. ①의 뉴스·시세 원본을 복제하지 않고 기존 NAS 저장·검증 경로와 필요한 파생 스냅샷을 사용한다.

**첫 구현 목표는 수익 모델이 아니라 신뢰할 수 있는 작은 재생이다.** 한 가지 돌파 기준선, 확보된 작은 구간, 명확한 체결 가정, 비용과 수량 대사, 결과와 한계 보고를 완성한다. 자동 학습·자동 배포·미수·강화학습을 한꺼번에 구현하지 않는다.

전략·모델·기간·계좌 한도의 값은 실제 확인 없이 정답으로 채우지 않는다. 승인되지 않은 위험 설정은 연구 전용 또는 미설정 상태로 두며 실거래 활성화를 막는다. 코드를 작성한 것, fixture 테스트 통과, 실제 시세 검증, 모의 체결 검증, 실계좌 검증을 분리해서 보고한다.

## 1. 연구 질문과 목표

사용자가 가진 경험칙의 예시는 다음과 같다.

- 거래대금 40~50억이 어느 종목·시각·계좌 규모에서 유효한 진입 기준인가?
- 같은 돌파도 지수 편중·테마 집중·수급 분산에서 결과가 어떻게 다른가?
- 장전 연속성이 있으면 시초 관찰시간을 줄이는 것이 유리한가?
- 추가매수·분할익절·재증액의 경로가 순손익과 위험에 어떤 차이를 만드는가?
- 작은 구조 이탈은 즉시 청산과 제한 관찰 중 어느 정책이 유효한가?
- 주도주 밖에도 비용·유동성·위험을 통과하는 패턴이 있는가?

질문에 대한 답은 ‘항상’이 아니라 **데이터 범위·상황·정책·비용·검증기간을 명시한 결과**다. 종목·상황마다 임계값을 지나치게 세분화해 사례가 몇 개밖에 남지 않으면 더 정교한 것이 아니라 불확실한 것이다.

초기 목적은 수익률 한 숫자의 최대화가 아니다. **비용 차감 기대값, 계좌 손실·낙폭, 꼬리 손실, 체결 가능성, 데이터 품질, 기간별 안정성**을 함께 비교한다. 위험 한도는 목적함수의 벌점만으로 처리하지 않고 별도 강제 제약을 둔다.

## 2. 전체 역할

```text
Research      : 가설·데이터셋·실험·후보 모델 생성과 검증
EV            : 현재 상태에서 행동별 순손익 분포·불확실성 평가
Position      : 행동·보유·미체결을 고려한 목표 노출 제안
Risk          : 계좌·종목·세션·자료·유동성·권한에 따른 허용 범위
Execution     : 허용된 주문의 전송·정정·취소·체결·대사
Learning Ops  : 매일 자료/결과 갱신, 후보 학습, 평가·승격·롤백
```

논리 모듈 구분이다. 여러 서버·별도 DB·범용 이벤트 플랫폼 도입 요구가 아니다. 실제 보유량과 현금은 **하나의 원장**에서 관리하고, 전략별 가상 분류는 그 원장과 대사한다.

## 3. 데이터 감사와 커버리지 명세

### 3.1 확보 여부를 추측하지 않는다

과거 1분봉 약 1년·5분봉 약 5년이라는 대화는 확보 완료 증거가 아니다. 공급자·요청 형태·실제 응답·가장 오래된 날짜·누락을 확인한다. 본 설계는 과거 틱 데이터 확보를 필수로 하지 않는다.

```text
dataset_id / dataset_version / provider_id
security_scope / universe_policy_id
venue_scope / session_scope / instrument_scope
requested_from / requested_to
verified_from / verified_to / verified_segments
bar_or_observation_kind / native_resolution
timezone / timestamp_precision / availability_basis
price_adjustment_policy / turnover_definition / units
missing_segments / duplicate_policy / correction_policy
source_refs / permission_status / known_limitations
```

가장 오래된 날짜와 가장 최근 날짜 사이가 모두 채워졌다고 단정하지 않는다. 완결 일봉과 미완결 당일봉, 수정주가와 실제 체결 주가, 거래정지·휴장과 수집 실패를 분리한다.

### 3.2 사용 가능한 해상도별 연구

일봉은 기억·연속성, 분봉은 봉 단위 돌파 정책, 1초 자료는 초 단위 관측 정책을 담당한다. 일봉·분봉을 보간해서 정교한 1초 타점 라벨을 만들지 않는다.

1초 스냅샷은 진짜 OHLC와 다르다. 그 초에 보지 못한 가격 경로를 정답으로 생성하지 않는다. 필요한 호가·방향·개별 체결량이 없으면 해당 특징을 쓰는 정책은 `UNSUPPORTED_BY_DATA`다.

### 3.3 단일 원본·파생 캐시

원본과 관측 이력은 불변 버전으로 보존한다. 특징·라벨·재생 결과는 입력 해시와 버전으로 관리한다. 원본을 별도 ‘AI 학습 DB’로 복제하지 않는다. 필요한 실험 스냅샷·파일 캐시는 원본 참조와 생성 경로가 있는 파생 산출물로 한정한다.

## 4. 연구 집합과 선택 편향

### 4.1 과거 Top40과 실시간 Top20

①의 당일 최종 거래대금 Top40은 **뉴스 기억 구축용 사후 선정 집합**이다. 이 집합에서 D일 이전 뉴스를 모을 수는 있지만, 그 결과만으로 D일 오전 전체 시장에서 종목을 선행 발견했다는 성과를 계산하지 않는다.

선행 평가에는 D-1까지 알 수 있던 후보, 당시 실제 Top20 기록, 또는 이용 가능 시각이 명확한 재생 스캐너를 사용한다. 과거 실제 조회 Top20이 없으면 거래대금 기준 대리 집합이라고 명시하고, 실시간 Top20과 별도 성과를 낸다.

### 4.2 실패와 미거래를 남긴다

성공 주도주만 모으지 않는다. 후보였지만 실패한 돌파, 거래대금 부족, 아무 반응 없음, 조건을 기다리다 종료, 모델이 진입하지 않은 사례를 기록한다.

거래대금 문턱을 연구하면서 문턱 아래 원본을 모두 삭제하지 않는다. 다만 연구 목적상 확보하지 않은 전 종목 고해상도까지 새로 수집할 필요는 없다. **보유한 집합 내 연구의 범위와 한계**를 명확히 한다.

### 4.3 독립 사례 수

동일 종목의 한 돌파를 1초마다 기록해 180행이 생겼다고 독립 성공 사례 180건으로 집계하지 않는다. `signal_event_id`, `episode_id`, `trade_date`, `theme_event_id`를 이용해 겹치는 사건·시장 영향을 그룹으로 평가한다.

보고서에는 최소 행 수, 고유 신호 수, 고유 종목 수, 거래일 수, 시장 국면 분포를 함께 적는다. 충분한 사례 수에 대한 단일 만능 숫자는 두지 않는다.

## 5. 시간 일관성과 미래정보 누출 방지

예측 시점에 사용할 수 없던 자료로 모델을 평가하면 성과가 과대평가될 수 있다. 전처리·특징 선택도 학습 구간에서만 맞춰야 한다. [R1]

모든 실험은 다음 시각을 구분한다.

```text
observation_time          # 시장·기사의 관측 대상 시각
received_at               # 실제 수신 시각
available_at              # 해당 버전을 판단에 사용할 수 있었던 시각
as_of                     # 의사결정의 정보 기준
computed_at               # 계산한 실제 시각
label_window_end          # 결과 관찰 종료 시각
label_available_at        # 결과가 확정되고 사용 가능해진 시각
```

검증 시 `input_max_available_at <= as_of`를 강제한다. 이미 미래를 담고 있는 종목 집합·테마 관계·시총·라벨·RAG 사후 결과도 검사한다.

당일 종료 후 산출한 ‘오늘은 강한 테마장’ 분류를 당일 09:05 특징으로 사용하지 않는다. 당시에 계산된 또는 당시 관측만으로 재현한 시장 상태를 사용한다. 현재 사전학습 LLM이 과거 사건의 이후 결과를 이미 알고 있을 수 있다는 ①의 한계도 유지한다.

현재 모델로 과거를 재설명한 결과와 당시 고정된 모델의 전진 예측을 구별한다. `first_seen_at`을 과거 기사 게시시각으로 위조하지 않는다.

## 6. 특징·라벨·정책 데이터셋

### 6.1 특징은 당시 관측만

②의 FeatureSnapshot을 재사용한다. 종목·시장·테마·뉴스·시간대·포지션·자료 품질을 포함할 수 있으나 처음부터 수백 변수를 만들지 않는다. 초기 기준선과 비교하며 필요성이 검증된 특징만 추가한다.

### 6.2 ‘성공’ 정의를 먼저 정한다

다음 확률은 서로 다르다.

- h분 뒤 가격이 현재보다 높은 확률.
- h분 내 정한 목표에 **보호 경계보다 먼저** 도달할 확률.
- 특정 진입·청산 정책을 적용한 episode의 비용 차감 순손익이 양수일 확률.
- ADD와 HOLD 중 ADD의 이후 계좌 성과가 더 나을 확률.

`p_success`만 저장하지 말고 `event_definition_id`, `horizon`, `exit_policy_id`, `cost_model_id`, `reference_price_basis`를 붙인다. 임의의 5분 상승 확률을 손절을 포함한 수익 확률로 바꾸지 않는다.

### 6.3 MFE·MAE 정의

비교 기준 가격 p0과 구간 [t,t+h]를 명시한다. 연구상 가격 경로 특징의 예시는 다음과 같다.

```text
MFE_return = max(0, max(P(u) / p0 - 1))
MAE_loss   = max(0, max(1 - P(u) / p0))
                u ∈ 관측 가능한 [t,t+h]
```

본 계약은 둘 다 0 이상으로 저장한다. 기존 MAE가 음수 수익률 방식이면 변환·표기를 명시한다. 고가/저가 봉을 쓰는지 관측 가격만 쓰는지 구분한다.

**MFE는 실현 가능한 평균 이익이 아니고, MAE는 실제 손절 평균 손실이 아니다.** 순서·체결·비중·비용이 있는 정책 재생 결과로 손익비와 기대값을 계산한다. 성공 사례의 MAE만 보고 손절선을 정하지 말고 실패·미회복·미관측 사례까지 포함한다.

### 6.4 경로·완결성

라벨에 첫 목표 도달 시각, 첫 보호 경계 도달 시각, 평가 종료, 경로 모호 여부를 남긴다. 같은 봉에서 목표와 보호선이 모두 닿으면 순서를 모른다. 해상도 부족은 `AMBIGUOUS_PATH`로 표시하고 보수 가정·제외·상하한 비교를 별도 보고한다.

관찰 끝이 아직 오지 않았거나 수집이 끊겼으면 `PENDING / CENSORED / MISSING`로 구분한다. 실패·수익률 0으로 자동 변환하지 않는다. 장 마감에 평가를 끝내는 정책과 다음 거래일까지 연장하는 정책도 구별한다.

### 6.5 사람 행동 기록은 선택 사항

사용자의 실제 판단·주문 기록은 모방학습 또는 복기 자료가 될 수 있다. 그러나 숙련 트레이더의 상세 로그가 없다고 시작을 막지 않는다. 초기에는 재현 가능한 규칙 기준선과 관측 가격에서 계산한 결과로 연구한다.

사람의 행동은 정답으로 확정하지 않는다. 매매 후 설명과 매수 당시 기록을 구분하고, LLM이 생성한 이유를 인간이 실제 당시 생각한 근거로 저장하지 않는다.

## 7. 연구 단계: 단순 기준선에서 시작

### 7.1 기준선

한 가지 돌파 정책을 먼저 고정한다. 진입 기준, 참고 가격, 관찰 창, 보호선, 청산 조건, 세션 종료, 비용·체결 가정을 빠짐없이 정의한다. 진입하지 않는 기준선도 비교한다.

### 7.2 제한된 실험

처음부터 모든 파라미터의 곱집합을 전수 탐색하지 않는다. 거래대금 후보 문턱, 시간대, 확인 지연, 손절·익절 한 가지처럼 질문을 나눠 탐색 예산을 제한한다.

예를 들어 40억·50억·80억의 비교를 한다면 선택한 범위·이유·실험 횟수를 기록하고, 주변 값에서도 결과가 유지되는지 확인한다. 한 점에서만 극단적으로 좋은 설정은 별도 의심 대상으로 본다.

### 7.3 조건부 통계·ML

규칙 기준선 → 조건별 통계 → 필요한 경우 작은 분류/회귀/분위수 모델 순으로 비교한다. 알고리즘 이름이나 파라미터 수가 성과를 보장하지 않는다. 같은 데이터·비용·검증 분할에서 비교한다.

### 7.4 행동 경로 연구

Entry/Add/Hold/Reduce/Exit/Re-entry와 목표 노출 경로를 정책 단위로 비교한다. ‘어제 제일 잘 된 30→60→90 경로’를 학습 정답으로 바로 삼지 않는다. 학습 구간에서 찾은 경로를 다음 검증 구간에서 평가한다.

### 7.5 강화학습·LLM 파인튜닝

초기 필수가 아니다. 강화학습은 체결·비용·시장 충격 모델의 허점을 이용한 가짜 성과가 생기지 않는지 검증한 뒤 고려한다. LLM 파인튜닝은 뉴스 추출·시나리오 형식 등 명확한 오류 목표와 평가셋이 있을 때 별도 실험으로 둔다.

LLM에 원시 시세를 많이 보여주는 것만으로 확률·주문·위험 모델 학습이 완료되었다고 표시하지 않는다.

## 8. 검증 설계

### 8.1 시간순 분리

학습 → 모델/정책 선택용 검증 → 최종 평가 구간을 시간순으로 나눈다. 이후 여러 전진 구간을 옮겨가며 반복한다. `TimeSeriesSplit` 같은 도구의 시간순·gap 기능은 참고할 수 있으나, 종목·날짜·사건 그룹과 중첩 라벨 처리는 직접 설계한다. [R2]

정규화, 특징 선택, 거래대금 문턱, 확률 보정, 정책 선택 모두 최종 평가 구간을 보지 않고 정한다. 동일 이벤트의 1초 행을 무작위로 나누지 않는다.

라벨 관찰 구간이 검증 시작을 넘어가는 학습 표본은 제거·분리한다. 경계 주변 간격은 라벨 기간과 종속성에 맞춰 설계하고 단일 고정 gap이 모든 경우를 해결한다고 가정하지 않는다.

### 8.2 과도한 탐색과 선택 편향 관리

실험 ID·시도한 조건·실패한 모델도 기록한다. 수많은 실험 중 최고 한 개만 고르고 탐색 횟수를 숨기지 않는다. 새 아이디어를 최종 평가 결과를 보고 반복 수정했다면 그 구간은 더 이상 최종 미사용 평가셋이 아니다.

날짜·시장 사건 단위 블록 재표집 등으로 불확실성을 볼 수 있다. 한 이벤트 내 행을 독립으로 취급한 지나치게 좁은 신뢰구간은 피한다. 사용 기법과 가정을 보고하고 유의성이 미래 수익을 보장한다고 표현하지 않는다.

### 8.3 필수 결과

```text
거래일·종목·고유 신호·episode·체결 수
총/순손익, 계좌 자산 경로, 비용과 회전율
승률과 정의, 평균 실현 이익/손실, 손익비, 기대값
MFE/MAE와 별도 정책 실현 성과
최대낙폭, 최악의 하루/episode, 연속 손실
노출·보유시간·동시 보유·테마 집중
부분체결·미체결·취소·지연·가격 불리함
시장·시간대·종목규모·자료품질별 성과
누락·미완결·모호 경로·표본 선정 한계
```

MDD는 계좌 순자산 경로에서 정의한다. 단일 종목 최고/최저 수익률로 대체하지 않는다. 익절·재진입을 잘게 쪼개 승률만 높아 보이게 만들지 말고 episode와 전체 계좌 성과를 함께 낸다.

## 9. EV: 현재 행동의 순가치를 비교

### 9.1 고정 정책의 기대값

정의된 정책에서 비용 전 평균 이익 W, 평균 손실 크기 L, 승리확률 p, 기대 비용 C라면 단순 모델은 다음과 같다.

```text
EV_net = p × W - (1-p) × L - C
```

이미 비용이 포함된 순손익 표본이라면 비용을 다시 빼지 않는다. 보합·미체결·여러 청산 결과가 있으면 이항 승패식 대신 실제 결과 분포를 사용한다.

### 9.2 행동별 비교

현재 상태 s와 행동 a에 대해 다음을 평가한다.

```text
V(s,a) = 지정한 미래 정책·기간에서의
         기대 순자산 변화 / 위험·실행 제약 정보

행동 집합: WAIT / ENTER / HOLD / ADD / REDUCE / EXIT / REENTER
```

ADD는 ‘앞으로 오를 확률이 높다’만으로 결정하지 않는다. 같은 출발 상태에서 **ADD 후 정책과 HOLD 후 정책**의 증가분 기대손익·비용·위험을 비교한다. 일부 매도 후 재증액도 동일하다.

보유 중 판단에서는 이미 지불한 매수 비용은 과거의 비용이다. 미래 행동 비교에 재청구하지 않되, 캠페인 전체 성과에는 원래 비용을 유지한다. 청산하면 앞으로 발생할 매도 비용과 남은 위험을 반영한다.

### 9.3 확률·불확실성 계약

```text
prediction_id / model_id / model_version
state_ref / as_of / action / policy_version
event_definition_id / horizon / evaluation_population
p_success / expected_net_pnl / expected_net_return
return_denominator / quantiles / tail_loss_estimate
calibration_report_id / training_cutoff
sample_support / independent_day_count
out_of_distribution_flags / uncertainty_flags
cost_model_id / execution_model_id
```

자료가 부족하면 확률·EV는 null이고 `INSUFFICIENT_EVIDENCE`다. 강한 점수를 임의로 85%로 바꾸지 않는다. 보정은 예측확률과 실제 빈도를 비교하는 과정이며, 보정에 쓰는 자료도 학습/최종 평가와 적절히 분리한다. [R3]

Brier score·log loss·확률 구간별 실제 빈도·표본수를 함께 볼 수 있다. 한 점수가 개선됐다고 확률 보정만 좋아졌다고 단정하지 않는다. 시장·시간대·정책별로 표본 부족 여부도 확인한다. [R3]

### 9.4 다른 행동의 결과를 얼마나 믿을 수 있는가

과거 시세에서 다른 매수·매도 경로를 시뮬레이션할 수 있지만, 내 주문이 가격을 바꿨을 결과까지 직접 관측한 것은 아니다. 특히 큰 노출·낮은 거래대금에서는 체결·시장 충격 가정에 의존한다.

행동가치에는 사용한 시뮬레이터와 거래 규모 지원 범위를 붙인다. 작은 주문으로 검증된 기대값을 수십 배 규모에도 동일하게 적용하지 않는다. 관측되지 않은 행동은 ‘실제 수익 확인’이 아니라 ‘가정하의 비교 결과’다.

## 10. 거래비용과 회계

### 10.1 기본 연구 프로파일

사용자가 정한 비용 가정을 그대로 명시한다.

```yaml
cost_model_id: user_conservative_023_v1
currency: KRW
buy_cost_rate: 0.00015       # 0.015%
sell_cost_rate: 0.00215      # 0.215%, 수수료·세금 합산 가정
same_notional_round_trip_rate: 0.00230
basis: user_selected_comparison_assumption
live_fee_schedule_verified: false
```

현재 확인한 키움 일반 주식 FAQ는 HTS·홈페이지 수수료 0.015%와 매도 시 세금 0.20%를 안내한다. 다만 거래 매체·주문 특성에 따라 수수료가 달라질 수 있다고도 명시한다. [R4] 이 연구 프로파일을 모든 계좌·상품·과거 시기의 공식 최대비용이라고 주장하지 않는다.

두 비교 방식을 분리할 수 있다.

- **동일 가정 비교:** 과거 전 구간에 사용자가 고른 비용을 적용해 전략 간 비교.
- **역사/실거래 재현:** 확인된 날짜·상품·시장·계좌별 비용표를 사용.

보고서에 어떤 방식을 썼는지 명시한다. 미수·신용 이자·기타 비용이 생기면 확인한 조건에 따라 별도 추가한다.

### 10.2 실제 체결금액별 계산

총매수 체결금액 B, 총매도 체결금액 S라면 위 프로파일의 기본 비용은 다음과 같다.

```text
explicit_cost = 0.00015 × B + 0.00215 × S
```

같은 가격에 1억 원어치 사고 1억 원어치 팔면 비용은 **230,000원**이다. 매도 가격·금액이 달라지면 정확한 비용은 최종 보유금액에 0.23% 한 번을 곱한 값과 다르다.

가격 수익률 g로 한 번 사고 전량 팔았을 때, 최초 매수 **명목금액** 대비 순손익률은 다음과 같다.

```text
r_net_on_buy_notional = (1+g) × (1-0.00215) - (1+0.00015)
```

따라서 가격 기준 손익분기 수익률은 약 **0.23050%**다. 실제 투자 현금 전체를 분모로 쓰면 수익률 분모에 매수 비용까지 포함한다. 화면·실험은 분모 정의를 표시한다. 이 계산은 슬리피지·추가 비용·원단위 처리 전의 수학 예시다.

### 10.3 분할과 회전을 구별

동일 가격·동일 총금액·순수 비례 비용을 가정하면 1억을 한 번에 사는 것과 2천만 원씩 다섯 번 사는 것의 **매수 수수료 합계는 같다**. 주문 횟수만큼 왕복 0.23%를 중복 차감하지 않는다.

반면 5천만 원을 팔고 다시 5천만 원을 매수하면 총 회전금액이 늘어 해당 체결들의 비용이 추가된다. 주문별 절사·최소수수료가 실제로 있다면 그 규칙을 따로 구현한다. 분할의 장단점은 가격·체결·시장 충격·회전과 함께 검증한다.

### 10.4 슬리피지 이중 계산 방지

실제/모의 체결가격에 스프레드·불리한 가격 이동·시장 충격을 반영했다면 동일 항목을 손익에서 또 빼지 않는다. 반대로 참조가격만 사용했다면 별도 명시한 실행 비용 모델을 적용한다.

```text
execution_price_policy: modeled_fill | observed_fill | reference_plus_cost
included_components[]
additional_cost_components[]
```

체결이 불확실한데 중간가격에서 전량 즉시 체결되는 기본값을 쓰지 않는다. 키움 안내도 시장가가 원하는 직전 가격과 다르게 체결될 수 있음을 설명한다. [R4]

### 10.5 원장

주문·체결 단위로 수량, 가격, 매수 비용, 매도 비용, 통화, 원단위 처리, 실제/추정 여부를 남긴다. 수익 실현 계산의 원가법은 기존 계좌 표시와 일치시키거나 차이를 설명한다.

포지션 PnL과 계좌 순자산 변화가 맞아야 한다. 현금·평가액·부채·누적 비용·실현손익을 이중 반영하지 않는다. 미결제 매도대금·주문가능금액·현재 순자산을 같은 값으로 취급하지 않는다. 브로커가 제공하는 상태를 각각 저장하고 매핑한다.

## 11. Position: 목표 노출과 분할 경로

### 11.1 단위

```text
E_t = 정의한 방식의 현재 계좌 순자산
V_i = 종목 i의 현재 평가금액
exposure_i = V_i / E_t
portfolio_gross_exposure = Σ abs(V_i) / E_t
```

초기 롱 전용 정책에서 음수 수량은 오류다. 분모 E_t가 0 이하·미확인·오래된 값이면 신규 위험을 확대하지 않는다. 100%=1.0배, 500%=5.0배 **명목 노출**이며 수익률·손실률이 아니다.

위험예산의 분모는 현재 순자산·세션 시작 순자산 등 별도 정책일 수 있다. 노출 분모와 섞지 말고 `equity_basis`와 시점을 기록한다.

### 11.2 목표와 실제의 차이

목표 평가액을 수량으로 바꿀 때 호가 단위·수량 단위·비용·주문가능금액을 반영한다. 계획 기준은 다음 관계다.

```text
effective_projected_qty
  = filled_position_qty
    + pending_buy_remaining_qty
    - pending_sell_remaining_qty

desired_delta_qty = target_qty - effective_projected_qty
```

이 식은 중복 의도를 줄이는 **계획용 근사**다. 매수·매도 미체결이 모두 체결된다고 위험을 낙관하면 안 된다. 실제 Risk는 ‘매수만 모두 체결’, ‘매도 미체결’ 등 불리한 상태도 검사한다. 취소 확인 전 주문은 계속 살아 있을 수 있다.

### 11.3 작은 차이에 계속 주문하지 않는다

목표 변화 최소 단위, 주문 갱신 주기, 같은 방향 중복 억제, 반대 의도 전환 절차를 둔다. 파라미터는 비용·체결 지연·전략 기간을 고려해 검증한다. 단, 보호 청산을 일반 재조정 대기시간 때문에 지연하지 않는다.

### 11.4 장기 연구 선택지

고정 비중, 단계형 증감, 조건부 목표 노출, 위험예산 기반 증감 등을 같은 검증 구간에서 비교한다. 완벽한 미래 확률을 안다고 가정한 최적 레버리지를 운영 기본값으로 쓰지 않는다.

주도주 정책과 비주도주 정책에 비중을 미리 서열화하지 않는다. 각 정책의 불확실성·순기대값·공통 위험·실행 가능성이 배분의 근거다.

## 12. Risk: 모델보다 우선하는 보호

### 12.1 위험의 네 기준

1. **최초 캠페인 자본 대비 손익:** 최초 진입부터 얼마나 벌거나 잃었는가.
2. **현재 순자산에서의 추가 손실:** 지금 보유를 유지하면 얼마를 더 잃을 수 있는가.
3. **최고 순자산 대비 반납:** 이미 만들어진 이익이 얼마나 줄어드는가.
4. **스트레스 손실:** 계획한 가격·시간에 청산이 안 되는 경우의 손실.

불타기가 이전 원금 기준으로 이익을 남기더라도 현재 순자산을 크게 잃을 수 있다. 평가이익·실현이익 모두 자산이며 공짜 위험예산으로 취급하지 않는다.

### 12.2 손절선과 위험예산의 수학

간단한 가격 모델에서는 `허용 손실 / 진입가와 청산 가정의 차이`로 수량 후보를 구할 수 있다. 그러나 가까운 보호선 하나만으로 수량이 무한히 커지지 않도록 노출·체결·스트레스·계좌 한도를 함께 적용한다.

현재가 P, 보유수량 q, 청산 가정가 S라면 현재 시점의 가격상 되돌림은 대략 `q × (P-S)`다. 여기에 추가 비용과 다른 포지션 위험을 반영한다. **이는 보호 가격에 체결된다는 조건부 예상값이며 실제 최대 손실 보장이 아니다.**

### 12.3 불타기 예시: 원금 보호와 현재 위험은 다르다

아래는 비용·세금을 제외한 계산 예시다.

```text
기존 10,000주 × 10,000원 = 100,000,000원
추가  5,000주 × 10,300원 =  51,500,000원
총원가                     151,500,000원
총수량                         15,000주
평균단가                       10,100원

현재가                         10,300원
계획 청산가                    10,150원
```

10,150원에서 전량 청산된다고 가정하면 원가 대비 이익은 **750,000원**이다. 하지만 현재가 10,300원에서 청산가까지 반납하는 평가액은 **2,250,000원**이다. ‘손절해도 원금은 남는다’와 ‘현재 위험이 작다’는 다른 판단이다. 실제 비용·청산 불리함을 추가하면 두 값은 더 달라진다.

### 12.4 강제 제약

```text
계좌별 live 허가·전략 허가
실제 주문가능금액·미수/신용 권한
단일 주문·종목·테마·계좌 총노출
거래·일일·누적 손실·최고 순자산 반납 한도
데이터 신선도·계좌 대사·주문 상태 확인
시장/상품/세션·거래정지·변동성 완화 상태
청산 가능성·스트레스 손실·보유기간
```

값은 승인된 위험 프로파일로 관리한다. 모델이 순기대값을 높게 평가하더라도 제한을 해제하지 않는다. 보호 제한은 검증된 코드와 계좌 상태로 실행한다.

### 12.5 미수·신용·주문가능금액

‘5배까지 연구 가능’과 실제 계좌에서 가능한 배수는 다르다. 종목·시장·계좌·증거금·주문가능금액·결제 조건을 브로커에서 확인한다. 평가이익이 생겼다는 이유로 같은 금액만큼 즉시 신용한도가 늘었다고 계산하지 않는다.

초기 신규 자동매매는 현금·소액 승인 범위다. 미수/신용 연구가 켜져도 실거래 권한은 별도 OFF다. 실거래 확대는 사용자의 별도 승인과 해당 규모의 체결·위험 검증이 필요하다.

### 12.6 Soft와 Hard

Soft 관찰은 ②의 사전 정의 정책을 검증해 적용한다. Hard 조건은 Soft timer·LLM 대기·새 확률·쿨다운보다 우선한다. Hard 발동 후 신규 ADD를 중지하고 미체결 증액을 안전하게 처리하며 청산을 시도한다.

하드 스톱이 있다고 가격 점프·거래 중단·상대 주문 부재의 손실이 사라지는 것은 아니다. 청산 의도·전송·접수·부분체결·완료를 각각 기록한다. 체결을 보장하지 않는다. [R4]

## 13. Capacity·Liquidity: 들어갈 때와 나올 때

### 13.1 거래대금은 출발점이지 보장서가 아니다

과거 1분에 100억이 거래되었다고 현재 큰 매도 주문을 같은 가격에 받아줄 매수호가가 남아 있다는 뜻은 아니다. 대금·호가·스프레드·주문 크기·시간·시장 상태를 함께 고려한다.

```text
historical_turnover_ratio
  = 내 계획 주문금액 / 최근 관측 구간 거래대금
```

이 값은 과거 거래와의 규모 비교값이다. 실제 주문 집행 구간의 시장 거래량 대비 체결 비중인 **실현 참여율**이나 체결 확률과 동일하지 않다. 주문금액과 비교하는 시간창을 맞추고 두 값을 이름부터 구분한다.

### 13.2 증액분뿐 아니라 전체 출구

2억을 추가하기 쉽더라도 이미 20억을 보유했다면 비상청산은 전체 보유량의 문제다. 새 주문과 현재+잠재 체결 보유량 모두에 대해 출구 위험을 평가한다.

미래 거래대금·호가 유지가 불확실하면 최근 평균을 그대로 확정치로 사용하지 않는다. 보수 추정·스트레스 시나리오·최대 집행시간·부분체결 가정을 사용하고 근거를 남긴다. 급변 시 대금 증가가 곧 유리한 청산을 뜻하지 않는다.

### 13.3 제한 결과

상한을 단순히 여러 숫자의 최솟값으로 끝내지 말고 최종 포트폴리오 상태를 재검사한다. 단일 종목 허용량이 작아져도 기존 보유·다른 테마와의 합산·미체결의 불리한 체결 조합이 계좌 한도를 넘을 수 있다.

```text
ALLOW / CAP / NO_NEW_RISK / REDUCE_ONLY / EXIT_REQUIRED / HALT_NEW_ORDERS
```

거래대금 감소만으로 보유를 버리는 전략 룰은 사용하지 않지만, 출구 위험이 승인된 한도를 넘으면 위험 모듈은 축소를 요구할 수 있다. 이때 사유는 대금 문턱 하나가 아니라 **보유 규모 대비 청산 위험**이다.

## 14. Replay와 체결 시뮬레이터

### 14.1 재생 순서

```text
원천 관측/수신 가능 이벤트
  → 특징·① 시점별 맥락
  → ② 행동 후보
  → EV/Position
  → Risk
  → 주문 의도
  → 지연·호가/시세·유동성 조건하의 체결
  → 비용·원장·다음 관측
```

순서를 바꾸어 한 봉의 미래 가격으로 신호를 만들고 같은 봉의 더 좋은 가격에 채우지 않는다. 체결가격·수량은 주문이 시장에 도착할 수 있는 시점 이후의 자료로 처리한다.

### 14.2 해상도별 체결 가정

분봉만 있으면 다음 적격 봉 가격·보수 비용 등 명시한 모델로 비교할 수 있다. 1초 자료가 있으면 다음 관측 이후 가능한 체결 가정을 사용한다. **‘고가/저가에 닿음=지정가 전량 체결’은 기본값이 아니다.**

호가가 없으면 큐 순서·잔량을 알 수 없다는 한계를 표시한다. 부분체결·미체결 시나리오를 비교하고, 보수 가정에서 기대값이 사라지는 정책은 실전 검증 우선순위를 낮추거나 보류한다.

### 14.3 시장제도·상태

세션별 주문 유형, 호가단위, 가격 제한, 변동성 완화·거래정지, 종목별 주문 가능 여부는 검증된 브로커/거래소 상태와 버전 규칙을 이용한다. 모든 과거 날짜에 현재 규칙을 그대로 적용하지 않는다. 미지원 구간은 거래 불가 또는 명시적 근사 상태다.

### 14.4 규모 민감도

작은 고정 금액과 큰 금액을 같은 즉시 전량 체결로 비교하지 않는다. 전략의 지원 주문 규모, 거래대금·호가 수준, 비용 민감도를 결과에 함께 남긴다. 시장 충격을 알 수 없는 규모는 `CAPACITY_UNVERIFIED`다.

## 15. Execution: 주문 의도에서 실제 체결까지

### 15.1 단일 주문 책임자

계좌·종목의 주문은 하나의 조정자가 소유한다. ②·LLM·개별 전략 worker가 증권사 주문 API를 직접 호출하지 않는다. 실거래 자격증명은 승인된 실행 경로에서만 읽는다.

새 문서를 이유로 기존 주문 기능을 다시 작성하지 않는다. 기존 기능의 멱등성·대사·권한이 충분하면 이를 어댑터로 재사용한다. 부족한 부분만 단계적으로 보완한다.

### 15.2 주문 의도 계약

```text
intent_id / decision_id / idempotency_key
run_id / execution_mode / account_ref
security_id / venue / session
policy_id / policy_version / model_id
as_of / expires_at
side / target_qty_or_delta_qty
order_type / limit_price / urgency
risk_approval_id / risk_snapshot_ref
position_version / order_ledger_version
reason_codes / evidence_refs
```

실제 계좌번호·키를 분석 문서·프롬프트·로그에 노출하지 않는다. `account_ref`는 내부 참조다. 식별 키는 동일 판단의 재시도와 새로운 판단을 구분한다.

### 15.3 전송 직전 재검사

신호 생성과 주문 전송 사이에 가격·잔고·미체결·계좌 권한이 바뀔 수 있다. 전송 직전에 만료·거래상태·자료 신선도·수량·금액·Risk 승인 유효성·현재 포지션 버전을 재검사한다.

낡은 snapshot으로 얻은 승인이라면 재평가한다. 전략 확신도만 다시 확인하고 계좌 상태를 생략하지 않는다.

### 15.4 상태 머신

```text
CREATED → RISK_APPROVED → SUBMITTING → ACKNOWLEDGED
                                  ├→ REJECTED
                                  └→ UNKNOWN
ACKNOWLEDGED → PARTIALLY_FILLED → FILLED
            → CANCEL_REQUESTED → CANCELLED / 추가 체결 확인
            → EXPIRED 또는 지원되는 종료 상태
```

전송 timeout은 주문 실패 확정이 아니다. 브로커 접수 여부를 조회·대사하고, 확인 없이 같은 주문을 다시 보내지 않는다. API가 자체 멱등성을 지원하지 않으면 로컬 의도/브로커 주문번호 매핑과 조회 기반 복구를 구현한다.

취소 요청 중에도 체결이 올 수 있다. `CANCEL_REQUESTED`를 즉시 미체결 0으로 바꾸지 않는다. 지연·중복·순서가 바뀐 체결 이벤트를 실제 체결 ID와 원장 규칙으로 처리한다.

### 15.5 재시작과 계좌 대사

시작 시 로컬 원장, 브로커 보유, 미체결 주문, 최근 체결, 주문가능금액을 대조한다. 차이가 있으면 신규 위험 확대를 막고 이유를 표시한다. 프로세스가 재시작됐다고 이전 주문을 모두 없던 것으로 간주하지 않는다.

수동 주문이 들어오면 기존 계좌 변화를 받아들여 원장에 반영하고 전략 목표를 재평가한다. 자동 정책이 수동 청산 직후 즉시 원래 목표로 재매수하지 않도록 사용자 일시정지·소유권 정책을 둔다.

### 15.6 비상정지의 의미

`신규 진입 중지`, `미체결 신규매수 취소`, `감액만 허용`, `전량 청산 시도`는 다른 동작이다. 하나의 불명확한 Kill Switch로 감추지 않는다.

기본 비상정지는 신규 위험 확대를 막되 기존 보호·대사는 유지한다. 모든 연결이 끊겼을 때 실제 청산을 보장하지 않는다. 사용자에게 **주문이 확인되지 않음/잔고 확인 필요**를 명확히 알리고 복구 절차를 제공한다.

### 15.7 브로커 능력 확인

현재 키움 연동 방식이 REST·OpenAPI+ 중 무엇인지, 주문·취소·정정·체결 통보·조회·모의환경·KRX/NXT·주문유형·호출 제한을 실제 공식 문서와 계좌 설정에서 확인한다. 이 문서의 추상 기능을 모두 지원한다고 추측하지 않는다.

기존 호출 제한 관리자를 재사용한다. 시세 수집·계좌 보호·주문 대사가 백필·대규모 연구 때문에 지연되지 않게 우선순위를 둔다.

## 16. 여러 전략이 같은 종목을 다룰 때

초기에는 하나의 주도주 돌파 정책만 사용한다. 나중에 추세 정책과 스캘핑 정책을 동시에 쓰더라도 계좌·종목 단위의 최종 목표를 하나로 합성한다.

상반된 매수·매도 의도를 그대로 각각 시장에 내지 않는다. 전략별 가상 기여와 실제 순주문·비용을 기록한다. 내부 상쇄가 있었다면 실제 체결이 발생한 것처럼 거래량·수수료·수익을 생성하지 않는다.

동일 테마 여러 종목의 기회는 독립하지 않을 수 있으므로 공통 위험을 합산한다. 전략별 모의 자금이 각각 계좌 전액을 사용할 수 있는 것처럼 합산 성과를 보고하지 않는다.

| 단계 | 확인하는 것 | 확인했다고 말할 수 없는 것 |
|---|---|---|
| 과거 재생 | 정의된 가정하의 정책 성과·회계·누출 | 당시 실제 주문 체결 |
| LIVE_SHADOW | 실제 수신시각의 신호·계산·품질·지연 | 실행 가능한 최종 순수익 |
| 내부 Paper | 실시간 자료+체결모델로 가상 원장 | 실제 시장 충격 |
| 증권사 모의 | 지원 범위에서 API 주문·접수·체결 연동 | 실계좌와 동일한 체결·세금·신용 |

| 점진 확대 | 승인된 다음 규모의 성과·위험 | 미래 수익 보장 |

증권사 모의가 선택한 API·상품을 지원하는지 먼저 확인한다. 미지원이면 내부 Paper를 만들 수 있으나 증권사 모의 검증을 통과했다고 보고하지 않는다.

승격 조건은 실험 전에 정한다. 최소 관찰·분산된 날짜/상황·순기대값 불확실성·낙폭·체결 성능·회귀 테스트·장애 대응 등을 포함한다. 단일 주간 수익이 높다는 이유로 자동 승격하지 않는다.

실거래는 별도 사용자 승인·정확한 계좌·현금 한도·정책 버전이 필요하다. 이 문서를 받은 Codex가 실제 주문을 실행할 권한을 얻는 것은 아니다.

## 18. 매일 갱신과 모델 재학습

### 18.1 ‘매일 학습’의 분해

```text
오늘 수집·정정 확정
  → 당일 특징과 관측 상태 확정
  → 관찰기간이 끝난 결과만 생성
  → 패턴·계좌·실행 통계 갱신
  → drift·자료 품질·성능 점검
  → 필요하고 지원되는 경우 후보 모델 훈련
  → 기존 운영 모델과 별도 검증
  → 승인된 경우에만 배포
```

RAG 인덱스 업데이트, DB append, 고정 모델로 오늘 확률 계산은 가중치 학습과 다르다. 미래 h일 결과가 필요한 사례는 오늘 장 마감만으로 정답이 되지 않는다.

### 18.2 증분 학습과 배치 학습

증분 학습 지원은 알고리즘마다 다르다. scikit-learn의 `partial_fit` 지원 모델처럼 명시적 능력을 확인해야 한다. [R5]

```text
trainer_capabilities:
  supports_incremental_update
  requires_replay_sample
  supports_feature_schema_change
  supports_new_target_classes
  batch_training_supported
```

새 하루 데이터만 더해도 되는 모델, 일정 창을 다시 학습해야 하는 모델, 구조가 바뀌면 초기화해야 하는 모델을 구별한다. warm-start나 트리 추가를 과거 전체 재학습과 항상 동일하다고 취급하지 않는다.

### 18.3 주기보다 조건

3개월·6개월은 의무 주기가 아니다. 특징·라벨·정책 변경, 보정 악화, 데이터 분포 변화, 새로운 자료, 누적 계산 오차·모델 한계가 재검토 계기다. 반대로 후보가 계속 기존 모델보다 나쁘면 기존 모델을 유지할 수 있다.

최근 자료에 높은 가중치를 주는 방법도 연구 대상이다. ‘최근이 항상 더 중요’나 ‘5년 자료면 모든 미래 국면 포함’을 고정하지 않는다. 과거 드문 국면의 기억과 현재 적합성을 별도 평가한다.

### 18.4 온라인 후보의 평가 순서

후보 온라인 모델도 새 표본의 결과를 배우기 전에 그 표본에 대한 예측을 기록한다. 결과를 본 뒤 바뀐 모델로 같은 시점 예측을 다시 써서 성과를 계산하지 않는다.

동일 데이터셋 해시·훈련 cutoff·가중치·시드·패키지 버전을 기록하고 모델 파일 checksum을 저장한다. 모델 교체 시 과거 결정에 연결된 모델 ID를 덮어쓰지 않는다.

운영 모델과 후보 모델은 동시에 같은 입력을 관찰할 수 있지만, 후보의 제안이 실제 원장을 바꾸면 안 된다.

## 21. 자원·배치·재개

초기 백필·특징 재계산·정책 탐색은 무거울 수 있지만, 장중에는 소수 후보의 현재 상태만 처리한다. 새로운 특징·모델을 도입하면 과거 재계산이 다시 필요할 수 있으므로 ‘초기에 한 번이면 영원히 종료’라고 설계하지 않는다.

파일·DB를 날짜·자료 버전·종목 범위로 나누고 필요한 부분을 읽는다. 모든 1초 기록을 매번 RAM에 올리지 않는다. 지원 알고리즘의 out-of-core 처리를 활용할 수 있으나 모든 모델이 외부 메모리 학습을 지원하는 것은 아니다. [R5]

실험은 입력 구간·결과 저장 단위별 체크포인트로 중단·재개한다. 같은 결과를 중복 집계하지 않도록 실행 ID와 데이터 버전을 키로 쓴다. 배치가 중단되어도 실시간 원장·시세 수집에 영향을 주지 않는다.

현재 장비에서 표본 실험의 CPU·메모리·스왑·I/O·지연을 측정하고 병목을 먼저 확인한다. 새 PC·특정 GPU·유료 API를 이 명세의 선행 조건으로 두지 않는다. ①의 로컬 LLM·Mac 사용자 제어를 유지한다.

## 22. 보안과 변경 통제

뉴스·LLM 응답·모델 산출물은 외부 입력이다. 셸·SQL·임의 주문 명령으로 실행하지 않는다. 모델은 허용된 스키마·정책 ID만 반환하며 최종 Risk가 검증한다.

원본·과거 판단·체결·계좌 대사 이력은 모델이 수정할 수 없다. 키·토큰·HMAC·계좌 비밀을 프롬프트·문서·테스트에 넣지 않는다. 라이브 자격증명과 모의 설정을 분리하고 잘못된 환경 연결을 감지한다.

실거래·미수·위험 한도·네트워크 개방·유료 결제·원본 대량 삭제는 별도 명시적 승인 없이는 실행하지 않는다. 학습 파라미터 검색 공간에 이 권한 키들을 넣지 않는다.

## 23. 최소 코드 구조

기존 연구/백테스트/주문 모듈을 우선한다. 아래는 책임 배치 예시다.

```text
research/
  datasets.py        # 범위·시점·분할
  labels.py          # 결과·완결성
  experiments.py     # 가설·실험 기록
  evaluation.py      # 순손익·위험·품질
  training.py        # 이후 후보 학습
replay/
  runner.py          # 시간순 재생
  fills.py           # 체결 가정
  ledger.py          # 기존 회계 재사용
trading_runtime/
  action_value.py    # 이후 EV 추론
  allocation.py      # 목표 노출
  risk.py            # 최종 보호
  execution.py       # 기존 주문 어댑터
  reconciliation.py # 기존 대사 재사용
```

첫 버전에서는 필요한 파일만 만든다. 전달만 하는 엔진·추상 factory·서비스 수십 개를 추가하지 않는다. 복잡성을 줄여도 시점·원장·권한의 경계는 생략하지 않는다.

## 24. 단계별 완료 기준

### R0 — 감사와 공통 계약

자료 범위, 원본 의미, 기존 연구·계좌·주문·수수료 코드를 확인한다.

**완료:** 작은 실제 구간 또는 명시한 fixture로 금액·시간·자료 품질의 검증 가능성이 확인되고 필요한 계약이 매핑된다.

### R1 — 재현 가능한 돌파 재생

한 기준선, 비용, 단순하지만 명시적인 체결 모델, 원장·결과 기록을 만든다.

**완료:** 같은 입력·버전·시드로 결과가 재현되고 수량·현금·비용 대사가 맞는다. 같은 봉 내 순서 모호·누락·상태 정지를 처리한다.

### R2 — 제한된 탐색·검증

거래대금·시간·확인 지연 등의 소수 가설을 시간순 비교한다.

**완료:** 시도 수·검증 구간·실패 결과·표본 범위·비용 민감도·불확실성을 보고한다. 승률·MFE만으로 성공 선언하지 않는다.

### R3 — 행동 EV·분할 정책

ADD/REDUCE/REENTER와 목표 노출 정책을 추가하고 ②에 결과를 제공한다.

**완료:** 서로 다른 행동의 비교 가정, 계좌 위험, 비용·회전·출구 제한이 일관되게 계산된다.

### R4 — 후보 학습·Shadow·Paper

학습 능력 확인, 후보 모델 기록, 전진 예측, 내부 Paper 또는 지원 확인된 브로커 모의를 연결한다.

**완료:** 과거와 실시간 차이, 데이터 지연, 모의 체결 한계, 실제 적용 안 된 후보 모델이 구분된다. 자동 live 승격 없음.

### R5 — 별도 승인된 소액 현금 실거래

사용자의 정확한 계좌·한도·정책 승인 후 실행·대사·정지·재시작을 검증한다.

**완료:** 실제 체결·비용·계좌 차이·장애 처리 결과를 보고한다. 더 큰 규모 성과로 일반화하지 않는다.

### R6 — 선택 확장

스캘핑·비주도주·새 모델·규모 확대·미수 연구를 개별 실행한다.

**완료:** 해당 자료·정책·규모의 별도 근거와 승인. 기존 위험 제한·원장·검증 분리 유지.

```text
1. 무엇을 연구/구현했는가: 질문·정책·현재 Phase

3. 자료의 실제 범위·해상도·시점·누락은 무엇인가
4. 비용·체결·시장 충격·자금 규모 가정은 무엇인가
5. 어떤 시간순 검증과 비교 기준선을 사용했는가
6. 순손익·위험·표본·불확실성 결과는 무엇인가

```

결과 없음·증거 부족·기대값 없음·매매하지 않음도 정상 결과다. 수익이 나오는 전략을 반드시 발견해야 완료되는 작업으로 정의하지 않는다. 연구 도구의 정확성과 전략 수익성의 검증은 다른 완료 조건이다.
