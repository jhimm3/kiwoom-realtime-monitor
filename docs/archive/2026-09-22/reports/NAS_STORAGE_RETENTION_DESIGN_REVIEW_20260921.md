# NAS 저장 용량·자동 보존 설계 재검토

> **2026-09-21 보류 결정:** 사용자가 자동 삭제 구현을 나중으로 미루기로 했다. 현재 범위는 PC/NAS 저장량의 읽기 전용 표시까지다. 아래 보호 참조·삭제 우선순위·기간/용량 충돌 정책은 실제 삭제 코드를 작성하기 전에 Astra Ultra로 다시 검토한다.

### ASTRA ULTRA 설계 재검토 필요

**현재 문제**

- 사용자는 뉴스, 주식 누적자료, 연구·시뮬레이션, 계좌·주문, 설정·기타별 저장량을 확인하고 기간을 정해 오래된 자료부터 자동 정리하기를 원한다.
- 현재 `docs/archive/2026-09-22/root/FUTURE_DEVELOPMENT_ROADMAP.md`와 `docs/archive/2026-09-22/root/DB_SCHEMA.md`는 중앙 분봉·일봉·순위·TOP20 이력을 자동 삭제하지 않는다고 규정한다.
- 같은 시장·뉴스 자료가 매매일지 복기, 연구 export, 최종평가, 후보·모의운용의 근거로 참조될 수 있다. 단순 날짜 삭제는 완료된 연구나 매매일지의 재현성을 깨뜨릴 수 있다.

**관련 영역**

- `central_server/database.py`: 중앙 시장·뉴스·계좌·연구 자료 저장과 조회
- `central_server/central_schema.py`: 중앙 PostgreSQL/SQLite 스키마와 참조 원장
- `central_server/app.py`: 진단·운영 설정 API
- `presentation/api_settings_dialog.py`: NAS 사용량·보존 설정 화면
- `infrastructure/persistence/research_repository.py`: 연구 실행·최종평가·근거 참조
- 중앙 자료 흐름: 실시간/REST 수집 → 중앙 원본·revision → 연구 export/후보 → 모의운용/매매일지 복기

**기존 설계를 그대로 유지할 경우**

- 장점: 과거 시점 재현과 매매일지·연구 근거가 훼손되지 않는다.
- 문제점: NAS 용량이 계속 증가하며 사용자가 종류별 증가 원인을 알기 어렵다.
- 예상되는 기술 부채: 디스크가 임계치에 도달한 뒤 수동으로 파일이나 테이블을 지우는 위험이 커진다.

**가능한 대안**

- 대안 A: 기간 기준만 적용한다. 구현은 단순하지만 참조 중인 근거를 지울 위험이 있어 권고하지 않는다.
- 대안 B: 자료 종류별 기간과 보호 참조를 함께 적용한다. 삭제 전 dry-run을 만들고, 일지·실제 주문/체결·사용자 설정·완료 연구·동결 export가 참조하는 원본을 영구 보호한다.
- 대안 C: 용량 상한만 적용하고 재생성 가능한 캐시·파생 자료부터 정리한다. 예측 가능성은 낮지만 디스크 고갈 방지에 유리하다.
- 대안 D: B와 C를 결합한다. 종류별 최소 보존기간을 지킨 뒤 전체 상한을 넘을 때만 오래된 삭제 가능 자료부터 배치 정리한다.

**현재 추천안**

- 대안 D를 추천한다.
- 기본값은 `0 = 무제한`, 자동 삭제 OFF로 유지한다.
- 1차 삭제 가능 대상은 만료 API 캐시, 최신값으로 대체되는 진단·파생 자료, 실패/취소된 임시 작업 산출물로 제한한다.
- 초봉·분봉·순위·뉴스 원문은 사용자가 기간을 명시한 경우에만 대상 후보가 되며, 매매일지·주문/체결·연구 export·최종평가·후보·모의운용이 참조하면 기간과 무관하게 보호한다.
- 실제 삭제 전에 종류별 대상 건수·예상 회수량·보호 건수를 보여주는 dry-run과 삭제 원장을 반드시 남긴다. 정리는 작은 batch로 실행하고 순위 수집 경계에서는 양보한다.
- 이번 단계에서는 읽기 전용 분류별 용량 진단만 구현하고 삭제는 수행하지 않는다.

**Astra가 판단해야 할 핵심 질문**

- 초봉, 분봉, 일봉, 순위, 뉴스 원문·AI 결과 각각의 기본 최소 보존기간은 얼마인가.
- 완료되지 않은 일반 연구 run도 보호할지, 완료·동결·최종평가에 사용된 자료만 보호할지.
- 매매일지의 종목·거래일 연결만으로 그날 전체 시장 원본을 보호할지, 실제 복기에 사용한 좁은 시간 구간만 보호할지.
- 기간 정책과 전체 GB 상한이 충돌할 때 어느 정책을 우선할지.
- 삭제 뒤 연구 재현이 불가능한 자료를 별도 압축 보관할지, 완전 삭제할지.

**재개 조건**

- 사용자가 자동 삭제 또는 저장 용량 상한 구현을 다시 요청한다.
- NAS 디스크 임계치 때문에 읽기 전용 진단만으로 운영하기 어려워진다.
- 재개 시 이 문서와 `docs/archive/2026-09-22/root/REFACTORING_CLOSEOUT_PLAN.md`의 보류 원장을 먼저 읽고, 보호 참조와 dry-run 계약을 확정한 뒤 구현한다.
