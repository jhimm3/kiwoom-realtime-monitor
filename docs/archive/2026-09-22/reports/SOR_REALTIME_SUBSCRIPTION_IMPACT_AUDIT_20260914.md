# SOR 실시간 구독 전환 영향 감사

기준일: 2026-09-14(KST)

후속 재검토 결정: [SOR 데이터 계약·Sol 구현 계획](SOR_DATA_CONTRACT_REVIEW_20260914.md). 기존 SOR/COMBINED 구분을 활용하며 핵심 모델 교체는 필요 없다. 아래 초기 권고와 다르면 후속 결정의 전환·품질·조회 계약을 따른다.

## 결론

중앙 실시간을 모든 종목에서 SOR 통합시세(`_AL`) 하나로 바꾸는 것은 권장하지 않는다. 화면의 현재가·등락률·상한가 감지와 전체 체결대금 수집에는 SOR가 적합하지만, 거래소별 선행성·지연·VI·체결 차이를 연구할 원본이 사라진다. 현재의 **일반 종목 SOR + 우선 연구 종목 KRX/NXT 상세** 혼합 구독을 유지하는 편이 맞다.

다만 현재 `_AL` 0B/0w를 수신하는 공통 parser가 이를 `SOR`가 아니라 `KRX`로 표시하는 결함이 확인됐다. 화면 가격에는 영향이 작지만 SOR 분봉·초봉과 프로그램 스냅샷이 KRX 원본처럼 저장되고, strict KRX 연구 입력에 섞일 수 있다. parser 한 줄만 바꾸면 기존 KRX 전용 조회가 SOR 행을 읽지 못하므로 소비 경로를 함께 전환해야 한다.

## 현재 실제 구독 방식

- NAS는 실전 키움 토큰 제약 때문에 WebSocket 한 개만 유지한다.
- 모든 활성 종목은 최소 한 개의 0B를 받는다.
- NXT 가능 일반 종목은 `_AL` 통합시세 한 개로 받는다.
- TOP20·실매수 편입 등 우선 종목은 0B 독립 200 item 한도에서 기본 종목 수를 뺀 여유만큼 `종목코드` KRX와 `종목코드_NX` NXT를 함께 받는다. 직전 구현에서 통합 190 item 계산을 수정했다.
- `0w` 프로그램매매는 실전에서 이미 `_AL`을 사용한다. 키움 공식 등록 계약상 `0B`와 `0w`는 각각 별도 실시간 type이며, 같은 종목을 두 type에 등록했다고 하나의 합산 item 예산을 두 번 소비한다고 명시돼 있지 않다.
- PC 직접 연결과 NAS 장애전환 worker는 아직 모든 NXT 가능 종목을 KRX+NXT로 나눠 받아 NAS 혼합 정책과 다르다.
- NXT 불가 종목은 SOR로 바꾸지 않고 KRX 코드로 유지한다.

키움 공식 화면 도움말도 통합시세를 KRX와 NXT를 합친 시세로 설명한다. SOR 주문은 두 거래소 중 최선 조건의 거래소로 전송되는 주문 정책이며, 통합시세 선택과 실제 주문 체결 거래소는 별개 기록으로 봐야 한다.

## 확인된 결함과 위험

1. `infrastructure/kiwoom_rest/realtime.py::_market`은 `_NX`만 NXT로 판별하고 `_AL`을 KRX로 반환한다.
2. 중앙 1분봉·1초봉은 `tick.market`을 DB 복합키와 누적값 기준키로 사용하므로 잘못된 KRX 표기가 영속된다.
3. 연구 재생기는 KRX만 엄격히 읽기 때문에 위 SOR 행을 순수 KRX 원본으로 오인할 수 있다.
4. `_AL`을 즉시 SOR로 고치는 것만으로는 충분하지 않다. 중앙 분봉 GET, coverage, 최근 2거래일 차트, TOP20 집계가 KRX/NXT 이름을 기준으로 조회하는 부분을 함께 정리해야 한다.
5. 같은 종목에 SOR와 KRX/NXT 상세를 동시에 구독할 경우 화면·집계가 세 흐름을 모두 더하지 않도록 용도를 분리해야 한다.
6. 감사 당시 `REALTIME_ITEMS_PER_CONNECTION=190` 계산은 `0B`와 `0w`를 같은 item 예산에서 차감했다. 공식 REST WebSocket 문서는 한 `data` 행의 `item` 최대 100개와 `type` 최대 2개를 별도로 정의하므로 이 합산 방식의 근거가 없었다. 현재 구현은 `0B`와 `0w`를 독립된 타입별 200개 한도로 계산한다.

## 최소 변경 권고 순서

1. `0B`와 `0w` 등록 예산을 분리하고, 각 type 안에서만 item 수와 100개 단위 그룹을 계산한다. `0w` 때문에 `0B` 상세 자리를 줄이지 않는다.
2. 현재 혼합 구독 정책은 유지하되 TOP20·실매수 상세 0B 우선순위를 명시한다.
3. 수신 원본에 `source_market=SOR/KRX/NXT` 의미를 정확히 보존하고, 기존 잘못 표기된 행은 서버 build와 수집 시각으로 구간을 구별한다.
4. 화면용 통합 자료는 SOR 한 벌 또는 KRX/NXT 상세로 만든 파생 한 벌을 선택한다. 전환 구간·부분 수집은 후속 재검토 문서의 품질 규칙을 따른다.
5. 연구용 저장은 KRX/NXT 상세 원본만 사용하고 SOR는 별도 통합 자료로 저장한다. strict KRX reader가 SOR를 받지 않는 회귀를 추가한다.
6. TOP20 집계는 종목마다 `SOR 한 벌` 또는 `KRX+NXT 합계` 중 하나만 선택한다.
7. PC 직접·장애전환 구독도 중앙과 같은 type별 예산 정책으로 맞춰 경로 전환 전후 데이터 의미를 유지한다.
8. 운영 DB에서 `_AL` 수신분이 실제로 어느 시장명으로 얼마나 저장됐는지 표본을 확인한 뒤 parser·소비자 변경을 한 묶음으로 구현한다.

이 변경은 기존 `TradingVenue.SOR`와 시장별 DB 키를 활용할 수 있어 핵심 데이터 모델 교체나 대규모 재작성은 필요하지 않다.
