# 개인 시놀로지 중앙 서버 설계

> **문서 성격:** 목표 설계와 구현 진행 기록이다. 현재 실제 실행 구조, 특히 로컬 우선 캐시·동기화와 장애전환은 `../ARCHITECTURE_CURRENT.md`를 기준으로 한다.

## 목표

각 사용자가 자신의 API 자격 증명과 시놀로지를 사용한다. 키움·뉴스·AI API는 시놀로지에서 한 번만 호출하고, 여러 Windows 앱은 중앙 서버가 저장·배포한 데이터를 사용한다. 앱의 수가 늘어나도 키움 TR 요청량과 AI 분석 횟수가 함께 증가하지 않아야 한다.

## 저장 위치 원칙

시놀로지 PostgreSQL을 데이터의 유일한 원본으로 사용한다. 시세·분봉·일봉·순위·수급·뉴스 원문·AI 결과·테마·매매일지·전략팩과 공통 설정을 저장 기간 제한 없이 보관한다. 날짜 파티션과 인덱스로 장기 데이터의 조회 성능을 유지한다.

로컬 PC에는 창 위치·크기·모니터 배치, 중앙 서버 주소와 접속 정보, 장애 중 화면을 유지하기 위한 임시 캐시만 둔다. 네트워크 공유 폴더의 SQLite 파일을 여러 앱이 직접 열지 않는다.

## 실행 구성

1. 수집 서비스가 키움 OAuth, REST 호출 큐와 WebSocket 세션을 단독으로 관리한다.
2. 같은 데이터 요청은 합치며 DB에 이미 확정 데이터가 있으면 키움 API를 호출하지 않는다.
3. 중앙 API는 과거 데이터를 REST로 제공하고 실시간 데이터는 WebSocket으로 여러 앱에 전파한다.
4. 뉴스 수집·사건 묶음·AI 분석도 서버에서 수행하고 결과를 재사용한다.
5. Windows 앱은 `로컬 직접 연결`과 `개인 서버 연결`을 선택할 수 있다.

## 호출 우선순위

1. 인증 갱신과 실시간 연결 복구
2. 실시간 순위 및 체결 순간 스냅샷
3. 현재 화면에 필요한 최신 데이터
4. 장 종료 후 분봉·일봉·수급 보완
5. 과거 매매일지 및 대량 백필

국내주식 실전 조회 제한은 중앙 큐 전체에 적용한다. 연속조회와 재시도도 같은 작업으로 추적하며 최종 실패 자료는 `미확정` 상태로 남긴다.

## 보안

- 키움·네이버·DART·AI 비밀키는 시놀로지 환경 변수 또는 비밀 저장소에만 둔다.
- 중앙 서버 설정 API는 비밀키 원문을 반환하지 않고 설정 여부만 반환한다.
- PostgreSQL 포트는 외부에 공개하지 않는다.
- 외부 Windows 앱은 VPN 또는 Tailscale을 통해 중앙 API에 접속한다.
- 중앙 API는 사용자별 긴 접속 토큰을 요구한다.

## 단계적 전환

1. 버전이 있는 중앙 API 규격과 서버 상태 확인 기능
2. PostgreSQL 마이그레이션과 키움 REST 중앙 큐
3. 키움 WebSocket 수집 및 앱 실시간 전파 — 코드 연결 완료, 장중 실데이터 병행 검증 예정
4. 분봉·일봉·순위·시장·수급 데이터 전환
5. 뉴스·AI·테마 전환
6. 매매일지·전략팩·공통 설정 전환
7. 로컬/중앙 병행 결과 비교 후 개인 서버 모드 정식 전환

## 현재 구현 상태

- 중앙 서버 상태·기능 조회와 접속 토큰 인증
- SQLite/PostgreSQL 저장소 선택과 Synology Container Manager 배포 구성
- 키움 조회 REST 중앙 큐, 동일 요청 병합, 확정 응답 캐시, 호출 우선순위
- 매매일지 조회의 로컬 중앙 서버·개인 서버 경유
- 로컬 중앙 서버의 앱 연동 시작·종료 및 부모 앱 비정상 종료 감시
- 실시간 앱 접속 WebSocket, 여러 앱의 구독 종목 합집합과 이벤트 배포 허브
- 서버의 단일 키움 WebSocket 수집과 `0B`·주문체결·시장지수·프로그램매매 배포
- 중앙 모드 데스크톱 앱의 실시간 이벤트 수신과 기존 Qt 신호 변환
- 로컬 중앙 서버 시작 실패 시 기존 직접 연결로 실행 단위 자동 복구
- 체결·시장지수·프로그램매매 최신값을 1초 단위로 SQLite/PostgreSQL에 저장
- 앱 재접속 시 최근 5분 이내 최신값을 먼저 복원하고 이후 실시간 이벤트 연결
- 중앙 `0B` 체결에서 KRX/NXT별 1분 OHLCV·거래대금을 생성해 영구 저장
- 서버 재시작이 같은 분 중간에 발생해도 기존 봉과 증분 병합
- 인증된 중앙 1분봉 조회 API 제공
- `ka10080` 조회 분봉으로 실시간 누락 구간을 중앙 DB에 보완
- `ka10081` KRX/NXT 일봉을 중앙 DB에 장기 저장하고 조회 API 제공
- `ka00198` 순위를 조회 기준·기준시각별 이력으로 저장
- NAS가 평일 08:00~20:00에 앱 없이도 `ka00198` TOP20을 30초마다 조회하고 현재/다음 코호트의 `0B`를 독립 구독
- 거래일 중 TOP20에 한 번이라도 편입된 전 종목과 1분 TOP20 거래대금 지수·구성 코호트를 중앙 DB에 누적 보존
- 20:05 또는 다음 거래일 07:40 이전에 편입 종목의 당일 분봉 전체와 최근 250일 일봉을 보완하고 coverage 완료 근거 저장
- 완료 coverage가 있는 분봉·일봉은 키움 TR을 다시 쓰지 않고 중앙 DB에서 우선 응답
- Yahoo 지연 시세를 임시 공급원으로 `MNQU26.CME`·`CLV26.NYM` 5분봉과 일봉을 공급원·계약코드별 누적 저장
- `ka10045` 외국인·기관 수급과 `ka90008` 프로그램 수급을 종목·거래일·시장 기준별 저장
- 코스피·코스닥 실시간 시장 상태를 분 단위 이력으로 저장
- 순위·시장·수급 공통 조회 API 제공
- 뉴스 기사·종목별 AI 결과·공유 AI 결과·AI 사용량을 보존하는 중앙 콘텐츠 저장소/API
- 테마 프로필·종목별 테마·테마 메타데이터를 보존하는 중앙 콘텐츠 저장소/API
- 중앙 콘텐츠는 로컬 뉴스의 200건 정리 제한 없이 항목 키별로 계속 누적
- 데스크톱·뉴스 프로세스에서 사용할 인증형 중앙 콘텐츠 클라이언트
- 중앙 모드 시작 시 기존 로컬 뉴스·AI 분석·API 사용 이력·테마를 백그라운드에서 중앙 저장소로 최초 이전
- 최초 이전은 항목 키 기반 upsert라 재실행해도 중복되지 않으며, 실패해도 로컬 DB와 메인 실시간 표는 그대로 사용
- 뉴스 전용 프로세스가 로컬 뉴스 DB 변경을 감지해 60초 이내 중앙 저장소에 다시 보존
- 지속 보존도 별도 daemon 작업으로 수행하여 중앙 서버 지연·장애가 뉴스창과 메인 실시간 표를 멈추지 않음
- 다른 PC가 중앙 뉴스·AI 결과·테마를 내려받아 로컬 캐시에 병합하고 기존 화면에서 그대로 조회
- 최초 전체 조회 뒤에는 중앙 문서의 갱신 시각을 기준으로 변경된 항목만 페이지 단위로 내려받음
- 중앙 서버가 네이버 뉴스 키를 환경 변수로 받아 종목 뉴스를 직접 수집하고 원문 주소 기준으로 영구 보존
- 중앙 서버가 선택적으로 DART 키와 종목코드 캐시를 관리하고 네이버 뉴스와 공식 공시를 한 작업에서 병합
- 여러 PC의 동일 종목 동시 요청은 실행 중 작업 하나로 합치고, 최근 5분 내 완료된 요청은 중앙 캐시를 재사용
- 중앙 모드 뉴스창은 네이버·DART를 직접 호출하지 않고 중앙 뉴스 API 결과를 기존 로컬 캐시에 반영
- 중앙 서버가 OpenAI·Gemini·Anthropic 키를 환경 변수로 관리하고 뉴스 사건 분석 요청을 단일 실행
- 종목·기사 식별자·본문 해시·AI 공급자·모델이 같은 분석은 중앙 저장 결과를 재사용하여 API 비용을 다시 쓰지 않음
- 여러 PC에 적용되는 중앙 AI 일일 상한과 실제 호출 기준 토큰 사용량을 중앙 DB에 기록
- 중앙 캐시 결과를 받은 PC는 로컬 일일 API 사용 횟수를 올리지 않음
- 중앙 모드에서는 기사 주소와 사건 묶음만 서버로 보내고 원문 추출·검색 요약 대체·본문 해시 계산을 서버가 담당
- 원문 사이트 접근이 실패해도 저장된 검색 요약이 있으면 AI 분석을 계속하고, 둘 다 없을 때만 해당 사건을 실패 처리
- 중앙에서 한 번이라도 조회한 종목을 영구 관심 목록에 등록하고 뉴스창이 닫혀 있어도 기본 5분 간격으로 순차 재수집
- 자동 수집 간격은 `NEWS_REFRESH_SECONDS`로 설정하되 60초 미만은 허용하지 않고 종목별 최근 조회 캐시를 함께 적용
- 관심 종목마다 자동 AI 분석 사용 여부·최근 분석 사건 수·공급자·모델을 중앙 관심 목록에 함께 저장
- 뉴스 자동 수집이 끝난 뒤 증권 관련 기사만 최근 48시간 동일 사건으로 묶고, 설정한 최근 사건 수만 중앙 AI가 자동 분석
- 동일 사건의 관련 기사는 최대 20개 사건씩 한 요청으로 분석하며, 본문 해시가 같은 기존 결과는 AI를 다시 호출하지 않고 재사용
- 한 종목의 뉴스 수집·원문 추출·AI 공급자 오류는 다음 관심 종목의 자동 수집과 분석을 중단하지 않음
- 테마 추가·일괄 수정·분리·이름 변경·색상 변경·삭제가 끝나면 0.4초 동안 연속 변경을 합쳐 별도 작업에서 중앙 서버에 즉시 보존
- 중앙 테마는 단순 추가가 아닌 현재 스냅샷 교체 방식으로 저장하여 삭제하거나 이름을 바꾼 테마가 다른 PC에서 다시 살아나지 않게 처리
- 테마 중앙 저장 실패는 로컬 편집을 되돌리지 않으며 메인 실시간 표의 화면 처리와 분리
- 매매일지의 개인원칙·구조화 원칙·전략팩·검토 초안·전략팩 버전은 `journal.sqlite3`에 먼저 저장하고 60초마다 중앙 서버와 갱신 시각 기준으로 병합
- 개인 서버가 끊긴 동안의 매매일지 설정 변경은 로컬에 남으며, 연결이 복구된 다음 동기화 주기에 중앙으로 재전송
- 키움 체결내역·사용자 복기·자동/수동 매매유형·회차별 유형 수정·수동 매매 묶음·체결 당시 스냅샷·실제 비용·매매일지 종목·보완 상태도 같은 로컬 우선 방식으로 중앙 보존
- 매매일지 1분봉·일봉은 중앙 시장 DB의 원본을 사용하므로 매매일지 콘텐츠로 중복 업로드하지 않음
- 중앙 자료와 로컬 자료가 모두 있으면 각 행의 수정·확정·체결·캡처 시각을 비교해 최신 행을 유지
- 순위 기준·강조 임계값·신고가 기준·테마 입력 규칙 등 앱 동작 설정은 로컬에 먼저 저장하고 수정 시각과 함께 60초마다 중앙 병합
- 창 위치·크기·글자/행 크기·현재 선택한 테마 프로필·로컬 파일 경로·Google Drive 동기화 상태·아이콘/소리 파일 경로는 PC 전용으로 남겨 중앙 전송에서 제외
- `ka10080` 조회 결과로 접속 전·누락 1분봉을 중앙 DB에 보완
- `ka10081` 조회 결과를 KRX/NXT별 중앙 일봉으로 최대 5,000개까지 보존·조회
- 중앙 저장 실패와 화면 조회 성공을 분리하여 DB 오류가 메인 표를 멈추지 않게 처리
- 개인 서버 모드에서 `local_fallback_enabled`를 켜고 해당 PC에도 키움 API 키를 저장하면, 중앙 서버 네트워크 장애 동안 조회 요청을 로컬 키움 REST로 자동 전환
- API 설정의 `장애 대응` 체크 상자에서 로컬 자동 전환을 켜거나 끌 수 있고 저장 즉시 API 실행 구성을 다시 불러옴
- 기존 키움 API 설정 창에서 `직접 연결 / 이 PC 중앙 서버 / 개인 시놀로지 서버`를 선택하고 서버 주소·접속 토큰·페일오버·병행 검증을 한곳에서 저장
- 이 PC 중앙 서버를 처음 고르면 로컬 주소와 임의의 긴 접속 토큰을 자동으로 채우며, 데이터 모드 변경은 뉴스·동기화 프로세스까지 일관되게 바꾸기 위해 앱 재시작 후 전체 적용
- 중앙 WebSocket 연결이 연속 3회 실패하거나 서버가 키움 원본 연결 실패를 명시적으로 알리면 로컬 키움 WebSocket으로 전환
- 중앙·로컬 실시간 연결은 동시에 열지 않으며, 로컬 전환 중 60초마다 중앙 복구 여부를 다시 확인해 복구되면 중앙 연결로 복귀
- 중앙 서버가 정상 응답한 API 오류는 로컬에서 중복 호출하지 않아 같은 주문성 요청이 이중 실행되지 않도록 제한
- API 설정에서 `중앙값과 로컬값 병행 비교`를 켠 동안에만 중앙 조회 결과를 화면에 사용하고 같은 로컬 조회를 백그라운드에서 실행
- 비교 결과는 PC의 `central_local_validation.jsonl`에 API·시각·일치 여부·차이 필드만 기록하며, 화면 갱신을 기다리게 하지 않음
- 병행 비교는 로컬 TR을 추가로 소비하므로 기본값은 꺼짐이며 장중 검증할 때만 사용
- 같은 검증 옵션을 켜면 로컬 보조 WebSocket도 함께 열어 중앙·로컬의 체결·시장지수·프로그램매매를 종목과 체결시각 기준으로 비교
- 실시간 비교값은 화면에 섞지 않고 `central_local_realtime_validation.jsonl`에 일치 여부와 차이 필드만 기록
- 검증 중 중앙 장애로 페일오버할 때는 비교용 로컬 WebSocket을 먼저 닫고 실제 화면용 로컬 연결로 교체하여 이중 로컬 구독을 막음

중앙 모드의 메인 실시간 표, 콘텐츠 양방향 캐시, 뉴스·AI·테마, 매매일지·전략팩·공통 설정의 로컬 우선 중앙 동기화와 선택형 로컬 장애 전환까지 연결했다. 정식 기본값은 아직 기존 직접 연결이다. 다음 단계는 장중 직접 연결·중앙 연결 결과를 같은 조건에서 병행 기록해 순위·거래대금·신고가·수급의 일치 여부를 검증하는 것이다.

## 시놀로지 배포 점검

- Container Manager 구성은 PostgreSQL과 중앙 서버의 상태를 각각 점검하며 이상 시 자동 재시작한다.
- PostgreSQL 자료는 `postgres-data`, 서버 캐시는 `server-data`에 보존하여 컨테이너 교체와 분리한다.
- `kiwoom-monitor-check`는 공개 상태 확인, 토큰 인증, 중앙 DB 읽기, 실시간 WebSocket 준비 응답을 순서대로 검사한다.
- 기능 광고 응답에는 현재 구현된 뉴스·AI·테마뿐 아니라 매매일지와 공통 설정 지원 여부도 정확히 표시한다.
- 실제 NAS 주소·토큰이 없는 개발 환경에서는 자동 테스트까지만 수행하고, 실제 장비에서는 설치 문서의 점검 명령을 통과한 후 개인 서버 모드를 켠다.
- Container Manager 실제 기동, 기존 시장 DB 이전, 장중 단절·복구 및 다른 PC 접속 검증은 시놀로지 장비 준비 후 수행할 후속 작업으로 둔다.

## 중앙화 완료 후 UI·데이터 후속 작업

- 메인 화면의 `기본설정` 글자 버튼을 톱니바퀴 아이콘으로 변경함.
- 톱니바퀴 오른쪽에 `TOP20 지수` 버튼을 배치함.
- 기본설정의 `API 및 외부 서비스` 화면에서 키움·중앙 서버, 네이버·DART·AI, Google Drive 설정에 모두 접근하도록 통합함. 기존 암호화 설정 파일은 그대로 사용하며 실행 중인 뉴스창에도 저장 내용을 다시 불러오게 한다.
- 기본설정의 `프로그램 정보`를 `정보`로 변경함.
- 인포스탁 엑셀과 키움 실전 `ka90001`·`ka90002`를 비교함. 비교 시점 기준 인포스탁은 74개 테마·1,993개 연결, 키움은 142개 테마·902개 연결이며 이름이 같은 테마 5개도 구성 종목이 완전히 같지 않아 동일 자료로 간주하지 않는다.
- 비교·정제된 테마를 최초 설치 시 기본 테마로 제공하되 사용자의 수정 테마와 갱신 규칙을 분리한다.
- 메인 표의 테마별 포함 종목 수가 같으면 해당 테마 종목의 거래대금 합계가 큰 테마를 위에 배치함.
- 테마 거래대금 정렬 기준은 1분·5분·60분·1일 중 선택하며, 선택한 시간이 테마 순서와 종목 표시를 함께 따라가게 함.
- `상위 테마`와 `제외 종목 반영 상위 테마` 중 동률 정렬 기준을 선택할 수 있으며, 후자는 지정 종목을 종목 수와 거래대금 합계에서 모두 제외함.
