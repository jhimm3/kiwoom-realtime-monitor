# SOR 통합 시세 저장·소비 계약 재검토

기준: 2026-09-14 현재 워크트리. 상태: S0~S4 로컬 구현·집중 회귀 완료, 운영 DB 미조회·NAS 미배포.

## 결정

현재 혼합 구독을 유지한다. 일반 NXT 적격 종목은 `_AL`, 우선 종목은 KRX와 NXT 상세를 받는다. 통합 원본도 영구 저장한다. 화면 전용으로 쓰고 버리지 않는다.

`TradingVenue.SOR`와 `TradingVenue.COMBINED`가 이미 있고 중앙 봉 키에 `market`이 포함되어 있으므로 핵심 모델을 교체할 필요가 없다. 앞선 ‘별도 시장을 새로 만드는 설계 변경이 필수’라는 판정은 과했다. 필요한 것은 기존 구분의 의미를 명확히 하고 parser·저장·소비자를 함께 보완하는 것이다.

| 값 | 시세 자료에서의 의미 | 허용 용도 |
| --- | --- | --- |
| KRX | KRX 원본 | KRX 연구, 화면 통합의 한 구성요소 |
| NXT | NXT 원본 | NXT 연구, 화면 통합의 한 구성요소 |
| SOR | 키움 `_AL` 통합 시세 원본 | 통합 화면·통합 연구의 원본 |
| COMBINED | 앱/NAS가 KRX와 NXT 원본으로 계산한 통합 결과 | 파생 화면·명시된 통합 연구 |

SOR는 물리적 제3 거래소가 아니다. 기존 enum 이름을 호환 목적으로 유지한다. 주문의 SOR 라우팅과 시세의 SOR 출처는 별개다. 실제 계좌 체결 venue는 00 원본의 거래소 필드로 판단하며 0B나 시각으로 덮어쓰지 않는다.

공식 근거: [키움 거래소 시세·SOR 설정](https://download.kiwoom.com/hero4_help_new/9991.htm)은 통합 시세를 KRX+NXT로, SOR 주문을 최선 거래조건 거래소로 보내는 설정으로 설명한다. 이 페이지의 거래시간·주문 제한 안내는 사용자가 전달한 개편 내용과 다르므로 이번 검토에서 최신 시간표 검증 근거로 사용하지 않았다. 타입별 총 200개는 직전 사용자 확인에 따른 운영 계약이며 이 도움말로 입증한 값이 아니다.

## 현재 문제와 코드 근거

1. `infrastructure/kiwoom_rest/realtime.py::_market`은 `_NX`만 구별하고 `_AL`은 KRX로 반환한다. 0B·0w와 잔고 parser가 같은 함수를 사용한다.
2. `central_server/minute_bars.py`의 두 accumulator는 `tick.market`을 봉·누적값 키에 사용한다. 잘못된 표기가 저장 경로로 이어진다. 실제 운영 DB의 영향 종목·행 수는 아직 확인하지 않았다.
3. `application/research_replay.py`는 관측 venue와 payload.market 둘 다 KRX인 봉만 허용한다. 잘못 KRX로 표시된 과거 SOR를 자동 구별할 수 없다.
4. `application/minute_chart_service.py`의 중앙 오늘/최근 2거래일 경로는 KRX·NXT만 조회한다. parser만 고치면 SOR 전용 종목의 저장 분봉이 화면에서 빠진다.
5. `application/minute_trade_value.py`는 누적 기준을 `(code, market)`으로 관리하지만 최종 분봉은 종목별로 합친다. SOR와 상세 틱을 동시에 전달하면 중복 합산될 수 있고, 상세→SOR→상세 복귀 때 남아 있는 누적 기준으로 비수신 구간 금액을 새 분에 붙일 수 있다.
6. `central_server/realtime_collector.py`의 연속 수신 시작 기록은 현재 희망 KRX/NXT 목록을 기준으로 한다. 실제 REG에 `_AL`이 들어간 경우와 상세로 전환한 경우의 수신 연속성 근거와 다르다. 정확한 원본 이름 수정만으로 이 문제는 해결되지 않는다.
7. 직전 92개 테스트 통과는 타입별 한도·기존 기능 회귀 결과다. SOR 출처·전환·통합 차트 안전성을 검증한 결과가 아니다.
8. 실제 보유·매수라는 직전 설명은 범위가 넓었다. 현재 우선순위 입력은 `autonomous_top20.py`의 TOP20 수집 코드와 `_account_entry_codes`다. 모든 계좌의 전체 보유잔고 자동 편입까지 완료됐다고 말하면 안 된다.

## 대안 비교

| 대안 | 장점 | 문제 | 결정 |
| --- | --- | --- | --- |
| 전 종목 SOR만 수집 | 구독 단순, 종목당 1 item | 거래소별 연구 원본 손실 | 채택하지 않음 |
| 전 종목 SOR + 우선 KRX/NXT 추가 | 화면 원본 일정 | 상세 종목마다 총 3 item, 같은 200 한도에서 상세 범위 감소 | 현재 채택하지 않음 |
| 현재 혼합 + 출처/전환 계약 보완 | 일반 수집 범위와 상세 연구 유지, 기존 구조 활용 | 전환 및 차트 선택을 검증해야 함 | 채택 |

0B 예산은 `활성 고유 종목 수 + 상세 NXT 종목 수 <= 200`, 0w는 독립된 `등록 종목 수 <= 200`이다. 예를 들어 고유 110개면 0B 상세 추가 자리는 최대 90개다. NXT 적격성과 세션에 따라 실제 사용량은 줄 수 있다. TOP20·실제 매수 편입·일반 앱 요청 순서를 적용한다. 조건 코호트는 기본 0B 수집을 보장한다. 고유 종목 자체가 200개를 넘는 상황은 상세 축소만으로 해결되지 않으므로 별도 대상 축소 정책이 필요하며, 이번 수정이 해결했다고 보고하지 않는다.

## 입출력 계약

### 원본과 저장

- `_AL` 0B/0w → 정규화 code + `market=SOR`. `_NX` → NXT, 정상 무접미 코드 → KRX. 필드 누락·상충을 KRX로 새로 추정하지 않는다. 기존 무접미 fixture 호환과 잔고 04 의미는 각각 테스트한다.
- 중앙 1초/1분은 기존 테이블·market 복합키를 유지한다. SOR를 KRX로 복제하지 않는다. 새 시장별 테이블이나 범용 provider 계층을 만들지 않는다.
- 원본 수신시각·관측시각·단위·partial/complete 의미는 유지한다. 등록 전환의 시작/종료, 구독 revision, 실제 item 집합을 기존 관측/문서 저장 경계에 남겨 후속 오염 판정에 사용한다. 영구 열 추가가 필요한 경우에만 명시 마이그레이션한다.
- `0w` 통합 누적값을 KRX/NXT별 값으로 분해하지 않는다. 장후 TR 보완도 원래 거래소 범위와 수집시각을 보존하고 다른 범위의 값을 같은 원본처럼 덮지 않는다.

### 화면과 차트

- 같은 종목·같은 시간구간은 **SOR 한 벌 또는 KRX+NXT 파생 한 벌**만 쓴다. SOR+KRX+NXT 합계는 금지한다.
- 비교 가능한 complete SOR가 있으면 그것을 사용한다. 없으면 해당 구간의 필요한 상세 venue가 모두 충족된 KRX+NXT를 사용한다. 두 경로 모두 부분이면 부분 자료임을 유지하고 완전한 봉으로 승격하지 않는다. NXT 비대상/정상 휴장과 장애로 인한 NXT 결측은 구별한다.
- KRX+NXT OHLC를 봉만으로 합칠 때 정확한 최초·최종 체결 순서를 알 수 없으면 파생값임을 남긴다. 거래대금·거래량은 원본 범위가 겹치지 않을 때만 합산한다.
- 시장 생략인 기존 GET의 의미를 몰래 변경하지 않는다. 명시적인 `view=combined` 같은 선택 입력/별도 capability로 중앙 통합 조회를 추가하고 기존 market=KRX/NXT 조회는 그대로 유지한다. 새 앱은 기능 협상 후 사용한다. 구 서버에서는 기존 조회를 유지하며 자동 TR 보완을 재도입하지 않는다.
- 가능하면 중앙에서 한 번의 DB 읽기 응답으로 통합 차트를 제공한다. 앱이 매번 세 시장을 각각 조회하는 새 지연 경로를 만들지 않는다. 최근 2거래일·오늘·coverage·캐시도 같은 선택 규칙을 사용한다.

### 구독 전환

- 희망 코드 집합 대신 실제 승인된 REG item/type 집합을 기준으로 source mode와 연속성을 관리한다. 우선순위만 바뀌어도 최종 item 집합이 바뀌면 재등록한다.
- SOR↔KRX/NXT, 로컬↔NAS, 재연결 때 이전 누적 기준을 새 연결 구간에 재사용하지 않는다. 해당 source의 첫 누적값은 기준점으로만 사용한다.
- 이미 수신한 봉은 보존하되 전환을 포함한 초/분은 partial로 남긴다. REG 승인 시각만으로 시장 이벤트의 정확한 인계시각을 알 수 없으므로 전환 구간을 완전하게 이은 것으로 선언하지 않는다.
- 이전 등록의 늦은 틱이 도착해도 현재 화면 집계에 다른 source mode가 동시에 섞이지 않도록 현재 승인 집합을 확인한다. event ID가 없는 상황에서 시간·가격이 같다는 이유만으로 서로 다른 실제 체결을 전부 제거하지 않는다.
- 새 epoch/revision은 원본 누적 상태와 집계 품질을 구별하는 최소 정보다. 별도의 구독 Manager를 추가하지 않고 기존 collector와 subscription 모듈에 둔다.

### 연구와 과거 데이터

- strict KRX reader는 계속 KRX 원본만 허용한다. 통합 시세를 KRX로 변환해서 연구를 계속 돌리지 않는다.
- 통합 시세 연구는 별도 명시 입력 프로필에서 source·세션·coverage를 고정한 뒤 후속 구현한다. 이번에는 수집과 조회가 가능하도록 보존한다.
- 과거 KRX 행을 날짜만으로 전부 SOR로 바꾸지 않는다. 정확한 item 등록 이력·원본·배포시각으로 입증 가능한 구간만 정정한다. 근거 부족 구간은 `venue_unverified` 성격의 품질 제한을 연구 입력에서 적용한다.
- 이미 확정한 연구 run/manifest/사용자 매매일지는 덮지 않는다. 영향 범위와 재실행 필요 여부를 별도 기록한다. TR 장후 보완은 사후 자료이며 당시 관측 원본을 복원했다고 취급하지 않는다.

| S0 재현 고정 — 완료 | test_realtime, test_minute_trade_value, test_central_minute_bars, test_minute_chart_service | `_AL`/상세/전환 fixture → 잘못된 결과 재현 | `_AL` 오표기와 전환 누적 위험 회귀 고정 |

S1~S3은 코드 작성 단계를 나눌 수 있지만 사용자 앱과 NAS에 부분 활성화하지 않는다. parser만 배포하는 것이 가장 위험하다. staging/fixture에서 연결 검증 후 하나의 누적 빌드로 활성화한다. 전체 보유잔고 수집 확대나 통합 연구 전략 신규 개발은 이번 수정과 분리한다.

필수 회귀: 기존 92개 + realtime/minute_trade_value/central_minute_bars/second storage/market observation/research replay/minute chart/remote client/main window 관련 모듈. 운영 검증 시 실제 주문은 필요 없다. 실전·모의 TR 예산은 독립 유지하고 테스트를 이유로 주문·추가 실전 WebSocket을 열지 않는다.

## 검토 범위와 남은 확인

정적 코드 경로와 공식 시세 설명을 확인한 뒤 제품 코드와 서버 build 후보를 갱신했다. 집중·인접 회귀 157개가 통과했고 S5에서 NAS SOR→로컬 KRX/NXT→NAS SOR의 누적 기준 회귀와 완전 비교 전용 요약을 추가했다. 실제 NAS에 들어온 `_AL` 이벤트의 필드, 과거 오표기 건수, 현재 배포 버전, 거래소별 실제 데이터 완전성은 배포 뒤 운영 검증에서 확인해야 한다.

판정: 설계 방향은 확정 가능하다. 기존 구조 안에서 Sol이 단계적으로 구현할 수 있으며 재작성·새 범용 프레임워크·추가 모델 승인 흐름은 필요 없다.
