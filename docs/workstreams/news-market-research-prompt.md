## 기준과 목적

사용자가 지정한 **00 종합의 기능·입력 구조가 기준**이며, 첨부한 포트폴리오 뉴스레터는 거시·금리·환율·수급·실적·가이던스·밸류에이션·경쟁우위·단기/장기 영향 분석의 참고다. 뉴스레터의 운용 모드·매수/축소 의견·가상 보유 비중·합계100% 시나리오 확률을 앱의 규칙으로 가져오지 않는다.

이번 작업은 ①이 필요로 하는 자료를 **받아서 기록하는 형식**을 만드는 것이다. 자료를 어떤 가중치로 조합하거나 언제 매수·축소할지 정하지 않는다. 분류값은 모델이 보고한 해석이며 학습 정답·검증된 인과관계·투자 정책이 아니다.

00 종합은 미완성 설계 초안이므로, 아래 대응은 요구 의미와의 대조다. 기존 앱에서 해당 기능 전체가 구현됐다는 표시는 아니다. 외부 LLM 공급 방식과 KST 시계 등은 현재 사용자 지시·저장소 지침을 따른다.

## 앱이 받는 형식

`news-market-research-v1`은 기존 `morning-market-brief-v4` DTO를 재사용하는 별도 연구 계약이다. 기존 저장 보고서를 새 버전으로 가장하거나 1,720일치를 새 형식으로 자동 변환하지 않는다.

- `events.category/variable/change`: 무슨 종류의 자료에서 무엇이 어떻게 변했는지.
- `events.impacts[]`: 어느 대상에, 어떤 방향·전달 경로·기간의 영향이 예상되는지. 대상이 미정이어도 사건은 보존한다.
- `market_data`: 기존9개 지표의 수치·단위·상품·비교 기준·시각·확인 상태.
- `measurements[]`: 추가 지표, 실적·가이던스·컨센서스·밸류에이션의 수치와 비교값·기간·전망/발표 구분·출처.
- `evidence/facts/unknowns`: 원문 링크·시각·모델 열람 표기·사실 상태·미확인 사항. 확인 부족으로 값을 null로 덮어쓰지 않는다.

`reason/interpretation/observation`은 사람용 설명이다. 앱의 `research_feature_rows()`는 그 문장의 긍정/부정 단어를 해석하지 않고 분류·수치·참조 필드만 투영한다. 근거와 미확인 메모도 행에 보존한다. 같은 수치가 여러 영향 대상에 연결되면 `measurement_key`로 구분하며 독립 근거 수로 중복 가산하지 않는다. 전체 검증 결과의 measurements/evidence/facts도 원본대로 보존해야 한다.

예시는 **합성 수치와 가상의 업종 노출**이다. 환율 상승을 수출기업에 자동 호재로 판단하는 규칙이 아니다. 특정 기업의 계약·헤지·원가·매출 노출은 실제 자료로 받아야 한다.

## 입력 방식과 현재 연결

실시간 조사에서는 `source_mode=ai_web_search`, 과거 동결 자료에서는 `provided_snapshot`을 명시한다. 후자는 도구·사후 지식으로 보완하지 않고 제공된 자료와 확인 상태를 받는다. 과거 시점이 미확인이면 그 상태를 보존하며 임의 시각을 부여하지 않는다. 수집·생성·수신 감사 시각은 실행자가 기존 키움 보정 시계/KST 또는 명시적 오프라인 KST fallback으로 관리한다.

앱 코드의 준비 경로는 `render_research_prompt()` → **호출자가 보존한 응답** → `validate_output(..., research=True)` → `research_feature_rows()`다. 프롬프트·스키마·예시는 같은 DTO에서 내보낸다. 렌더러/검증기/투영 함수는 직접 검색·LLM 호출·DB 쓰기·예약 작업을 하지 않는다.

이 경로를 과거 batch나 기존 연구 입력 loader/자동 연구/운영 설정에 연결하는 작업은 아직 하지 않았다. 기존 v4 운영 프롬프트·사용자 저장 설정·07:55 예약도 교체하지 않았다. 원래 batch에는 STOP이 있으며, 사용자가 재개를 요청하기 전에는 제거하지 않는다. 원자료·원응답·입력 hash·시황·진행 기록은 유지한다.
