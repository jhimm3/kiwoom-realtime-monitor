# 보강 검사와 확인된 제품 오류의 후속 수정

2026-10-18 사용자 요청에 따른 로컬 수정이다. [원래 5,504건 감사](README.md)의 기준 원장과 최초 실패를 보존하고, 남아 있던 보강 검사와 확인된 제품 오류를 수정했다. 별도로 진행 중인 순위표 묶음 조회·R3 저장 개선은 보존했으며 이 작업의 실적으로 합치지 않는다.

## 보강 대상의 처리

보강 216건 가운데 이미 반영된 99건은 유지하고, 미반영 117건을 보완했다. 검사마다 기존 요구사항·제품 경로·수정 내용·현재 실행 여부를 [후속 개별 원장](followup-cases.json.gz)에 기록했다. 이름을 정확한 검사 범위로 바꾼 2건도 원래 ID와 대응시킨다. 기존 검사를 수정한 것과 새 오류 재현 검사를 추가한 것을 구분한다.

실제 저장값과 실패 후 원본 보존, 입력과 출력의 대응, 취소·종료 후 자원, 화면의 내용·렌더링, 시계 경계를 검사한다. 내부 함수 호출 여부나 같은 구현의 왕복만으로 결과를 확인하던 부분을 보완했다. **generic-report라는 단어의 정확한 분류 정답은 사용자 요구가 확정되지 않았으므로 만들지 않았다.** 해당 검사는 원문·본문·hash·건수·결과 파일 보존을 확인하며 기존 독립 규칙 검사와 함께 실행했다. 이것을 분류 효용의 검증으로 확대하지 않는다.

원래 [해석 미결 49건](unresolved.json)은 그대로 보존했다. 돌파·눌림의 미정 수치, 미확인 뉴스 제외, 연구 제한, canonical UTC와 업무 시각의 구분을 새로 정하지 않았다.

## 수정한 제품과 연결 경로

| 확인된 문제 | 수정과 연결 확인 |
|---|---|
| 일지의 혼합 UTC/KST 문자열 비교로 최신 값·삭제 상태가 뒤집힘 | 값을 비교할 때 실제 순간으로 비교한다. 원래 저장 문자열은 유지한다. 원격 병합·동기화 상태·삭제·재수신·동일 순간을 실제 SQLite로 확인했다. |
| SQLite metadata 범위에서 같은 순간의 다른 offset이 누락됨 | 조회 비교만 정규화하며 microsecond를 보존한다. subject·정확한 시작/종료 경계·극단 offset·원래 저장값을 확인했다. raw 날짜 사전 범위로 불필요한 파싱도 줄였다. PostgreSQL 실행 검증으로 확대하지 않는다. |
| 뉴스 AI 후보가 백업·복원 중 유실됨 | `theme_candidates`를 기존 백업 경로에 포함한다. 옛 백업에 필드가 없으면 기존 후보를 지우지 않는다. 전체 결과 왕복·실패·strict restore·테마 검토 소비자를 확인했다. |
| Daishin summary 누락 오류 뒤 앞 페이지가 커밋됨 | 같은 기존 transaction 안에서 EOF summary를 확인해 오류 시 롤백한다. 기존 행 보존·다시 가져오기를 확인했다. |
| 뉴스 revision의 같은 가용 시각 또는 늦게 받은 과거 시각에서 페이지 누락 | 기존 accepted sequence를 따르는 revision cursor를 저장소→인증 API→client→corpus exporter에 연결했다. 같은 시각 1,005행과 시각/수신 순서가 다른 행을 확인했고 기존 `as_of`는 보존했다. |
| 영문 포함 6자리 종목코드가 계좌 조회에서 소실됨 | 기존 유효 코드 형식을 공통 reader에 적용했다. 모의·실제 계좌 reader와 unit fill의 코드 보존을 격리 확인했다. 주문 정책이나 송신은 바꾸지 않았다. |
| 가격 저장의 writer 없는 실패 경로에서 RAM 대기값 유실 | 기존 실패 병합 경로를 사용해 재시도한다. 더 최신 값 우선·세 값의 저장·정상 재시도·종료를 확인했다. |
| API 설정 교체 중 예외가 나면 일부 새 자원만 적용됨 | controller의 기존 자원과 MainWindow 소유 화면 상태를 복원한다. factory 중간 실패·실제 view 적용 실패·복원 실패의 원래 오류 보존·성공 경로·연결된 저장소 시계를 확인했다. |
| NAS worker의 expected failure가 성공 처리됨 | 기존 결과의 expected/unexpected 실패를 집계해 실패로 보고한다. operator에는 숫자 진단만 전달하며 권한·승인·sudo 정책은 바꾸지 않았다. 실제 NAS 적용은 하지 않았다. |
| 안전하게 끝난 skip·빈 suite에서 전수 실행기가 나머지를 중단함 | 불완전 결과는 계속 실패로 기록하되 종료·격리가 확인되면 예정된 다음 묶음을 실행한다. timeout·중단·불안전한 자식은 중단한다. 작은 가짜 묶음으로 검사했으며 전수 실행은 하지 않았다. |
| 기사 pool에서 최신 시작 작업을 최장 대기로 표시 | 가장 먼저 시작한 실제 활성 작업을 고른다. 서로 다른 두 작업의 경과 시간과 후속 cooldown을 확인했다. |
| AI 묶음 결과의 중복/범위 밖 ID로 다른 기사에 결과를 붙임 | 기존 1..N ID 계약을 지키고 역순 ID는 올바른 기사에 대응한다. 새 뉴스 분류 기준은 추가하지 않았다. |
| 전용 PG URL 검사와 benchmark의 자원 수명 오류 | 기존 지원 scheme의 정확한 일치만 사용하고 benchmark SQLite 연결을 실제로 닫는다. 오류·재시도·출력 보존을 관련 검사로 확인했다. |

시계는 별도 시계나 조회를 추가하지 않고 기존 `server_now`/`ranking_now` 전달을 사용한다. AI 일별 소유권·뉴스 사용량/Naver 예산, broker/store 캐시와 realtime freshness, event의 수신·가용 시각, HTTP archive 기준일, 일봉/분봉/테마 저장, 후보 화면 만료, 뉴스/연구 검토 화면을 연결했다. MainWindow의 저장소뿐 아니라 저장 worker가 내부에서 만드는 일봉·분봉 저장소에도 같은 provider를 전달한다. API 교체 후에는 현재 loader의 시계를 따른다. epoch는 순간을 보존하고 업무 ISO 표현은 KST로 내보낸다. TOP20 시장 분할 보정 뒤 해당 일자의 일별 캐시도 무효화한다.

이 목록은 **이번에 확인·수정한 경로**다. 전체 앱의 모든 독립 시각이나 canonical/lease 경계까지 일괄 변환했다는 뜻이 아니다. 확인이 더 필요한 연구 시각 경계와 실제 PostgreSQL 잠금·장중 부하·외부 공급자·예약 실행은 기존 미검증으로 남는다.

## 검증과 보존

현재 관련 검사 **고유 1,879건이 통과**했다. 정확한 ID·실행 근거는 [후속 실행 원장](followup-verification.json)을 따른다. 이전 감사의 1,086건을 이번 수정 후 통과로 재사용하지 않는다. 현재 관련 검사에서 다시 실행한 ID만 중복 제거했다. 이번에 추가 보강한117건은 모두 현재 실행에서 통과했다. 기존 보강을 포함하면216건 중171건을 이번에 실행했고, 수정하지 않은 나머지45건은 이전 감사에서 반영·검증한 것으로 `prior_audit_only`로 구분한다. 전체5,504건을 다시 실행한 결과가 아니다.

최초 실패·샌드박스 오류·Qt core와 widget을 같은 worker에 섞어 종료된 실행·안전한 중단·재개 기록을 보존했다. Qt core 전용 저장 검사와 화면 검사는 분리된 worker에서 재확인했다. API 비교에서는 옛 내부 `time()` patch를 현재 주입 시계로 바꾸며 기준 JSON을 재생성하지 않는다. 의도적으로 달라진 clock 열은 먼저 정확한 주입값을 검증하고 비교 사본에서만 기존 표현으로 맞춘다. 나머지 저장값·hash·HTTP/ASGI 동작의 비교를 유지한다.

근거 원문은 `data/diagnostics/test-case-review-20261018/`와 `data/diagnostics/test-review-fixes-20261018/`에 있다. 전수 회귀·새 CI·NAS 배포·운영 DB 변경·실제 계좌/주문·외부 AI 호출·commit/push는 수행하지 않았다. 코드와 격리 검사의 완료를 운영 수락으로 확대하지 않는다.
