2026-10-18. **기준 고유 검사 5,504건 / 460개 모듈의 개별 검토를 완료했다. 미검토·중복 배정·범위 밖 ID는 각각 0건이다.** 각 검사 본문·fixture·현재 제품 경로·요구사항을 대조한 원장을 합쳤다. ID 집합 검사는 기록 누락을 확인하는 수단이며, 정적 목록 생성이나 일부 실행을 개별 의미 검토로 대신하지 않았다.

기준은 `6cf3d4c83845c6a7ee0a1ad5b5bc0a6a5bafb373`의 Actions `39091008148`에 실제 나온 고유 ID다. 당시 5,516회에는 중복 등록 12회가 포함됐다. 기존에 이름을 바꾸거나 이동한 검사 2건은 원래 `baseline_id`를 보존했다. **이 문서는 5,504건의 검토 완료이며, 모든 문제가 수정됐다거나 현재 작업본의 전수 실행이 통과했다는 뜻이 아니다.** Windows 기준 밖의 별도 Linux/PostgreSQL 전용 검사를 이번 숫자에 합치지 않았다.

## 중요한 검증 누락·제품 불일치

아래는 이번 감사에서 **제품을 수정하지 않은 별도 발견**이다. 격리 재현과 정적 발견을 구분한다. 테스트 개수로 이 문제가 없다고 말할 수 없다.

| 발견 | 확인 범위 | 기존 검사가 놓친 이유 |
|---|---|---|
| 일지 동기화가 더 최신 UTC 자료를 오래된 KST 자료보다 이전으로 판단 | 격리 SQLite 재현. KST10:00 로컬과 UTC02:00(한국11:00) 원격에서 옛값 유지 | 같은 시각 문자열 형식 또는 빈 로컬만 사용 |
| metadata 범위 조회가 같은 순간의 UTC/KST 경계에서 다른 결과 | 격리 SQLite 재현 | 모든 fixture가 같은 offset |
| 뉴스 AI 백업에서 `theme_candidates` 유실 | 실제 격리 왕복 원본1 → 복원0 | 비어 있는 후보로 존재 여부만 검사 |
| Daishin artifact에 summary가 없으면 오류 뒤 이미1행 커밋 | 격리 SQLite 재현 | 정상 summary 또는 오류 예외만 검사하고 실패 뒤 저장 결과 누락 |
| NAS worker가 `expectedFailure`를 통과로 표시 | 격리 worker 재현: passed/tests1/failures0/errors0 | skip만 검증하고 expected failure 집계를 누락 |
| writer 없는 가격 저장 fallback 오류 후 대기 RAM 값 유실 | 격리 controller 재현 | 실제 writer 오류 또는 fallback 성공만 검사 |
| 일부 시계가 공통 키움 시계 대신 호스트 날짜·독립 UTC를 사용 | 뉴스 일일 사용량, 0B available_at, 후보 화면 만료 등의 격리 반례와 나머지 정적 경로 확인 | 주입 시계와 호스트 시계가 같은 fixture |
| full runner가 안전하게 종료된 skip/빈 suite에서도 후속 묶음을 중단 | 현재 실행기 분기 확인, 제품 미수정 | 성공 진행과 안전하지 않은 프로세스 중단만 검사 |

추가로 오래 기다리는 REST/cache/backoff·native UI/child·프로세스 종료 검사는 실제 유지 목적이 있다. 그러나 65분 시험 중 일부는 고정 monotonic 시간과 burst 재생이며 실제65분 연속 운용 증명이 아니다. 이번 정리 뒤 전체 실행 시간을 새로 측정하지 않았다.

해석 미결49건에는 임의 돌파/눌림 수치의 원래 승인 근거, 미확인 뉴스의 DROP 기대, 연구 탐색의 자본·수량 제한, 일부 장후 coverage 근거, UTC canonical 원본과 업무 KST 표시의 경계가 포함된다. 테스트가 현재 구현과 같다는 이유만으로 사용자 확정 요구라고 취급하지 않는다. 확정하지 못한 규칙을 조용히 바꾸거나 통과 기준을 약하게 만들지 않았다.

실제 장중 0B→NAS→Windows 표시·강도·알림 지연, 실제 모의 주문과 체결 대사, 실제 예약/외부 AI, 연구 규칙의 효용은 이 격리 감사의 통과 범위가 아니다. fake broker나 SQLite 동시성 검사를 실제 NAS PostgreSQL 부하·실계좌 수락으로 확대하지 않는다.

## 실행·변경 범위

관련 테스트 **고유1,086건이 통과**했다. 정확한 ID와 실행 근거는 [실행 원장](related-execution.json)을 따른다. 반복 실행은 합산하지 않았으며 최초 실패·환경 오류·취소와 성공한 재실행을 별도 보존했다. Windows 샌드박스의 asyncio socketpair/임시 DB 접근 문제는 같은 검사 경로를 사용자 환경에서 재검증했고 제품 이벤트 루프·의존성을 바꾸지 않았다. `httpx2` 설치나 오류 검사 생략은 없다. 전체5,504건 재실행 결과가 아니다.

이번 감사의 변경은 테스트·문서·감사 자료다. 제품 코드·NAS·운영 DB·주문·권한·실제 외부 추론은 변경하지 않았다. 전수 회귀·새 CI·commit/push·배포도 하지 않았다. 이전 CI의 성공을 현재 수정본에 승계하지 않는다.

검토 도중 같은 작업 공간에 별도 순위표 저장값 묶음 조회 변경(`stock_repository.py`, `main_window.py`, 해당 테스트3개 추가와 관련 문서)이 나타났고 이후 다른 자료 조회 경로의 수정도 진행됐다. 이를 보존했으며 이 감사의 제품 수정이나5,504개 기준 ID에 섞지 않는다. 순위표 추가3개 본문과 제품 diff는 별도 대조했지만 해당 작업의94건 실행을 이번 실행 합계에 더하지 않았다. 이후 별도 작업의 변경까지 이번 고정 기준 검토의 완료 범위로 승계하지 않는다. 모든 작업 공간 변경을 이번 감사에서 만든 것으로 보고하지 않는다.
