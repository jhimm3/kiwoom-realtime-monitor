# A5c 매매일지 체결 대조 read projection

완료일: 2026-09-16

## 목적

kt00007에서 가져온 계좌 체결과 중앙 모의 실행 원장의 상세 FILL이 같은 실제 체결을 설명할 때
두 출처를 각각 거래로 더하지 않는다. 후속 FeedbackEvidence는 이 read projection의 선택 체결과
품질 상태를 사용해야 한다.

## 대조 단위

- canonical 계좌 scope
- KST 거래일
- broker 주문번호
- 종목코드
- 매수/매도

같은 묶음의 총수량과 `수량 × 가격` 합계가 모두 같아야 `EXACT`다. 주문번호가 없는 kt00007 행은
상세 원장에 추정 연결하지 않는다. run ID와 decision ID는 상세 체결의 연구 계보로만 보존한다.

## 상태와 선택 규칙

| 상태 | 의미 | 결과 체결 |
| --- | --- | --- |
| `EXACT` | 두 출처의 수량·금액이 모두 일치 | 상세 FILL 한 벌 |
| `DETAIL_ONLY` | 상세 FILL만 존재 | 상세 FILL 한 벌 |
| `SUMMARY_ONLY` | kt00007 요약만 존재 | 기존 요약 한 벌, 미확인 |
| `PARTIAL` | 두 출처의 수량이 다름 | 확인된 상세 FILL만, 미확인 |
| `CONFLICT` | 같은 수량의 금액 차이 또는 broker 체결 ID 내용 충돌 | 중복 제거한 상세 FILL만, 미확인 |

상세가 하나라도 있으면 kt00007 요약을 결과 수량에 더하지 않는다. 따라서 부분 수신 중에도
확인된 상세 수량과 요약 수량을 합친 잘못된 손익이 생기지 않는다. 비용은 이 단계에서 체결별로
확정하지 않으며, 다음 단계가 kt00015 일별 비용의 완전성과 함께 순손익 사용 가능 여부를 판정한다.

## 보존 경계

- 기존 `trade_fills` 행과 화면 조회는 수정하지 않는다.
- 사용자 복기, 수동 묶음, 수동 매매유형을 수정하지 않는다.
- 새 DB 표나 Kiwoom TR을 추가하지 않는다.
- 중앙 상세 projection은 canonical 계좌와 기간으로 읽고 원본 행은 변경하지 않는다.

## 검증

- 정확 일치에서 요약+상세 이중 합산 없음
- 부분 수량에서 상세 수량만 한 번 선택하고 미확인 표시
- 같은 수량·다른 금액 충돌
- 요약 전용과 상세 전용 분리
- run 변경 뒤 같은 broker 체결 ID 중복 제거
- 같은 broker 체결 ID의 내용 충돌 표시와 수량 중복 방지
- 다른 계좌 자료 거절
- canonical alias와 KST 기간 필터 저장소 조회
- 인접 대조/projection/query 27개 및 전체 trade 회귀 120개 통과

## 다음 단계

대조 결과, kt00015 실제 비용, 연구 run/decision 연결을 동결해 FeedbackEvidence를 만든다. 체결 또는
비용이 미확인이면 확정 순손익을 내보내지 않고 누락 사유와 선택 편향 상태를 함께 기록한다.
